## Agent Brief

**Category:** bug
**Summary:** 跨来源取值比较改用三档规则（0.5% 内相容／单位错／其余冲突），不再零容差

**Current behavior:**
多个注册来源的已认证声明，只要数值不完全相等就判为冲突：`metric_series` 与目标日投影的选值逻辑都用 `max(values) - min(values) > tolerance`，而所有调用方传入的 `tolerance` 都是 `0.0`。社融 2026-08 `ytd_increment`，TuShare 是 239109 亿元，央行是 239100 亿元（原文"23.91 万亿元"），被判为冲突，`selection_status` 不是 `selected`，下游公式拒用。

**Desired behavior:**
按 ADR-0033 判定，证据库查询（`EvidenceQueryResult` / `MetricSeriesPoint` 的冲突标记）和投影选值（`_selected_among` 一类）两处结果一致：
- 两两比较参与比较的值（范围与现在相同：已认证、`validated`、`REPORTED_VALUE`、值非空）。相对偏差 `|a−b| / max(|a|,|b|)` 不超过 0.5% 视为相容。
- 两值之比接近 10 的整数次幂（指数不为 0，误差在 1% 以内），判为冲突，原因码 `unit_scale_mismatch`，下游能读到这个原因码。
- 其余超过 0.5% 的偏差判为冲突，原因码与单位错区分开（例如 `value_disagreement`）。
- 两值都为 0 视为相容；只有一方为 0 判冲突。
- 相容时按现行证据优先级规则选值，不取平均。
- CLI `evidence-query --tolerance` 的绝对容差仍可显式传入；没有传入时走三档规则。是否保留这个参数由实施者决定，但不能让默认行为继续是零容差。

**Key interfaces:**
- 冲突判定目前在证据库查询和投影选值两处各写了一份，应收敛为一个共享的判定函数，返回"是否冲突"和原因码。
- 冲突结果要带原因码，供票 09 的缺口清单使用。

**Acceptance criteria:**
- [ ] 239109 与 239100（亿元）判为相容，`selection_status == "selected"`。
- [ ] 239109 与 23.9109（同一单位标注）判为冲突，原因码 `unit_scale_mismatch`；100 倍、1 万倍同样判为冲突。
- [ ] 100 与 101（1%）判为冲突，原因码不是 `unit_scale_mismatch`。
- [ ] 0 与 0 相容；0 与 1 冲突。
- [ ] 证据库查询与投影选值对上述用例给出相同结论（同一组用例分别覆盖两处）。
- [ ] 受影响的现有测试按 `docs/agents/testing.md` 选择并通过；原本依赖零容差的用例，按新规则改写预期并在提交说明里列出。

**Out of scope:**

- 给指标定义加逐指标容差字段。
- 官方补缺按 `scope.metric_ids` 限定导入范围（调查发现的连带导入整族问题，本票不处理）。

**实施（2026-09-28）**
