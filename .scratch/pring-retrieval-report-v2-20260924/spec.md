# 检索与报告二期：可检索缺口、TuShare 资讯、AI WebSearch 与精简报告输入（实施规格）

## Problem Statement

首次真实完整运行（2026-09-23）跑通了，但暴露出三处近乎失效的环节：

1. **检索补缺基本无效**：16 次 Tavily 查询由“指标 ID + 名称 + 来源编码 + 统计期”拼成，返回的 43 个候选有 42 个不在白名单，多是 TuShare 文档页和无关站点，且有一半花在网页上根本不存在的派生指标上。缺口清单里 16 项“检索未通过”，没有一项被补上。
2. **AI 报告两路超时**：交给 AI 的证据包约 14.6 万字节，Codex 与 Claude 各跑满 300 秒、零输出，每天只能拿到确定性的简版报告。
3. **AI WebSearch 没有适配器**：降级链的最后一级一直是“未配置”，P1 宏观与 P2 海外指标缺值时没有兜底。

作为运行者，我每天看到的是大量无法补齐的缺口和没有解释的报告；而当天发布的 CPI、LPR 等数字其实在官方发布几分钟后就出现在主流财经资讯里。

## Solution

- **只搜能补的缺口**：只对“可检索缺口”（属于登记解析器家族或登记了宽松主机的指标）搜索。
- **查询更准**：查询按家族发布稿标题模板生成，并按域名限定到官方主机加媒体白名单，搜索命中即可解析。
- **新增 TuShare 资讯渠道**：放在 TuShare 数据接口之后、官方直连之前。每次运行统一拉取一次 `major_news`。P1/P2 可按家族登记的资讯解析规则从正文取值，被采用的值留存命中原话以便追溯；资讯原件只保留 2–3 天。TuShare 取到值后不再去官方或媒体页面。
- **接入 AI WebSearch**：用 Codex CLI 与 Claude Code 自带的联网搜索（Codex 先、Claude 备），按固定结构返回网址、原话、数值、统计期、发布日期，采用规则与资讯一致。
- **精简报告输入**：AI 报告只接收已验证结果（结果值、来源、是否有异常），不再附证据链、不再逐段引用证据；生成后只校验“结论未被改写”与“结构合规”。

## User Stories

### 可检索缺口与查询

1. 作为运行者，我想让系统只对属于登记解析器家族或登记了宽松主机的缺口发起搜索，这样搜索预算不会浪费在网页上根本不存在的派生指标上。
2. 作为运行者，我想让由 TuShare 计算的派生指标（宽度、商品篮子、期货仓单、估值、融资、确认类指数）以及 NHII 在 TuShare 重试后直接列为缺口，原因为“无可检索来源”，这样我知道这些缺口搜索也补不了。
3. 作为运行者，我想在缺口清单里看到“无可检索来源”的中文标签，并与“检索未通过”“缺失”等区分开，这样能一眼分辨缺口性质。
4. 作为维护者，我想让每个解析器家族（及 LPR、中证核心、三项 P2）在代码常量里登记一条查询模板，按发布机构发布稿标题的写法并带中文格式统计期，这样查询能直接命中发布页。
5. 作为维护者，我想让查询模板与该家族的白名单主机、解析器放在同一登记处，随代码版本一起变化，这样新增家族时不会漏配。
6. 作为运行者，我想让 Tavily 调用时把该家族的官方主机加媒体白名单作为域名限定传入，这样返回结果只来自可取值的站点。
7. 作为运行者，我想让 Exa 在顶替 Tavily 时同样按域名限定，这样两个渠道口径一致。
8. 作为排查者，我想在检索记录里看到实际发出的查询文字与域名限定清单，这样能判断一次未命中是查询问题还是来源问题。
9. 作为维护者，我想有一份代码常量的媒体白名单：国内财联社、新华网、人民网、中国政府网、中国证券报、上海证券报、证券时报、第一财经、财新、华尔街见闻、新浪财经、东方财富；国外路透、彭博、CNBC、MarketWatch、华尔街日报、金融时报、雅虎财经、Investing.com。这样“主流媒体”有明确边界。
10. 作为运行者，我想让不在官方主机和媒体白名单里的候选继续以“不在白名单”列入“检索未通过”，这样人工排查时有迹可循。

### TuShare 资讯

11. 作为运行者，我想让每次完整运行在 TuShare 数据接口之后、官方直连之前统一拉取一次 `major_news`，时间范围从上次成功运行的截止时点到本次截止时点，这样一次拉取供所有缺口共用。
12. 作为运行者，我想在首次运行、没有上次截止时点时，只拉取最近 3 天的资讯，这样首次运行不会拉取过量。
13. 作为运行者，我想让资讯拉取按接口的 400 条上限自动翻页直到覆盖整个时间段，这样不会漏掉当天的发布资讯。
14. 作为运行者，我想让资讯拉取失败（无权限、超时、结构不符）只记录在批次里并继续后续渠道，这样资讯故障不会拖垮整次运行。
15. 作为运行者，我想让每个缺口在本地按其家族的资讯解析规则筛选这批资讯，规则命中且统计期相符的值即可采用，这样当日发布的宏观数据能及时补上。
16. 作为运行者，我想让 TuShare（数据接口或资讯）取到值后，本缺口不再尝试官方直连、Tavily 与 AI WebSearch，这样节省调用。
17. 作为维护者，我想让每个家族登记资讯解析规则，只认特定句式（如“CPI同比上涨x%”“1年期LPR为x%”），规则未命中的数字一律不取，这样不会从正文里抓到无关数字。
18. 作为运行者，我想让资讯里的统计期与发布时间也须通过校验（统计期为本缺口的应有期，发布时间不晚于运行截止时点），不符则不采用，这样不会把上月数字当成本月。
19. 作为排查者，我想让被采用的资讯值在明细旁留存命中原话、资讯标题、来源、发布时间和正文哈希，这样 120 个交易日内都能说清这个数的出处。
20. 作为运行者，我想让资讯原件只保留 2–3 天、解析后即删除，这样存储不会被每天上千条资讯撑大。
21. 作为运行者，我想让资讯原件的删除与 120 日留存清理在同一处完成，失败的运行不删除，这样行为与现有留存一致。
22. 作为运行者，我想让 P0 三核心不采用资讯值，仍只认 TuShare 与中证官网，这样正式阶段的输入不被放宽。

### 媒体网页与严格路径

23. 作为运行者，我想让 Tavily/Exa 搜到的白名单媒体页面，对 P1/P2 按同一家族的资讯解析规则取值，并留存命中原话，这样媒体转载也能补缺。
24. 作为运行者，我想让官方主机上的页面仍由登记解析器从重抓原文解析，规则与二期前一致（统计期、发布日期、与搜索值数量级核对），这样官方原文的严格性不降。
25. 作为运行者，我想让媒体页面规则未命中时以新的原因“解析规则未命中”列入“检索未通过”，这样我知道页面找对了但没有取到可认的句式。
26. 作为运行者，我想让 P2 宽松路径的主机清单并入媒体白名单，同时保留原来的按指标登记主机，这样 USDCNY 16:30、VIX、SOX 有更多候选。

### AI WebSearch

27. 作为运行者，我想让降级链最后一级的 AI WebSearch 由 Codex CLI 的联网搜索执行、失败或超时时改用 Claude Code 的联网搜索，这样与报告的降级方式一致。
28. 作为运行者，我想让 AI WebSearch 只针对可检索缺口，并在提示中给出该缺口的指标、应有期、查询模板和白名单主机，这样 AI 在对的范围内搜。
29. 作为运行者，我想让 AI WebSearch 按固定结构返回候选（网址、原话、数值、统计期、发布日期），不合结构的输出整次拒收，这样系统能逐项校验。
30. 作为运行者，我想让 AI 返回的每个候选都经同一套校验：网址在官方或媒体白名单内、原话命中家族资讯解析规则且规则取出的值与返回的数值一致、统计期为应有期、发布日期不晚于截止时点，这样 AI 不能凭空给数。
31. 作为运行者，我想让 AI WebSearch 每个缺口每次运行至多调用一次、单次 300 秒超时、每次运行合计不超过 60 分钟，到上限后剩余缺口注明原因不再调用，这样一次运行不会被拖到无限长。
32. 作为排查者，我想在检索记录里看到每次 AI WebSearch 的适配器、耗时、返回的候选及逐个候选的通过与否，这样能复盘 AI 给了什么、为什么没采用。
33. 作为运行者，我想让 AI WebSearch 不使用、不保存任何模型厂商 API key，只依赖 CLI 自身登录，这样与报告适配器的安全边界一致。

### AI 报告

34. 作为读者，我想让 AI 报告只基于已验证结果生成：正式阶段（或为空的原因）、三核心状态及变化原因、宏观与库存结论、核心沿用与缺口概况，每项附结果值、数据来源和是否有异常，这样报告聚焦结论与解释。
35. 作为运行者，我想让交给 AI 的报告输入不含逐条证据行、观测序列、证据编号和允许引用清单，这样提示缩小一个数量级、两路 CLI 都能在 300 秒内完成。
36. 作为读者，我想让报告段落不再列出证据编号与反证引用，但在涉及具体数值时写明数据来源，这样报告易读又能知道出处。
37. 作为运行者，我想让报告生成后只校验两点：AI 提到的正式阶段、核心状态与宏观/库存结论与输入一致；输出符合固定结构，并保留禁用词检查。这样“AI 只解释、不改写结论”的底线仍然成立。
38. 作为运行者，我想让两路 CLI 都失败时仍回落确定性报告，确定性骨架也不再包含证据引用，这样降级行为不变。
39. 作为排查者，我想让报告快照记录新的输入版本与提示版本，旧快照照常可读，这样新旧报告可以区分。
40. 作为读者，我想在页面和报告阅读器里照常看到缺口清单与“检索未通过”“无可检索来源”分组，这样报告精简后缺口信息不丢失。

### 真实运行暴露的小缺陷

41. 作为运行者，我想让交易日历作为运维证据不参与时效判定、不再以 P0 缺失出现在缺口清单里，这样缺口清单不会出现假的 P0 缺口。
42. 作为运行者，我想让社融总量与 GDP 从官方列表页定位发布稿时能在多篇同期稿件中选出唯一正确的那篇，这样这两项不再因“链接不唯一”被拒收。
43. 作为运行者，我想让未配置 EIA key 时的 EIA HTML 历史表在正常缺周（如节假日无报价）时不被整表拒收，真正的数据断档则如实记为缺口，这样 Brent/WTI 能经 HTML 路径取得。

### 追溯与验收

44. 作为排查者，我想让资讯拉取、媒体页面抓取与 AI WebSearch 调用都挂在本次加工批次下，与现有取数记录同样可查，这样一次运行的全部外部调用都能追到。
45. 作为运行者，我想在实现完成后再做一次真实手动完整运行，记录各渠道命中数、补齐的缺口、报告是否由 AI 生成及耗时，这样能确认二期真正解决了首次运行暴露的问题。

## Implementation Decisions

### 检索登记处（按家族）

- 在现有官方解析器家族的登记（家族 → 发布机构、官方主机、指标集）之上，为每个家族增加三项：
  - 查询模板：按发布稿标题写法，带中文统计期占位；
  - 资讯解析规则：每个指标、每个维度成员对应一条句式规则，产出数值；
  - 是否允许资讯/媒体取值：由优先级决定，P0 一律否。
- LPR、中证核心、三项 P2 同样登记模板；P2 的宽松主机与媒体白名单合并使用。
- 新增“媒体白名单”常量（国内外主流财经媒体主机）。
- 新增“可检索缺口”判定：指标属于某个登记解析器家族，或登记了宽松主机。完整运行计划中，不可检索的缺口不进入搜索级（Tavily/Exa/AI），仍经 TuShare 与资讯两级，最终以原因“无可检索来源”列入缺口清单。

### 降级链

- 顺序改为：本地有效证据 → TuShare 数据接口 → TuShare 资讯 → 注册官方直连 → Tavily（Exa 在 Tavily 月限额耗尽后顶替）→ AI WebSearch。前一级取到完整模型输入即止。
- 预算规则沿用：每次运行 Tavily 16、Exa 8，无每日上限。AI WebSearch 不计入这两项，但受“每缺口每次运行一次、单次 300 秒、每次运行合计 60 分钟”约束，由检索台账记录与判定。

### 搜索调用

- 查询由家族模板与应有期生成，不再使用指标 ID 与来源编码。
- Tavily 请求增加域名限定参数（官方主机 + 媒体白名单）；Exa 请求同样增加域名限定，并请求返回正文摘要，使宽松路径有可取值的文本。
- 检索记录增加实际查询文字与域名限定清单。

### 候选验证

- 官方主机页面：沿用登记解析器严格路径（统计期、发布日期、与搜索值数量级核对）。
- 媒体主机页面（P1/P2）：重抓页面保存原文，按家族资讯解析规则取值；规则未命中记新原因 `rule_not_matched`（页面标签“解析规则未命中”）；统计期、发布时间同样校验。
- 检索未通过的原因集合在现有基础上增加 `rule_not_matched`。缺口清单增加类别 `no_searchable_source`（页面标签“无可检索来源”）。

### TuShare 资讯模块（新增深模块）

- 对外接口：给定运行与截止时点，返回本批次资讯集合（标题、来源、发布时间、正文、正文哈希），并提供“按家族规则为某缺口取值”的查询。
- 内部行为：按时间段翻页拉取 `major_news`（每次 400 条上限），整批原文作为本批次的取数记录保存。资讯拉取属于 TuShare 渠道，走现有 TuShare 请求与结构校验；无权限或失败只记批次、不阻断。
- 时间范围：上次成功完整运行的截止时点至本次截止时点；无上次时取最近 3 天。

### 命中原话留存（数据结构变更）

- 新增一张明细附属表，按明细（claim）登记：命中原话、资讯或页面标题、来源名称、发布时间、正文哈希、取值途径（TuShare 资讯 / 媒体网页 / AI WebSearch）、网址（如有）。
- 与明细同生共灭：随 120 日留存清理一起删除。以迁移新增。
- 资讯原件（及媒体页面原文）另设 3 天留存，在成功运行末尾的留存清理中删除超期者。被采用的值只依靠命中原话与哈希追溯。

### AI WebSearch 适配器（新增）

- 复用报告 CLI 子进程框架：可执行文件查找、版本探针、超时与进程组清理、审计记录。
  - Codex：以联网搜索模式和输出结构约束调用；
  - Claude：开放 WebSearch 工具、以 JSON Schema 约束输出。
  - 两者都不注入模型 API key。
- 输入：缺口的指标、维度、应有期、查询模板、白名单主机清单、所需句式说明。输出：候选数组（网址、原话、数值、统计期、发布日期）。
- 每个候选依次校验：白名单主机 → 家族规则命中原话且取值等于返回数值 → 统计期 → 发布日期不晚于截止时点。通过即以“AI WebSearch”途径写明细并留存命中原话。
- 调用登记在检索台账的 `ai_websearch` 渠道，沿用“每缺口每次运行一次”的判定；单次 300 秒；运行内累计时长到 60 分钟后，后续缺口记为“AI 时长已用尽”，不再调用。

### 报告输入与校验（报告模块改造）

- 以“报告输入”取代“证据包”：
  - 报告身份与截止时点；
  - 正式阶段或阶段为空的原因；
  - 三核心状态与变化原因；
  - 宏观（政策、信用、过热、价格）与库存结论；
  - 核心沿用标注；
  - 缺口概况（各类别计数，加 P0/P1 缺口指标名）。
  - 每项附结果值、数据来源名称、是否有异常。
- 去掉允许引用清单、证据编号、结构化上下文中的逐条证据行与观测序列。
- AI 输出结构中段落不再含证据与治理引用字段。
- 后置校验：结构合规；正式阶段、三核心状态、宏观/库存结论与输入一致（改写即拒收）；禁用词检查保留。
- 确定性骨架与降级报告同步去掉证据引用。报告快照记录新的输入与提示版本；旧快照按原版本读取展示。
- 单适配器超时 300 秒、Codex 首选、Claude 备用、双失败降级不变。

### 小缺陷修复（独立切片）

- 交易日历：归入不参与时效判定的运维证据集合（与发布日程、来源可用性同列）。
- 社融总量与 GDP 的官方列表选链：先以真实列表页诊断“链接不唯一”的成因，再收紧选链规则（如按发布稿标题模板与统计期精确匹配，排除解读稿、答记者问等同期稿件）；选链规则与本期的家族查询模板共用同一标题写法。
- EIA HTML 周连续性：先以真实历史表诊断拒收成因，区分“正常无报价的缺周”与“数据断档”；前者不再整表拒收，后者如实记缺口。

## Testing Decisions

- **什么是好测试**：只测外部可观察的行为——运行完成与否、投影里的缺口清单与分组、明细取值与其命中原话、检索记录（查询文字、域名限定、候选与原因）、报告快照内容与状态。不测内部函数调用顺序与中间数据结构。
- **唯一主接缝**：手动完整运行的公开入口。经 `run-submit` 提交，Worker 执行，读取公开输出与批次/检索记录。
  - TuShare（含 `major_news`）、Tavily/Exa、官方与媒体页面、时钟：一律替身。
  - AI CLI（报告与 WebSearch）：把假的 `codex`/`claude` 可执行文件放到 `PATH` 上，走真实子进程与协议边界。
  - 不为内部函数另开接缝。
- **例外**：资讯解析规则与报告输入的体积可在保存的真实样本上做无接缝检查（同中证官网解析器样本测试的做法）。样本取自真实 `major_news` 与真实投影，脱敏后入库。社融/GDP 列表页与 EIA 历史表的诊断同样先保存真实页面作为样本，再以样本复现拒收、验证修复。
- **需覆盖的场景**：
  - 不可检索缺口不发起搜索，列为“无可检索来源”；
  - Tavily/Exa 请求携带模板查询与域名限定；
  - 资讯规则命中后补齐 P1，其后渠道不再调用；
  - 资讯规则未命中或统计期不符时不采用；
  - P0 不采用资讯值；
  - 媒体页面命中规则补齐 P1/P2，未命中记“解析规则未命中”；
  - AI WebSearch 以 Codex 补齐，Codex 超时后由 Claude 补齐；
  - AI 返回非白名单网址或原话与数值不符时拒收；
  - AI 时长上限到达后停止调用；
  - 资讯原件 3 天后清理，命中原话随明细保留；
  - 报告输入体积显著缩小且不含证据编号；
  - AI 改写正式阶段时被拒收并降级；
  - 旧报告快照仍可读；
  - 交易日历不再列入缺口清单；
  - 社融总量、GDP 在同期多篇稿件的列表页上选中正确发布稿；
  - EIA HTML 历史表含节假日缺周时照常取得，真实断档时记缺口。
- **先例**：
  - 完整运行与 TuShare 替身：`test_core_official_fill`、`test_retention`、`test_release_preannouncement`；
  - 检索候选与原因：`test_retrieval_strict_path`、`test_retrieval_p2_lenient`；
  - 假 CLI 可执行文件：`test_cli_protocol`；
  - 样本解析：中证官网解析器样本测试。
- **验证策略**：按 ADR-0025，日常跑受影响测试，终点前跑一次全套，最后做一次真实手动完整运行并记录结果。

## Out of Scope

- NHII 的官方页面解析（南华官网无可解析页面）。
- 为 VIX、SOX、UST 另找注册数据源；本期只让它们经媒体白名单与 AI WebSearch 有机会补齐。
- TuShare `news`（快讯）接口：当前无权限。
- Wind：无公开新闻网页。
- 全套测试耗时优化（`/improve-codebase-architecture`）。
- 放宽 P0 的取值来源。

## Further Notes

- 资讯解析规则按家族登记，是有意不做通用抽取器（ADR-0023 的取舍在 ADR-0026 中仍然保留）。新增家族时规则需与样本测试一同提交。
- 付费墙媒体（彭博、华尔街日报、金融时报）可能取不到全文，只能依赖搜索摘要或 AI 返回的原话。真实运行后按命中情况调整媒体白名单。
- AI WebSearch 的 60 分钟上限与单次 300 秒属于系统层面的宽松限制（业务上无上线压力），可在真实运行后按耗时调整。
- 首次真实运行的缺口清单（16 项检索未通过、15 项缺失、4 项拒收）是二期验收的对照基线。
