# 11: AI WebSearch 适配器

**What to build:** 降级链最后一级由 Codex CLI 联网搜索执行、失败或超时改用 Claude Code，均按固定结构返回候选（网址、原话、数值、统计期、发布日期）；每个候选校验白名单主机、家族规则命中且取值一致、统计期、发布日期后补齐缺口并留存命中原话。每缺口每次运行一次、单次 300 秒、每次运行合计 60 分钟；不注入任何模型 API key。

**Blocked by:** 06, 07

**Status:** done

## Comments

- 2026-09-24 完成。报告的 CLI 子进程部分抽成 `cli_process.run_structured_cli`（查找可执行文件、版本探针、同一截止时限、进程组清理、审计；只放行固定环境变量，不传任何模型 API key），报告适配器改用它，行为不变。新增 `ai_websearch.py`：降级链最后一级先调 `codex --search exec`、失败或超时再调 Claude Code（只开放 `WebSearch` 工具，其他工具事件即拒收），以 JSON Schema 约束固定结构（网址、原话、数值、统计期、发布日期）；每个候选依次校验官方或媒体白名单主机 → 家族规则从原话取出的值与返回数值一致（P2 宽松指标：原话写明该日且恰有一个值）→ 统计期 → 发布日期不晚于截止时点，通过即以 `ai_websearch` 途径写明细并留存命中原话。台账记 `ai_websearch` 请求（适配器、起止时间）与逐候选校验结果；每缺口每次运行一次（台账既有规则）、单次 300 秒、每次运行累计 60 分钟，用尽后记 `ai_time_exhausted` 不再调用。只对可检索的 P1/P2 缺口（有资讯规则或宽松主机）启用。
- 与票面不同之处：默认关闭，须在运行配置 `config.toml` 写 `[retrieval] ai_websearch = true` 才启用。原因是本机装有真实 codex/claude，不设开关时任何未注入替身的完整运行（含大量既有测试）都会真实联网调用，耗时且消耗额度。本地运行说明已写明。
- 测试 `tests/integration/test_ai_websearch.py`（PATH 上的假 codex/claude，走真实子进程：Codex 候选补齐 P1 CPI 且不见 API key、查询为模板、域名以官方主机开头；Codex 超时后由 Claude 补齐；非白名单、数值不符、统计期不符、发布晚于截止、规则未命中逐一拒收；时长用尽不再调用）。报告 CLI 协议测试随抽取改指补丁位置。受影响 49＋85 例全过。
