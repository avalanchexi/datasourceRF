# 03: 三核心计算预热的逐截止点验证

**Parent:** [固定窗口、预热证据与目录迁移规格](../spec.md)；[已批准拆分记录](../ticket-breakdown-proposal.md)。

**What to build:** 从新窗口的输入需求，经公开证据选择与预检/回放边界，读回三核心每个结果实际需要的预热版本及缺口。

**Blocked by:** [01 — 固定新窗口并从公开预检读回交易日范围](01-fixed-window-calendar.md)

## Scope

本轮目标固定 2026-09-22，正式窗口为 2026-04-01 至 2026-09-22，含首尾 120 个中国交易日。执行跨日不移动末端；必要预热按冻结公式另定，来源缺件不导致缩窗。

基础 259 日和状态初始化用途分开；仅令一个必要预热值未知、未来公开、未认证或损坏即不能通过，补入合格版本后正确恢复。日期精度按来源时区下一自然日；不以最早日期或总行数代替中间覆盖，不改变趋势规则。

**规格覆盖：** User Stories 5、6、7、8、9、10、11、28；本票同时继承规格中的版本、证据与验收边界。

## Acceptance criteria

- [ ] 按冻结的三核心规则从固定新窗口导出必要输入及各消费 cutoff；默认基础需求为 2025-08-29 至 2026-09-22 共 259 日，其中窗口前 139 日。
- [ ] 完整合法材料经公开选择和预检/回放边界成功，能追溯每个实际消费的来源版本；基础计算可用与持续性/初始化状态分别判断。
- [ ] 保持窗口内材料合法，仅使一项必要计算预热未知、未来公开、未认证或原件损坏，即准确拒收或报必需缺口；补入合格版本后经同一入口恢复。
- [ ] 验证可靠日期按来源时区下一自然日零点可见，包括周末边界；采集时间不倒填 PUBLIC，SYSTEM 按实际取得及校验时刻。
- [ ] 中间断档不能被最早日期或总行数掩盖；初始化历史不成为正式计算输入的时间豁免，不修改趋势及持续性公式。

## Testing decisions

沿用已批准的公开任务命令/API → 持久任务 → 单次 Worker → 投影/运行/证据/报告读取边界；必要时使用 PUBLIC/SYSTEM 选值或趋势/阶段的公开领域接口。只替换外部传输、时钟或 CLI，解析、选择、仓库与投影保持真实。先复用有效反例和交付，仅为实际缺口补行为验证；相关重型及同版本全套按[项目测试规则](../../../docs/agents/testing.md)执行，记录实际终态与身份，不为每票重复整套。
