# 固定 2026-09-22 窗口、公式预热发布证据与 CNY030 目录迁移

## Problem Statement

用户需要接续已经开展的数据获取修复，让本轮结果覆盖截至 2026-09-22 的固定 120 个中国交易日。
旧验收窗口为 2026-03-09 至 2026-08-28；已有软件、研究原件和旧窗口收据不能直接证明新窗口完成。
新增日期的数值、逐值发布证据和公式所需窗口前输入仍有缺件，今天能够下载某个历史值也不能证明该版本当时已公开。

此前“预热无需公开时间证据”的建议混淆了计算预热与初始化预热。用户已选择保留 PUBLIC 无前视要求，
为参与正式结果计算的预热补证。同时，债券确认指标 CNY030 尚未取得合格的目标日数值及发布证据；
用户同意仅将该项在新目录中降为 P2、保留待认证缺口。债券核心仍是 000012。

需要一份可执行的增量规格，将新窗口、证据要求和目录迁移贯穿预检、候选准入、回放及最终真实验收，
复用已经完成的工作，并让每个未满足条件继续阻塞其实际依赖的交付。

## Solution

建立新的窗口验收范围：**2026-04-01 至 2026-09-22，含首尾共 120 个交易日**。
这一范围由已保存的交易所休市安排复算；运行时仍须通过项目既有日历认证和完整性检查。
与旧窗口重叠 103 日、新增 17 日。执行跨日不移动末端，也不因缺件缩短窗口。

从每个公式及其版本生成输入需求，分别记录窗口内输入、计算预热和初始化预热。
计算预热逐值满足来源认证、质量和 PUBLIC 可见性要求；日期精度沿用既有保守规则。
复用已保存的新 17 日原件，补齐缺失值、版本和发布证据，通过正式入口取得可追溯声明。
无法取得的材料形成精确缺口，不转为推测时间或默认值。

在新的不可变目录与候选模型中，将 `CN_BOND_FULL_PRICE_CNY030` 从 P1 改为 P2，保持
`awaiting_source_certification`。新候选可将其作为可选缺口；其他 P1、三核心及其认证要求保持。
旧目录、旧声明、已发布投影和报告保持原样。

软件迁移和离线验证可以先完成；真实完整候选、PUBLIC 回放、报告及切换继续依赖真实证据和原有验收门。
交付时分别呈现软件收据、材料覆盖、来源认证、真实回放、真实运行与显式生效记录。

## User Stories

2. As a 分析用户, I want 窗口包含完整的 120 个中国交易日, so that 缺数据不会被缩窗隐藏。
3. As a 分析用户, I want 新窗口起止与交易日清单可核对, so that 周末、节假日和行政补班不会混入交易日。
4. As a 维护者, I want 明确新旧窗口重叠、新增和移出的日期, so that 已有有效材料可以复用。
5. As a 维护者, I want 移出展示窗口但仍参与计算的日期继续受检查, so that 右移窗口不会误删必要预热。

7. As a 分析用户, I want 计算预热满足与正式输入相同的发布证据要求, so that 历史结果没有使用后来才可得的值。
8. As a 审阅者, I want 初始化预热有明确用途及边界, so that 它不会被用来豁免正式公式输入。
9. As a 分析用户, I want 仅有可靠发布日期的值按来源时区下一自然日才可见, so that 日期精度不足不会产生当日偷看。

17. As a 分析用户, I want CNY030 在新目录中成为 P2 并显示待认证, so that 该确认指标的缺件不单独阻塞完整候选。

## Implementation Decisions

1. **窗口冻结。** 本轮目标交易日和回放末端均为 2026-09-22；回放起点为 2026-04-01，恰好 120 个中国交易日。实际执行时刻、SYSTEM 截止点和历史 PUBLIC 截止点分别记录，沿用既有截止点规则，不用目标日期代替实际获取时间。
2. **日历有据。** 使用经项目认可的日历证据生成并绑定有序日期清单及哈希；不得将工作日日历或临时 120 条有值日期作为替代。缺日历或端点不符继续阻断。
3. **输入范围按公式生成。** 默认三核心 120 日均线、20 日斜率的首个基础计算点需要 140 条输入；覆盖本轮 120 日需至少此前 139 日，即 2025-08-29 至 2026-09-22 共 259 个交易日。这只是基础公式需求，不证明状态持续性已满足，也不统一适用于上下文指标。
4. **计算与初始化分开。** 输入需求记录用途、公式版本、指标/维度、频率、统计期、回看单位、原件/版本和各消费截止点。凡被正式公式实际读取的输入，均按计算预热规则处理；初始化历史不产生正式回放结果，沿用既有口径与质量要求，不扩展其豁免范围。
5. **低频依实际期次。** 月频、季频、事件和跨期派生按实际依赖生成期次及比较基线，不补成每日观测，也不要求每项有 120 条。当前上下文回看有 730、95、62、10 个自然日及零回看，具体集合从冻结的公式依赖推导。
6. **发布证据绑定值与版本。** 计算预热同样要求来源认证、质量合格以及消费时点非空且不晚于 cutoff 的公开可用时间。精确时刻、可靠日期、未知时间沿用既有规则；日期精度为来源时区下一自然日零点。来源计划、统计期、抓取时间、模板时间或未经证实的修改时间不填充公开时间。
7. **修订保留。** 新取得的历史原件先验证其承载版本；后来的修订不得回写旧声明或借用首次版本时间。重复抓取不产生重复经济事实；SYSTEM 可见性以系统实际取得并通过校验为准。
8. **增量采集。** 复用既有原件及已获授权保存的新 17 日材料。核验哈希、内容、日期和版本后，经正式导入/解析/选值入口取得应用收据。研究目录中的对象、HTTP 200 和人工摘值均不直接成为来源认证。
9. **缺件可定位。** 区分数值、发布证据、原件完整性、来源身份、字段/单位、维度成员、日历及派生父输入；记录缺失期次和受影响结果。取证失败是可交付的事实结论，但不能关闭依赖该材料的真实认证与验收。
10. **CNY030 专项迁移。** 为明确批准的这一项优先级变化提供版本化迁移路径，生成新的完整目录和候选模型。保持指标 ID、债券确认角色、源代码与其他定义字段；初始认证状态为待认证。不得通过关闭全目录漂移校验来实现。
11. **迁移兼容已有决定。** 以当前批准的完整目录为基础，保留已批准的沪深融资身份、外汇身份与两项黄金删除等处置。新迁移的优先级差异仅为 CNY030；目录总项数不变，P1 减一、P2 加一。旧规格中的固定数量不作为目录事实，计数从实际版本导出。
12. **核心与 P1 守门。** 三核心映射不变；其认证及其他 P1 认证继续强制。CNY030 待认证可以成为可选缺口，但不得作为已验证证据进入投影、公式或报告事实。不得删除它来隐藏缺口，也不自动调整其他指标。
13. **版本不可变。** 同目录版本内容改变必须拒收；已发布模型、投影、声明及报告不原地修改。旧审核包、旧窗口结果和旧认证绑定不得冒用作新候选审核。
14. **预检不是行数检查。** 针对窗口内逐 cutoff 和计算预热逐个需求验证日历、原件、PUBLIC 可见性、维度及父输入。最早统计期、最早公开日和数据总量只能作为诊断，不能单独证明覆盖。保留必需缺口与可选缺口的区别。
15. **完整检查后才称就绪。** 当前预检仍报告未完成项；新验收不得由退出码 0、空必需缺口数组或已存在观测直接授予就绪。所有必需检查及下游准入/回放门均满足才形成对应阶段的成功记录；预检本身不签发来源认证。
16. **沿用公开接口。** 优先复用已有起止日期参数、认证请求、目录注册、持久运行和回放查询入口；必要扩展只用于传递本轮绑定。旧默认日期、历史夹具和来源 URL 中的日期逐处辨别，不进行全库日期替换。
17. **独立软件验证。** 目录迁移、范围绑定和拒收路径可用合法隔离材料验证，不等待真实外部证据齐备。旧生命周期和家族实现按实际身份复用，不重做全部旧任务；隔离成功不计真实认证或产品完成。
18. **真实回放完整。** 候选与合法比较模型须覆盖同一固定 120 日的可认证交集。缺核心、缺公式输入、缺合法比较基线或认证生效不覆盖时明确阻断；不缩到有数据的日期，也不将已隔离的旧模型伪装成合格基线。初始化结果与正式输出区分，预热不扩大展示窗口。
19. **真实交付门继承。** 完整候选之后，真实配对检索测量与 PUBLIC 回放按各自真实依赖开展，二者不互相设无关阻塞；目标日真实运行、AI 解释、恢复和最终验收沿原要求收口。模型生效、30 交易日内部回退及系统切换继续使用既有机器门和适用的显式授权。
20. **收据准确复用。** 软件身份、实际导入发行物和被读取材料分别绑定。软件稳定后完成受影响验证及同版本必需全套；仅新增业务数据时按已确认规则复用仍有效的软件收据，并重做受影响数据/产品验收。材料或版本改变不能拼接旧通过数。
21. **新旧任务衔接。** 新 effort 承担新窗口与此次目录/证据规则的增量义务；旧任务的代码、证据和历史状态保留。源缺件只阻塞实际依赖它的真实交付。后续任务按可独立核验的纵向切片发布，分别列明软件、材料与真实运行依赖。

## Testing Decisions

1. 沿用用户在原规格中已接受的主入口：公开任务命令/API → 持久任务 → 单次 Worker → 投影、运行状态、证据与报告读取。使用隔离 SQLite 与内容寻址目录，仅替换外部传输、时钟及 CLI 子进程；解析、认证/选值和投影保持真实。无需新增测试后门。
2. 沿用两个已接受的领域边界：PUBLIC/SYSTEM 公开选值接口，以及趋势/阶段的公开确定性接口。断言可观察行为和持久证据；期望值用独立手算或人工核对，不复制实现算法自证。
3. 日历正例精确包含 2026-04-01 至 09-22 的 120 日，重叠 103、新增 17；负例覆盖端点缺失、重复日期、将 09-20 行政补班星期日算成交易日和以 119 日通过。窗口右移不改写历史回放记录。
4. 计算预热正例追溯到被实际消费的原件/版本；负例保持窗口内所有值有效，仅令一个必要预热值发布时间未知、晚于消费 cutoff、未认证或原件损坏，验证该结果不能通过。补入合法版本后须能从同一公开入口读回正确结果及血缘。
5. 日期精度检查来源本地日末之前不可见、下一自然日零点可见；周末不延到下一交易日。采集在今天但证据证明历史版本当时公开时，PUBLIC 与 SYSTEM 分别按自身时点选值。
6. 按冻结公式覆盖自然日回看、月/季频父输入、修订、缺维度、中间断档和未完成预检；不能只验证最早日期。基础趋势输入满足不等于已确认资产状态，持续性规则仍有独立期望。
7. CNY030 迁移成功例通过公开候选准入、注册目录读取和 Worker 消费，验证 P2 待认证缺口、其他必需数据可完成及旧目录哈希不变。负例覆盖无迁移声明直接改优先级、顺带降级其他 P1、更换核心/角色/源身份、冒用旧审核包和原版本覆盖。
8. 使用包含已批准身份修正的完整目录验证迁移组合；断言保留沪深融资身份及其自身认证依赖，计数只发生本次一项 P1→P2 变化。不可用内置旧目录悄悄恢复已删除/更名指标。
9. 采集原件的离线成功路径经过解析、声明、PUBLIC/SYSTEM 选值和消费者；错误代码、日期、单位、空数组、截断文件及未确认修订均保留拒收原因，不用假的声明 ID 代替完整链。
10. 固定窗口回放覆盖全部日期与每个实际采用的输入版本；少一天、缺基线、旧认证不覆盖或时间不可见必须失败。允许可解释的新旧差异，核对历史 SYSTEM 投影与报告未被修改。
11. 目标日运行验证页面、报告事实骨架、证据包、来源血缘、模型和 cutoff 一致。保留真实 CLI 解释成功与确定性降级的独立验收，不用某个 CLI 不可用推断所有解释渠道可用或不可用。
12. 可复用先例包括候选准入、沪深融资迁移、模型不可变生命周期、输入预检、回放回归以及登记目录 Worker 可选来源失败。具体定位见[实施边界](implementation-context.md)，先按变更挑选必要行为用例，不把所有先例当作每次必跑清单。
13. 实施及测试选择遵守[项目测试规则](../../docs/agents/testing.md)：先受影响快速用例，关键路径变化再完成相应重型验收，稳定后同版本必需全套；重型任务串行、检查真实磁盘及导入身份。已有收据只有绑定仍有效才复用。
14. 本规格阶段仅检查结构、链接、日历推导和需求一致性，不运行应用测试。将来真实取证、真实认证、真实回放、检索测量及最终切换各自留存真实收据；任何离线通过都不替代这些证明。

## Out of Scope

- 不替换三核心，不更改趋势/阶段公式、持续性规则、商品基准或既有 PUBLIC/SYSTEM 语义。
- 不自动降级其他 P1，不取消来源认证或使用计划发布时间补齐未知历史时间。
- 不将窗口滚到实际交付日，不缩短 120 日，也不扩大到全量六年/三年历史抢救；原长历史离线校准范围维持既有要求。
- 不为提速另起性能项目，不重开所有旧任务，不机械替换历史日期、不修改旧来源 URL 或旧发布结果。
- 不增加数据库备份、双写、旧系统运行时降级、多 Worker、额外付费数据采购或厂商模型 API 接入。
- 本次规格发布不执行来源认证、生产模型激活或系统切换，也不宣称研究中未取得的材料一定能补齐。
