# 前端重构：以真实投影说明 Pring 结论与数据依据

日期：2026-10-15。实施基线：本地 main `325a9f9`。范围：报告式首页、数据链路、运行状态，以及这些页面所需的 Worker 展示字段和查询契约。

## Problem Statement

用户首先需要确认 Pring 模型取到了正确的数据，并按既定规则给出结论。目前后端已完成取数、模型规则与缺口处理，线上界面仍为八页平铺的旧 Dash 站。用户难以在一个连续阅读流程中看清当前结论、三核心走势、宏观支持与反证、缺失原因，以及每项结论使用的原始证据。

报告式原型 v2 已确认信息架构和内容密度，使用真实运行材料，但还不能作为生产页面：走势图另行查询来源声明，部分比较口径与现行计算不同；缺期归因手工映射；筛选和查看原文没有真正接入；运行健康汇总未由 Worker 统一留存。直接移植原型会造成“图表看起来正确，却与结论不是同一截止点”的风险。

本批次把模型已经发布的结果完整、准确地呈现出来，让用户从结论追溯到依据，并辨别模型有效观测、取数问题、正常发布时滞和运行故障。

## Solution

以 2026-10-15 刷新的原型 v2 为信息架构与密度基准，保留 Dash + Plotly，建设一个七段报告式首页和两个二级页面：数据链路、运行状态。首页先解释当前周期结论，再展示资产与宏观依据，最后提供数据说明、报告解读与追溯入口。

Worker 预先生成有身份、有截止点、有单位、有缺失原因的展示数据。网页只读取、筛选和排版；数值、走势和证据跳转使用同一分析投影。运行与报告作为单独更新的运行读模型，明确关联投影，不能冒充分析数据更新。旧页面的运行操作、报告历史、发布日历与深链接继续可达，八页平铺导航退出。

本规格收束已经确认的两轮访谈、最新领域决定和报告解读批次。后续拆成可逐票验收的任务；不以本规格触发正式运行、模型调整或 dot 迁移。

## User Stories

1. 作为模型使用者，我希望首页首先显示当前正式阶段或暂无阶段的原因，以便立即理解系统结论。
2. 作为模型使用者，我希望看到目标交易日、数据截止时间、模型版本和投影身份，以便知道结论对应哪一批事实。
3. 作为模型使用者，我希望区分分析生成时间和运行状态刷新时间，以便不把页面刷新误认为重新分析。
4. 作为模型使用者，我希望非典型组合、核心数据待处理和待定方向分别说明，以便不把所有空阶段当成故障。
5. 作为模型使用者，我希望看到上次确认阶段及其日期和回溯来源，以便理解当前非典型组合的历史背景。
6. 作为模型使用者，我希望阶段标签统一为可读名称，以便不看到重复的 Stage 前缀或内部枚举。
7. 作为模型使用者，我希望通过固定目录快速跳到七个报告段落，以便在高密度长页中定位信息。
8. 作为模型使用者，我希望按债、股、商三条线查看核心状态和同类资产，以便比较核心趋势与周边价格事实。
9. 作为模型使用者，我希望查看三核心最近 120 个交易日的实际价格与 MA120，以便理解当前稳定方向的依据。
10. 作为模型使用者，我希望最新值、近 5 日与近 120 日变化带有单位和比较日期，以便避免把不同口径的涨跌当成同一指标。
11. 作为模型使用者，我希望数据不足的走势或变化显示原因，以便不被补零、插值或缩短窗口后的伪完整值误导。
12. 作为模型使用者，我希望看到距均线、斜率、噪声带和稳定方向切换候选，以便理解系统已确认什么、还在等待什么。
13. 作为模型使用者，我希望 30 日候选方向与趋势切换候选及持续天数分别标明，以便不把即时方向当成已持续的趋势。
14. 作为模型使用者，我希望同类价格、价格内部一致性和债券归因明确不计入确认度，以便避免同源信息自我确认。
15. 作为模型使用者，我希望海外与汇率数据保留各自统计期、频率和时效，以便不把周频或时差误认为漏取。
16. 作为模型使用者，我希望按政策、信用、过热、物价、库存分组阅读关键指标，以便理解宏观事后确认。
17. 作为模型使用者，我希望看到支持、反证、仅观察、未确认的逐项关系及其理由，以便判断证据实际支持了哪条命题。
18. 作为模型使用者，我希望确认度按关键指标计数，并说明非概率属性，以便不把五个分组或支持数当成阶段正确率。
19. 作为模型使用者，我希望当前无正式阶段时确认度显示不适用、五维事实仍可阅读，以便保留信息而不制造评分。
20. 作为模型使用者，我希望展开主要成员、辅助成员的一致与分化，以便理解为何某项只能观察。
21. 作为模型使用者，我希望区分水平、动量、斜率变化、持平与未知，以便不把方向未知解释成缓和。
22. 作为模型使用者，我希望看到指标时序、宽限与信号成熟度的现有说明，以便理解为何尚未计为反证。
23. 作为模型使用者，我希望库存区同时显示象限、需求、生产和库存依据，以便理解库存周期结论。
24. 作为模型使用者，我希望仓单按品种和统计期展示真实缺失与变化，以便不把单个库存数据重复计入确认度。
25. 作为模型使用者，我希望阶段色带区分正式阶段、非典型组合和数据待处理，以便看清实际发布的阶段历史。
26. 作为模型使用者，我希望历史更正、未重算和无法更正有明确说明，以便不把更正后的核心结论当成宏观全部重算。
27. 作为模型使用者，我希望查看发布时间、首次可用时间和下次检查信息，以便理解数据沿用与等待发布。
28. 作为模型使用者，我希望数据说明分别呈现仅模型用到和目录全部两种完整度口径，以便区分核心结论可用性与目录覆盖。
29. 作为模型使用者，我希望正常等待发布、上游缺失、取数失败、来源冲突和原因未记录分别展示，以便决定下一步是否需要处理。
30. 作为模型使用者，我希望首页解读匹配当前投影的最新报告版本，以便不把其他日期的解释混入当前结论。
31. 作为模型使用者，我希望非典型解读列全所有只差一项资产的典型组合，而不选一个猜测阶段，以便理解差异而不被引导成正式判断。
32. 作为模型使用者，我希望 AI 不可用时看到标注“确定性模板”的事实段，以便仍能阅读结果且知道解释来源。
33. 作为模型使用者，我希望旧投影未提供新字段或报告尚未生成时如实显示，以便不把兼容空态当成新的 AI 故障。
34. 作为模型使用者，我希望保留报告生成、历史选择与正文阅读，以便复查当时实际发布的内容。
35. 作为模型使用者，我希望点击指标数值或图点进入对应证据，以便核对其选值、日期与来源。
36. 作为模型使用者，我希望在数据链路页按指标、维度和统计期搜索，以便从已知数据点直接开始调查。
37. 作为模型使用者，我希望证据链展示选中声明、其他来源、冲突与修订，以便理解系统为什么使用这个值。
38. 作为模型使用者，我希望同定义的跨目录版本归并被标明，以便理解历史证据的连续性。
39. 作为模型使用者，我希望派生指标可递归展开公式与输入版本，以便追到参与计算的实际原始观测。
40. 作为模型使用者，我希望查看获取回执及实际留存的原文，以便核对来源交付与解析结果。
41. 作为模型使用者，我希望原件超出留存、从未留存和校验失败分别说明，以便不把追溯不可用误认为当时取数失败。
42. 作为模型使用者，我希望证据深链可刷新、可返回，并保留原投影与筛选条件，以便调查过程中不会悄悄切换数据。
43. 作为运行维护者，我希望按来源、环节、结果查看取数桑基图，以便了解请求走过哪些路径。
44. 作为运行维护者，我希望请求、声明、候选和缺期各自标明计数单位，以便不误读图中流量。
45. 作为运行维护者，我希望检索降级链显示每层尝试、跳过、终止及原因，以便知道补缺为什么走到这一层。
46. 作为运行维护者，我希望未完成期由 Worker 留下逐期原因，以便不依赖手工对照指标名猜测。
47. 作为运行维护者，我希望筛选来源、环节、结果或指标后图表与明细一致更新，以便缩小调查范围。

52. 作为运行维护者，我希望重复点击只提交一个有效命令，并明确受理结果，以便避免重复工作。
53. 作为运行维护者，我希望运行页的刷新不打断阅读或重置筛选，以便持续观察任务。
54. 作为已有用户，我希望旧八页书签仍能进入对应内容，以便不丢失常用入口。
55. 作为桌面用户，我希望紧凑表格、清楚的数值对齐和稳定的字号层级，以便在一屏内比较足够多的信息。

59. 作为维护者，我希望绑定地址、端口与允许访问的 Host/Origin 可以配置，以便在 dot 访问方式确定后接入而不重写前端。
60. 作为项目负责人，我希望离线回归与真实数据验收各有明确证据，以便知道哪些行为已验证、哪些仍待实际运行确认。

## Implementation Decisions

### 1. 决定优先级与架构

- 以现行 GLOSSARY、已接受 ADR、2026-10-15 报告解读决定为语义依据；第二轮访谈覆盖第一轮的信息架构，原型负责呈现参考。原型脚本、示例数值和过时文案不成为新模型规则。
- 保留 Dash、Plotly、FastAPI、SQLite WAL 与独立单 Worker。Web 查询已发布材料和提交现有命令；不在请求、回调或浏览器内抓取数据、调用 AI、计算趋势或推导阶段。
- 本批次新增展示契约及必要的持久化、查询接口；不改变生效模型、六阶段映射、趋势参数、选源规则、确认关系、取数日程或留存政策。
- 维持当前指标目录范围，不把“61”写成永远固定的 UI 数量；从本投影对应的目录/模型身份取得实际成员。旧项目未接入指标不显示为本批次待补数据。

### 2. 页面结构与旧入口

- 主入口为报告式首页。两个二级入口为“数据链路”“运行状态”。桌面目录常驻且当前段落可辨；窄屏采用可操作的紧凑目录。首页七段顺序固定如下。

| 段落 | 必须呈现的内容 |
|---|---|
| 周期识别结论 | 正式阶段/原因、三核心状态与候选、上次确认阶段、确认度摘要、确定性一句话说明、解读入口 |
| 三核心与同类资产 | 债/股/商三组，核心价格与 MA120，距离/斜率/候选，现有同类观察接口，价格内部一致性、债券归因 |
| 海外与汇率 | 当前目录中已接入的海外与汇率事实、统计期、频率、时效、证据入口 |
| 宏观事后确认 | 五维关键指标、关系计数、支持命题、主要/辅助成员、分化、时序、成熟度及缺什么 |
| 库存周期 | 库存象限及需求/生产/库存三线读法，已有库存与仓单事实，未分类原因 |
| 周期说明与阶段史 | 现有阶段含义说明、120 交易日色带、每日已发布版本、历史更正与回溯标识 |
| 数据说明与解读 | 两种完整度口径、时效/缺期与发布日历入口、方法说明、匹配投影的解读与报告历史入口 |

- 报告生成、历史列表和阅读作为首页所属的二级工作区保留；发布日历作为数据说明的展开工作区保留。不增设第四个顶级分区。
- 原核心资产、宏观、库存、阶段史链接定位到新首页对应段落；原发布日历和报告链接打开相应工作区；原运行链接进入运行状态。直接打开、刷新、前进后退均可达，旧的有效查询条件继续对应正确上下文。
- 完成迁移后移除旧八页平铺导航和重复页面实现；旧 URL 的兼容路由保留，不以删除旧测试来掩盖行为丢失。

### 3. 分析身份与刷新

- 一次分析页面显示共享一个不可变投影包络：投影、模型、证据快照、目标交易日、冻结截止点、生成时间、证据窗口与完整度。顶栏展示可读摘要，详细身份可展开。
- 首次读取后按投影身份读取分域数据；当前指针变化时，完整取得新包络及必要数据后统一切换。加载或失败期间保留上次完整视图并说明状态，禁止新旧卡片混装。
- 历史/证据深链固定其投影与截止点，不能随当前指针悄悄改变。补算日遵守其自身公开时间边界；目标日遵守运行冻结截止及现有期次规则，不能用“现在最新声明”替换当时选值。
- 报告、运行进度、日历实际发布事件可以独立更新，但注明它们的身份与更新时间。实际发布日历和投影内日历事实若来自不同时间，明确区分。
- 时间展示统一标时区，默认北京时间；保留完整时间用于展开和核对。不能只显示“最新”而丢掉目标日和截止点。

### 4. Worker 展示投影

- 单日汇总在现有冻结证据和目录身份下生成所需点列、变化与展示摘要，随分析数据一起原子发布。沿用观测选值、同定义归并和模型单位，不能移植原型“声明按日期最后一条覆盖”的查询。
- 展示字段至少表达：指标及维度身份、单位与频率、实际统计期、最新值、时效/沿用状态、点列日期与值、MA120 可得值、5/120 日比较的结果/种类/两端日期、不可得原因，以及可追溯的观测/选中版本引用。字段命名在实施票确定，语义必须一致。
- 三核心图展示窗口内最近 120 个交易日。每个 MA120 点使用该日对应的完整公式回看，不能拿“图上已有点”凑短均线。无足够输入的位置为缺值，曲线断开并解释；已有核心历史覆盖能力复用，不为美化图表扩展留存。
- 日频价格的“近 5 日”“近 120 日”是分别相隔 5、120 个交易日端点的收益，分别需要相应跨度的 6、121 个真实日点；三核心 120 日口径复用现有价格内部一致性。图中 120 个展示点与 120 日收益的比较基线是两个概念，基线日期必须可查。
- 对应市场日历、目标期和缺点判定沿用现有规则；核心目标日仅沿用旧收盘价时，最新值标注沿用，不能虚构目标日实际价格或收益。缺少可靠日历/端点时该项不可得，不退用窗口首点或按周一至周五猜日历。
- 利率/比例类差值明确标为百分点或基点，价格收益标为百分比；展示加工携带种类与单位，不套用一个涨跌公式。月度、季度、周频与事件值保留自身频率和既有读法，不重复铺成日线来制造“5 日变化”；不适用的列显示原因，走势使用真实统计期。
- 非核心指标仅展示现有规则已提供的状态/方向；不为填满 MA120 或候选列新增核心式判定。前端可格式化、筛选、切换图例，不能重算金融数值或关系计数。
- 老投影不原地补字段。缺新字段时说明“该版本未提供”，继续显示原有可用内容；新运行开始生成新契约，不要求历史全量回填。

### 5. 结论与确认度

- 正式阶段仅显示已发布结果。非典型组合是有效观测，阶段为空；核心不足、冲突或待定方向按现有 reason 分别说明。上次确认阶段是历史背景，不能占用当前阶段位置。
- 稳定方向、趋势切换候选及持续天数、30 日候选方向分开显示。确认门槛读取本投影规则，不能把即时 30 日候选配上趋势候选天数，也不能写死门槛。
- 确认度以关键指标等权计数，五维只负责分组。显示支持/反证/仅观察/未确认的项数与适用状态，展开可核对每项；新增全局摘要由 Worker 汇总已有关系，不把所有成员或派生指标再次计数。
- 旧访谈的“可评估 n/5＋支持率”由 ADR-0037 和现行术语覆盖。本批次不引入支持率或新的评分；不显示概率、胜率、维度投票或旧四项宏观单一标签。
- 无正式阶段时确认度不适用，五维读法仍展示；不能把事实缺失、方向未知或分化自动变成中性/支持。库存象限是一项，单个库存/仓单不重复计数。
- 同类观察接口、价格内部一致性、债券归因与宏观确认清楚分区并标明不计数。商品供需说明保留既有不确定性，不从价格上涨断言驱动来源。

### 6. 非典型解读与报告

- 复用已实现的固定标题“非典型组合解读”、Worker 对照依据与报告来源标记。两个非典型组合分别有三个只差一项的典型组合对照，必须展示完整；不排名、不命名“最接近阶段”、不改写正式阶段或阶段史。
- 确定性事实与 AI 解释分开。新非典型报告沿用既有受约束文本契约：完整事实段加经过校验的观察句；页面不扩写或再次生成建议。
- 当前首页选择同一投影的最新报告版本。AI 成功标识 AI 来源；两个适配器均失败时显示同标题事实段，来源为“确定性模板”，保留降级状态。结论区可摘要/链接到末段，不重复整篇报告。
- 对尚无报告、生成中、旧投影未含依据、正文超出留存分别显示对应空态。保证新非典型报告结束后的事实兜底可见，不把此保证扩张成旧历史均有解读。
- 报告历史选择后保留原报告身份与内容，不套当前投影改写正文。生成命令在受理时绑定投影，后续当前指针变化不能改变它的输入。
- 已实现的拒绝输出留存与原因审计继续可用；本批次不把 AI 报告包装成证据链，也不在普通运行摘要页展开被拒原文。

### 7. 阶段史与发布日历

- 色带使用现行阶段历史读模型的每日最新有效版本和更正关系。同一截止点有更正时按被替代关系选择，不能凭列表顺序或时间相等时任取一条。
- 不沿用原型 README 中“首次历史全部待处理，等日常累积”的旧假设。按现行核心历史规则展示已得到的逐日结果；真实失败日继续如实空缺。
- 历史卡能辨别整日更正、仅核心更正、仅上次确认阶段更正、上下文未重算、无法更正；不得借当前宏观事实填历史缺项。窗口外上次确认阶段注明回溯得出。
- 发布日历保留预计发布、实际发布、首次可用、沿用期、下次检查及关联观测；查询使用相应模型目录定义。不会因日历显示发布而自动把缺期标为已经获取。

### 8. 运行健康摘要与未完成原因

- Worker 在运行进入终态时留存运行健康摘要；成功、降级、失败和取消均有适用的结果。异常中断后恢复流程按真实已记录步骤收尾；尚未完成时显示进度与已知数据，不伪造最终摘要。
- 摘要包含运行/命令/投影身份、状态与下一步、受理/开始/结束时间、总耗时及分段耗时、请求与结果计数、实际预算消耗、缺期数及两种完整度口径、时效分布、来源→环节→结果分布。新增存储遵守现有窗口和原有记录不改写原则。
- 最终补缺计划对每个指标、维度、统计期记录实际状态与原因，能区分未发布、已持有/采用、来源未交付、校验拒收、请求失败、门禁跳过、预算/流程终止及原因未记录等现有情形。原因来自实际执行与规则结果，不靠指标名手写映射或前端猜测。
- “请求零失败”不能推出“数据完整”。仅模型用到与目录全部分别显示真正缺失，同时列等待发布等其他状态；已知缺口可说明背景，不自动从原有完整度计数中豁免。
- 上次对比使用同类命令及可比较口径，展示对比运行身份。模型、目录或摘要版本变化造成不可比时说明原因；首次运行或旧摘要缺失时不显示虚构增减。
- 运行趋势默认覆盖留存期内全部可用运行，可按类型与状态筛选。手动完整、计划完整、仅报告和定向任务可区分，不把报告生成耗时混成完整取数耗时。

### 9. 数据链路页与真实筛选

- 数据链路页分为取数流向、检索降级链、门禁与未完成期、证据追溯；运行状态页提供本次关键数和跳转入口。分析证据上下文与所选运行身份分别标明，默认选择本投影的产出运行，不静默用最新运行替代。
- 桑基图首版统一使用“请求数”。每个请求在来源、环节和终态分类上唯一归属，各层总数守恒；运行中单列进行中/尚无终态。重试算不同请求，缓存命中和未发请求的缺期不算外部请求。
- 声明、候选校验和缺期用独立计数及表格，注明单位。一请求多条声明、部分接受、零行应答都不能强行映射成等量“采用声明”；缺口不作为虚构请求流入桑基图。
- 降级链展示现有实际路径、每级结果、跳过及停止原因，不把未尝试画成失败。原型中的“来源/环节/结果/指标”等筛选成为真控件，影响相应图表和明细并显示筛选后数量；清空恢复默认，无匹配有明确空态。
- Web 只筛选 Worker 已生成的汇总/事实。筛选后的聚合统计由读模型提供，不能在浏览器从原始请求重新拼造事实；不把全站所有证据明细一次塞入首页。

### 10. 证据追溯与原件

- 采用竖向链和可展开的派生树：结论或数值 → 观测 → 选中/其他/冲突/修订声明 → 获取回执 → 原件。所有入口携带投影身份、指标/维度/统计期及冻结截止；从指标检索开始也先明确查询上下文。
- 复用现有观测、派生追溯和原件读取契约，补充指标＋统计期搜索、必要的版本绑定及递归展开能力。树按实际公式输入版本追溯，不在展开时重新按“最新值”选择父输入。
- 同定义的跨目录版本归并标识采用 ADR-0036；定义、单位、频率、维度或公式不同的观测不能为了画连续线而合并。
- 深层树按需展开，重复节点可引用，异常环或缺失父节点有明确状态；不能因一个父节点不可用使整条证据链消失。
- 原件操作真正打开留存内容或明确下载，普通文本/HTML安全呈现而不执行来源脚本。可从回执定位 raw/normalized，但不接受任意本地文件路径或借查看原件重新向外网取数。
- API 与页面区分观测找不到、原件未留存、留存过期、文件缺失及哈希校验失败；过期不是观测时效 stale，也不是当时获取失败。留存窗口外公式回看明细按既有政策不可得，不扩大留存或伪造可追溯性。
- 请求参数、哈希与原文不在运行健康摘要中铺开；必要回执细节只在主动打开的证据上下文中显示，沿用现有敏感信息保护。

### 11. 运行操作与访问配置

- 保留现有手动完整运行、报告生成、确认恢复、取消后续步骤及有效状态限制；若旧入口提供定向操作，也继续可达。受理结果、幂等键、正在执行与需要确认的区别可见，重复提交不产生重复工作。
- 沿用运行中约 30 秒、空闲约 300 秒的低频轮询；更新不重置筛选、阅读位置或键盘焦点。不新增 WebSocket、浏览器定时启动 Worker 或第二调度器。
- 绑定地址、端口、允许的 Host、允许的 Origin 是显式配置，启动、健康检查、HTTP 和命令校验读取同一配置来源。现有本机默认值可以保留，但不能成为新页面或测试中不可配置的部署假设。
- 允许/拒绝访问行为可测试；不通过放开所有 Host/Origin 解决访问问题。dot 的实际地址、隧道、代理和鉴权部署方案等实测决定，本规格不指定公网服务或多用户方案。

### 12. 视觉、交互与空态

- 采用定稿原型的报告密度、分段层级和债/股/商分组。桌面先看到结论和关键事实，表格数值右对齐、单位与统计期可辨；长标题和负数不截掉有意义的信息。
- 颜色搭配文字标签，涨跌、牛熊、确认关系、运行成败不能只靠颜色区别。明/暗主题覆盖 Plotly 图、表格、弹出层和空态，主题选择在本地保留并尊重首次系统偏好。
- 窄屏不出现整页横向溢出；宽表可在自身容器滚动，关键指标名和表头仍能理解。固定目录不能遮住锚点，详情返回恢复原位置和选择。
- 筛选、目录、图例、证据展开、原件操作、报告选择和运行按钮都有明确状态与键盘焦点。图表提供文字/表格等价读法，不要求仅靠悬停获得结论。
- 支持减少动画；加载、无匹配、首次空库、请求失败、数据不适用和旧字段缺失各有文案。交互资源加载前显示有意义的结论/运行状态或首次空库说明，不能只剩空白框。

## Testing Decisions

测试边界经代码核对后形成，详细理由见附带的测试分析。用户提出“需要分析一下”，本规格据分析给出实施方案，不记作用户已逐项批准。

1. **主要验收边界为已发布数据到用户可见行为。** 复用 Web 应用公开 HTTP、现有页面契约和真实浏览器入口，验证内容、状态、筛选、返回和请求结果。不以内部函数调用次数、组件嵌套或 CSS 字符串存在作为功能正确的证据。
2. **新投影事实走单日汇总入口。** 按 ADR-0034，准备隔离证据与真实交易日序列的离线夹具，发布并读取新投影，检查选中声明、单位、点列、比较日期、MA120 和不可得原因。预期值来自可手算样本，不调用同一生产计算函数生成。
3. **运行级材料走少量完整 Worker 用例。** 健康摘要、最终计划原因、发布与当前指针、报告关联、失败/取消/恢复及留存属于完整运行边界。复用已有公开命令和测试替身，避免每个表格/指标都跑整轮取数。
4. **保护冻结一致性。** 覆盖截止后修订、同截止更正、跨目录同定义/不同定义、当前指针在请求间前进、旧报告与新投影并存。断言图点、指标、证据和报告的身份关系，不只断言页面有某个数字。
5. **覆盖名义相同而口径不同的数值。** 至少包括 5/120 交易日端点、120 展示点与 121 收益端点、少点/缺日/沿用、百分比与百分点、低频不适用和未知方向；不得用首点回退让测试样本“总有值”。
6. **覆盖实际结论状态。** 典型阶段、两类非典型组合、核心不足/冲突、待定方向、首次空库；核对确认度按关键指标计数、仅观察不算支持、无阶段不适用，且五维事实仍可读。现有模型规则的详细组合用例复用，不在浏览器重做一套模型测试。
7. **覆盖报告来源与历史。** 同投影最新版本、AI 成功、双适配器失败的确定性模板、生成中、旧投影无新字段、正文过期。用离线适配器替身，不以真实 AI 每次生成相同句子为回归前提。
8. **覆盖健康计数与原因。** 一请求多声明、零行、拒收、重试、缓存、未发请求、取消和无上次可比运行；验证请求流守恒、计数单位、两种缺失口径、筛选后图表与明细一致，以及旧运行没有摘要时的诚实空态。
9. **HTTP 与浏览器各测其真实行为。** 现有端点函数直调用例可保留为快速反馈；新增真实 HTTP 覆盖参数/状态码、深链、原件错误语义、配置的 Host/Origin 与命令幂等。浏览器验证刷新深链、筛选、图表、递归展开、原件打开和返回；不能以路由函数相同代替。
10. **保留少量贯通冒烟。** 正常发布后从首页进入证据再返回；新非典型投影配确定性模板；运行失败未发布新投影时仍正确显示上次分析与本次失败。共享已有离线准备方式，不新增另一套模拟运行服务。
11. **视觉与可访问性验收。** 桌面和窄屏、明暗主题、键盘路径、减少动画、长表/长标题/空数据。用真实投影逐段对照原型，截图记录身份与视口；用行为断言保护交互，避免数据更新即大面积失效的像素快照门禁。
12. **执行规则。** 按项目测试说明运行受影响的具体测试与每切片既定两例冒烟；涉及 Worker 编排时补完整目录与三核心沿用/阻断用例。普通回归离线，每例独立可变库，不触碰正式运行库。终点真实运行前才跑一次全套，遵守时钟检查、重型锁和磁盘保护。非 editable 安装须更新实施用环境，不能误测旧包。
13. **终点关口 C。** 新站在本机使用新代码生成的真实投影运行，七段、二级页面、操作与旧入口逐项有证据；数据质量体检复核取数/模型结果，用户验收。记录实际版本、投影、测试范围、退出码与未解决限制；离线通过不冒充真实环境验收，不宣称证明了经济预测正确性。

## Out of Scope

- 改变 Pring 模型、六阶段映射、趋势参数、确认度预期表、选源规则或生成投资/仓位建议。
- 增加旧项目中的缺失资产、外部来源、新指标、长周期代理或新的 AI 自由判断。
- 重新访谈已确定的信息架构、生成多轮视觉 A/B，或把静态原型脚本变成另一套生产数据管道。
- 全量回放模型历史、回填旧报告解读、原地修改既存投影、扩大证据/原件留存窗口。
- AI 报告证据链、任意外部网页抓取器、原件编辑或补造已经清理的公式输入。
- 改造调度、另建任务队列、并行 Worker、WebSocket、重新选择前端框架。
- dot 宿主验收、数据迁移、密钥/登录交付、实际隧道/公网访问部署、多用户权限系统和生产切换。
- 本次规格编写即执行正式 Worker、真实 AI 调用或新前端代码实施。
