## 补验发现与修正

1. 空闲页受理命令后仍可能等待原 300 秒轮询：增加受理事件触发立即刷新并采用当前运行状态的轮询间隔。
2. 刷新会重置日期并重建可点击按钮：日期按会话持久化，命令在当前尝试终态前保持禁用，状态结束后释放。
3. 隐藏启动占位与交互内容使用重复 ID，键盘跳转落在占位区域：占位使用独立 ID，并在交互内容就绪后移除及释放观察器。
4. 报告重试按钮使用的投影定位与提交逻辑不一致：二者共用投影解析。此项来自 `command-refresh-review-result.md`，已修正。
5. 报告排队状态未计入首页刷新指纹：加入当前投影的报告运行。真实 HTTP 反例先失败（页面返回 no_update），修复后通过，5.06 秒；日志 `/tmp/pring-ui-report-refresh-red.log`、`/tmp/pring-ui-report-refresh-green.log`。这是全套期间用当前源路径执行的一个轻量 HTTP 检查，未改动全套固定安装。
6. “30 日候选”明确标为“30 日即时方向”，与趋势切换候选和持续天数分别阅读。
7. 真实运行的请求数可能在同一步骤中增长，但轻量运行身份没有变化：操作页刷新指纹纳入当前摘要，实际变化时重绘、未变化时保留视图。HTTP 反例先失败后通过，并验证无变化时不重建内容。
8. 真实计划有 3064 条需求明细，一次全部渲染使持续重绘明显变慢。改为每页 100 条，显示总数与页码，所有明细可翻页访问，筛选与运行身份保留；分页反例先失败后通过。最终相关 Web 回归 39 项通过（33.59 秒），稳定轮询反例另行通过（3.41 秒）。日志见 validation/live-poll-*.log、validation/pagination-*.log。
