# 02 — 双点时证据摄取与追溯

**What to build:** 让用户通过正式 CLI 摄取固定证据，并按公开点时或系统点时查询当时可见的规范观测；同一证据可以从版本化 REST 和最小证据追溯页查看来源、发布时间、首次系统可用时间、修订和派生血缘。

**Blocked by:** 01 — 本机离线启动与 doctor

**Status:** ready-for-human

- [x] 来源制品、来源声明、规范观测、派生观测、发布事件、获取尝试和修订 vintage 采用追加式存储，不原地覆盖历史。
- [x] 查询必须显式选择 `public_as_of` 或 `system_as_of`，发布前不可见和系统晚到行为分别正确。
- [x] 同一统计期的初值、复核值和修订值可以共存，旧查询与已冻结快照仍返回当时 vintage。
- [x] 多来源超出容差时保存全部声明与冲突，不平均、不静默丢弃候选。
- [x] `not_applicable`、`not_disclosed` 与获取失败、尚未发布、缺失明确分离，任何空状态不写成 0。
- [x] REST 与证据追溯页显示观测身份、值/值状态、单位、来源、四类时间、认证状态、质量、冲突和 supersedes 链。
- [x] 固定多频 fixture 覆盖最近 120 个中国交易日、月季已发布观测及必要基线，不伪造 120 条低频值。
- [x] `REG-PIT-001..007` 在临时 SQLite 上通过，测试只观察公开查询和追溯输出。
