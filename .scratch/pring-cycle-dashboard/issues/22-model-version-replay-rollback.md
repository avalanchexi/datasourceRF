# 22 — 模型升级、并行回放与30交易日回退

**What to build:** 让维护者创建后续候选模型，在可认证区间与当前模型并行回放、比较质量与稳定性、显式生效，并在新模型首次正式发布后的30个中国交易日内逻辑切回上一生效模型，而不改写任何发布历史。

**Blocked by:** 21 — 保留、容量降级与重新初始化

**Status:** ready-for-agent

- [ ] 任何会改变选值或分析结果的趋势、阶段、指标、来源认证、选源或派生规则变化创建新不可变模型清单。
- [ ] 候选模型只生成版本回放和验收产物，不影响当前正式运行或当前指针。
- [ ] 回放仅覆盖新旧模型可认证区间交集，来源认证前历史不能产生正式版本回放。
- [ ] 比较展示核心状态/阶段差异、质量、稳定性、缺口、回归和性能，并要求用户显式批准生效。
- [ ] 生效原子切换唯一模型指针；旧投影、报告、派生结果和验收记录保持可读且不覆盖。
- [ ] 从首次正式发布目标交易日起按中国交易日历含首日保证30个交易日可直接运行上一生效模型。
- [ ] 回退只切换生效指针，不恢复数据库、不删除新结果；被回退模型恢复为候选并需重新验收。
- [ ] 窗口结束后历史继续可读，但系统明确不保证旧模型仍可运行。
- [ ] 模型生命周期的CLI、页面、审计和离线测试使用同一正式接口。
