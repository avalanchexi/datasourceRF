# 21 — 保留、容量降级与重新初始化

**What to build:** 让维护者看到运行数据的保留与磁盘风险，按冻结规则清理非权威大对象，在空间不足或升级失败时安全降级或停止写入，并明确接受 V1 无运行数据备份、只能重新初始化的边界。

**Blocked by:** 20 — 报告生成、历史与阅读工作区

**Status:** ready-for-human

- [x] 未验证响应保留7天且上限1GiB、日志保留14天且上限200MiB、报告正文保留30天、孤立制品保留7天。
- [x] 被引用证据、结构化血缘、投影清单、运行身份、模型版本和报告结构化身份长期保留。
- [x] 清理只删除满足规则且未被权威对象引用的目标，过程幂等、可审计并支持失败重试。
- [x] 剩余空间20GiB警告、10GiB限制非核心大任务、5GiB停止Worker写入；页面读取继续服务上一完整投影。
- [x] 容量降级不得删除权威状态、伪造完成结果或自动切回旧系统。
- [x] schema/配置升级失败进入 `reinitialize_required`，不提供跳过验证或自动破坏性恢复。
- [x] `doctor` 和运行状态明确显示 `backup_mode=none`、RPO/RTO不保证、容量水位及重新初始化含义。
- [x] GitHub只管理源码与静态定义；SQLite、制品、报告、密钥和升级前状态不建立第二副本。
- [x] 故障注入覆盖清理中断、引用保护、三个容量水位和升级失败。
