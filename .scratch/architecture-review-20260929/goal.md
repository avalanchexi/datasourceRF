# Goal：架构加深 30 张票落地

## 目标

按 [README](README.md)「全局推荐顺序」逐张实施票 01–30，终点通过 `check.py full` 与一次真实完整运行。纯重构票保持可观察行为不变；差异修正票只改票面写明的行为。

## 完成判定

- [ ] 01–30 的 `Status` 均为 `done`（或经用户决定改为 `wontfix`），README 票表同步。
- [ ] 每张票单独提交，提交信息英文，沿用项目惯例。
- [ ] `check.py full` 通过一次，并记下耗时和最慢用例，与票 01 改动前的基线对比。
- [ ] 真实完整运行成功，核对票 03（广度血缘指向核心日历回执）、票 04（VIX／SOX／美债按当地日历判断应有期）。
- [ ] 模型 v0014 已由用户注册并激活，运行用的是 v0014。

## 每轮流程（一轮一张票）

1. 用户输入 `/implement <票路径>`；这一轮只做这一张票。
2. 按票面 TDD 实施；只读勘察交给 `codex exec`。
3. 收尾：按 `docs/agents/testing.md` 跑受影响测试与切片冒烟；更新票面 `Status` 和 `## Comments`、README 票表；提交。
4. 用户 `/clear`，进入下一张。

## 约束

- 票与票之间不并行（见 README「串行约束」）。
- 外部调用（TuShare 等）一律串行。
- 从 `src/` 直接导入调试时加 `PYTHONDONTWRITEBYTECODE=1`。
- 后台长任务约每 10 分钟报一次进度。
- C 盘空间不足时先清理再继续。
