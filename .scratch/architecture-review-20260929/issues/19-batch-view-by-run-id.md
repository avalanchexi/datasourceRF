## Comments

- **按运行 id 归属**已在票 17 提交（`3831c2b`）：记录了 `run_id` 的尝试只归该运行，并可越过受理时间边界；没有 `run_id` 的旧记录才退回时间区间，随留存期删除。本票未再改动。
- **统一排序**：`latest` 与批次视图都先按精确记录时间（换算到 UTC 比较），同一时刻再按写入顺序（rowid）排序。原来 `latest` 在同一时刻按哈希 id 排，批次视图按时间字符串排；字符串在不同时区偏移下会排错。
- **目录过滤**：
  - 批次视图只读该运行所用模型的目录版本。没有目录字段的旧记录保留；模型不在册时不过滤。
  - LPR 发布日历把目录版本传给 `latest`，原来没传。
  - P2 与 ECB 补记原本就传了目录版本。
- **可观察变化**：
  - 其他目录的失败不再改变本批缺口清单的类别，其他目录的成功也不再清除本目录的失败。
  - 同一时刻的多条尝试改为取后写入的那条，可能改变 ECB 补记的判断。
  - LPR 日历在系统时间模式下不再被其他目录的失败覆盖。
- **只记录、不修**：
  - rowid 是正常追加时的落库顺序，不是持久序号：`VACUUM` 可能重编号，项目里没有执行 `VACUUM`。
  - 无运行 id 的旧记录，时间区间仍按 ISO 字符串比较。这是过渡期的旧行为，随留存删除。
- **测试**（先红后绿）：`test_acquisition_outcome.py`
  - 排队运行沿用票 17 那例。
  - 恢复旧运行：旧运行恢复后的记录只归它，下一运行只见自己的；目标日视图跨批次取到当日最新的那条（同目标日跨批次）。
  - 同一时刻并列：跨时区偏移写入，后写入者胜。
  - 目录不符：批次视图和指定目录的目标日视图都排除。
  - 改动前，并列与目录两例失败。
- **验证**（`PYTHONPATH=src`）：
  - 完整运行集合加读取获取结果、发布日历、缺口清单的测试文件，共 70 个文件，936 过 1 败（54.8 分钟），其中包括两例冒烟。
  - 失败的是 `test_lpr_gap_uses_a_recorded_source_failure_after_the_release_window`：它手工写入的 LPR 失败记录没有目录版本，被新的目录过滤排除。真实写入方自票 17 起都带目录版本，所以给夹具补上目录版本，重跑该文件与获取结果测试共 50 例全过。
