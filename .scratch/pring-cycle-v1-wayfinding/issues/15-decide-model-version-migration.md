# 确定模型版本升级、历史重算与可比性边界

## Question

当120日趋势参数在实际试运行后调整，或核心资产来源、指数方法和指标定义发生变化时，`model_version`、趋势规则版本、来源认证版本及派生观测应如何共同升级？需要冻结历史重算是生成并行版本还是覆盖旧结果、不可变报告是否永不回写、新旧阶段时间线如何比较、默认页面选择哪个版本，以及迁移失败时如何回滚，确保参数优化不破坏历史可追溯性。

## Answer

模型升级采用[ADR-0012：模型升级采用原子版本、并行回放与限时逻辑回退](../../../docs/adr/0012-atomic-model-versions-and-parallel-replay.md)。

### 版本身份与升级边界

- `model_version`是一套经过认证且不可变的完整规则清单，固定趋势规则、阶段映射、指标定义、来源认证与选源规则及派生公式的具体版本；各组件保留独立版本用于血缘，但生产运行不得自由混搭。
- 模型使用永不复用的递增显示编号，例如`model-v0001`，同时保存内部ID、不可变清单哈希、创建时间、前置版本和变更理由；不使用SemVer表达分析口径兼容性。
- 改变公式、规则、选源行为或结果生成逻辑的参数调整和错误修复必须创建新的组件版本与模型版本。只改善获取能力、产生新证据vintage但不改变规则含义的修复不升级模型版本。
- 升级复用身份和定义均未变化的来源制品、来源声明与基础证据观测；从变化的指标定义、选源规则或公式开始，沿依赖闭包生成新的派生观测、核心资产状态、正式阶段与分析投影，不复制整库、不原地修改，也不得遗漏下游重算。

### 候选、生效与历史

- 新版本先成为候选模型版本，只能用于离线校准、版本回放、影子运行和验收。完成数据质量、稳定性、回归与差异检查并经用户显式批准后，才原子切换为唯一生效模型版本；每次运行在创建时固定其模型版本，不随当前指针变化。
- 发布历史保存系统当时在生效模型下实际发布的投影与报告；版本回放让选定模型使用历史点时证据生成并行时间线。两者永不互相覆盖，版本回放不得冒充当时发布结果。
- 每个模型声明不早于相关来源认证生效日的可认证回放区间。后来才认证的更早历史不能生成正式版本回放或进入发布历史；通过历史口径与质量验收后，只可作为离线校准和当前状态初始化预热输入。
- 新旧模型只在各自可认证回放区间的交集上比较，至少输出阶段一致率、转换日期差异、确认延迟和不可判定比例；缺口保持为空，不使用代理或最新修订值强行补齐。

### 页面、报告与失败处理

- 当前驾驶舱始终显示唯一生效模型。历史页默认显示生效模型的版本回放并醒目标记，用户可以切换到发布历史或显式选择两个模型比较；打开旧报告时始终显示其固定的原始模型和证据快照。
- 版本回放默认只生成结构化时间线和确定性差异摘要，不自动调用AI。用户可以显式为某日期和模型版本生成标记为版本回放的新不可变报告快照；原报告永不改写。
- 未通过验收的候选版本长期保留清单、哈希、变更理由、验收结果、差异摘要和拒绝状态；未被报告或决策引用的大批量回放制品可按未引用制品策略清理。
- 候选版本在独立命名空间构建，失败不影响当前生效版本。模型回退由用户显式触发，只原子切换生效指针，不恢复数据库、不删除较新版本结果，也不改写发布历史。
- 回退保证从新模型首次正式发布分析投影的目标交易日起，按中国交易日历含首日计数30个交易日；项目停机或漏跑不暂停计数。窗口内当前程序和数据库结构必须同时支持当前模型与上一生效模型运行。回退后较新模型恢复为候选状态，重新生效必须重新验收。
- 第30个交易日结束后，旧投影、报告、版本清单和验收记录继续可读，但不再保证旧模型可直接运行；再次启用必须作为候选版本重新验收。
