# 定义 Markdown 页面与只读投影契约

## Question

在暂不制作视觉原型的前提下，用 Markdown 锁定首页、资产详情、宏观证据、库存特征、发布日历、历史阶段、报告和检索状态页面的导航、信息层级、字段、空状态、故障状态、刷新动作与来源追溯。每个页面依赖哪个只读投影？如何确保正式阶段、转折观察和宏观确认不会在文案或布局语义上混淆？

## Answer

已冻结[《Markdown 页面数据与只读投影契约》](../assets/markdown-page-and-read-projection-contracts.md)：V1 将周期总览、核心资产、宏观、库存、发布日历和阶段历史拆为共享同一 `projection_set_id` 的原子分析投影集；报告、任务和检索采用独立运行读模型并显式关联投影版本。三个资产采用共同趋势骨架和资产专属确认扩展；宏观四组状态与库存七类特征保持独立，不产生综合分数。历史保留每日核心状态、正式阶段及非典型/P0不可用空档；未认证来源保留定义但不填值或自动使用代理。

契约同时冻结公共数据包络、各数据集字段、空值/降级/故障语义、幂等刷新命令边界和证据追溯入口，不涉及布局、图表、配色或 Dash 组件。原子一致性选择另记为[ADR-0008](../../../docs/adr/0008-atomic-analytical-projection-sets.md)。

## Comments

### 2026-08-21 第一轮确认：导航、投影一致性与语义层级

- 导航分为“周期判断”和“运行与追溯”。前者包含首页、参数化核心资产详情、宏观证据、库存特征和阶段历史；后者包含发布日历、报告和运行状态。股票、债券、商品不复制三套页面契约。
- 当前页面统一绑定同一个完整只读投影版本；Worker原子发布新投影前继续展示上一份完整投影，禁止不同卡片混用不同截止时间。页面顶部显示`system_as_of`、`projection_version`、最近完整更新时间和刷新状态。
- 首页信息层级严格区分：当前正式阶段、三核心资产状态、资产候选状态与转折观察、宏观事后确认、数据时效/冲突/运行状态。`current_stage=null`时主标题为“当前阶段暂不判定”，上一确认阶段只能作为次级历史信息。
- 删除“候选阶段”说法；领域中只有资产候选状态和转折观察，不得伪装成正式阶段预测。
- 首页和详情使用当前`system_as_of`投影；历史回放集中在阶段历史页并显示明显的只读历史标识，不设置全站时间切换器。`public_as_of`无前视校准不混入日常首页。
- 指标卡默认展示值、统计期、变化、时效和来源机构；“查看证据”进入完整追溯，包括实际发布时间、系统可用时间、vintage、质量、冲突和已验证来源链接。
- 本票只定义报告列表、生成状态、快照元数据、安全Markdown容器和证据入口；AI报告正文结构留给“原型化证据约束的AI报告契约”。
