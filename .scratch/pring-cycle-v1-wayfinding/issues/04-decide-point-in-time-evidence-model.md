# 确定 point-in-time 证据模型与修订语义

## Question

证据观测、发布事件、来源版本、修订 vintage、派生指标和报告快照应如何建模，才能同时支持 `as_of` 查询、月季数据按真实可用时点生效、同一观测不重复计数、来源冲突、修订回放和不可变报告？需要锁定实体边界、身份键、时间字段语义、状态转换和最小查询契约，但不在本票选择具体数据库。

## Answer

已锁定[《Pring 周期驾驶舱 V1 point-in-time 证据模型》](../assets/point-in-time-evidence-model.md)，并接受[ADR：证据采用双点时语义和不可变版本](../../../docs/adr/0006-dual-as-of-and-immutable-evidence-vintages.md)。

模型同时支持按可靠公开时间的 `public_as_of` 和按系统首次验证时间的 `system_as_of`；来源声明、规范观测、修订vintage、派生观测与报告快照分层且追加保存。指标身份、实际发布事件、预期发布窗口、合法空值、选源冲突、分优先级时效、状态转换和四类最小查询均已冻结，不在本票选择数据库。

P0过期或来源冲突时不产生新的当前阶段；P1/P2旧值继续展示但按角色降级。获取失败不创建空观测，历史回填不能伪造公开可用时间。报告截止后到达的数据不修改旧快照，同一业务日重跑产生新快照版本。

## Comments

### 2026-08-20 第一、二轮已确认

- 同时支持公开点时查询与系统点时查询；前者按可靠实际发布时间用于无前视校准，后者按系统首次验证时间重现页面和报告。
- 来源声明与规范证据观测分离；同一经济事实的多来源值不重复计票。
- 修订与回填只追加新vintage，旧版本永久可重放。
- 环比、同比、累计等分别建模为标量指标；一次实际发布事件可以关联多条观测，不建立虚构的统一月度发布事件。
- 每个指标使用独立预期发布窗口和宽限期；沿用上一期只展示，不生成每日新观测。
- 统计观测身份由指标定义版本、统计期和规范维度确定；来源、抓取时点和vintage不改变经济事实身份。政策事件优先使用官方事件编号，缺失时按事件类型、公告时点和来源识别。
- 历史回填有准确发布时间则使用；只有发布日期时从次日00:00进入公开点时查询；没有可靠日期时只能从系统首次验证时间进入，不得用于更早校准。
- 派生观测绑定公式版本、确切输入观测ID和计算as-of；输入修订生成新的派生vintage。
- P0过期时不产生新的当前阶段；P1过期后只展示、不作当前转折或宏观确认；P2过期后带警告作为历史背景。
- 默认时效：日线至下一预计完成时点、T+1至第二个中国交易日、计划月季数据至窗口后1个工作日、无固定日期月度数据至独立窗口后2个工作日、国际日频至一个完整来源市场交易日。稀疏政策事件本身不因无新事件过期，只监控来源扫描健康。

### 2026-08-20 第三轮已确认

- 指标定义冻结主源、认证后备源、误差容忍和选择规则；来源冲突不平均。P0冲突不产生新阶段，P1冲突不形成当前验证，P2显示主源值与冲突警告。
- `available_at` 是首次取得并通过字段、单位、统计期和质量校验的时间；重复抓取不改写，内容变化形成新vintage。
- 当前页面按系统点时选择最新已验证vintage；无前视校准按公开点时选择当时已发布vintage；历史报告固定生成时观测ID，按今日修订值回看只能是显式研究模式。
- 尚未发布、无权限、限频、源失败和解析失败只形成分类明确的获取尝试，不创建空的来源声明或证据观测。
- 最小查询契约包括规范观测、实际发布事件、观测血缘/冲突、冻结快照清单；生产查询必须显式传入`as_of`和`public/system`模式，并返回时效、质量、选源状态与来源ID。

### 2026-08-20 最终轮已确认

- 所有真实时刻保存为UTC并保留来源时区，as-of边界包含；统计期使用起止、类型和日历表达。
- 官方合法空值区分`reported_value/not_applicable/not_disclosed`，与尚未发布和获取失败分离。
- 获取尝试、来源声明和规范观测各自使用独立状态；校验失败不升级为来源声明，历史不物理删除。
- 报告快照冻结数据、来源、规则、AI与输出清单；晚到数据不修改旧报告，重跑生成新版本。
- 完整Markdown保留30天不可变；结构化快照、阶段、血缘、规则和哈希长期保留。
