# 锁定 V1 实施顺序与验收计划

## Question

在所有数据、模型、架构、页面、报告和运行决策已解决后，如何把最终蓝图拆成可独立验证的里程碑、依赖顺序和验收门？必须明确每个里程碑的可运行成果、测试证据、数据质量门槛、失败降级、旧项目只读对照、文档交付，以及达到什么条件才允许切换到新系统。该票解决后，地图应没有需要实现者自行猜测的产品或架构决策。

## Answer

已冻结[《Pring 周期驾驶舱 V1 实施与验收计划》](../assets/v1-implementation-and-acceptance-plan.md)。

计划采用七个逐步可运行里程碑：工程与领域骨架、点时证据与确定性核心、真实P0与首个候选模型、完整P1证据层、本地产品运行面、报告与运维降级、最终验证与直接切换。每个里程碑都有统一无凭据验收命令、离线fixture、失败降级、真实源抽样、文档和追踪矩阵；35个`REG-*`已逐项分配到具体里程碑和计划测试路径。

切换硬门冻结为：P0最近120个中国交易日及必要预热通过质量验收；全部P1实现离线契约并按独立适配器/Schema族完成真实烟雾；P2允许显式未认证；确定性回放与原型统计复现；固定本机性能/RSS预算；报告实现完整但CLI运行时失败可确定性降级；文档在干净环境演练。切换前只做一次最新完整目标交易日的真实端到端演练，不设置多日生产影子。

最终由统一CLI校验不可变切换清单且不允许强制绕过，用户显式确认后执行单向系统切换。切换后旧项目只读保留但不再运行或降级；首次失败只在新系统内修复、恢复或重新初始化。当前早期规格与12张实现票不得直接执行，下一步必须经`/to-spec`和`/to-tickets`按本计划重写。

## Comments

### 2026-08-28 第一轮方向

- 实施采用逐步可运行的纵向里程碑；每个里程碑必须有离线fixture、真实接口接缝、可执行命令或页面、自动化测试和明确退出门，未通过退出门不得开始依赖它的下一里程碑。
- 用户不采用新旧系统生产影子共存，要求直接切换；“直接切换”的精确触发点与旧项目切换后保留边界待下一轮确认。
- 报告协议、Codex/Claude CLI适配器、后置校验、超时/取消和确定性降级必须实现并通过测试；切换当天CLI不可用不阻塞，只要结构化驾驶舱和`completed_degraded`正常。
- 切换前，三个P0核心必须完成身份、权限、历史、时点和当前数据认证；全部P1必须有可运行适配器或派生链并通过至少一个真实发布/交易日烟雾测试。P2可以明确保持`awaiting_source_certification`，不得用代理补齐，也不阻塞切换。

### 2026-08-28 第二轮确认

- 不设置生产影子期。旧系统维持只读现状，直到新系统通过全部里程碑、数据门和最终验收；用户执行一次显式系统切换后，新系统立即成为唯一受支持的结果生成路径。旧目录继续只读保留作故障证据，不再运行、双写或提供降级结果。
- 实施采用七个可运行里程碑：工程与领域骨架；点时证据与确定性核心；真实P0与首个候选模型；完整P1证据层；本地产品运行面；报告与运维降级；最终验证与直接切换。
- 每个里程碑必须提供统一验收命令，包含无凭据自动化测试、固定输入离线端到端fixture、外部适配器成功/失败形状、独立脱敏真实源烟雾结果、`REG-*`/规格/ADR追踪表以及失败与降级用例；日常测试不得联网或依赖账号。

### 2026-08-28 第三轮方向与确认

- 用户把数据质量硬门从“三核心最近240个交易日、逐个P1真实烟雾”调整为“三核心最近120个交易日、P1抽样验证”；窗口前预热如何验收以及P1按何种单位抽样仍待下一轮确认。
- 确定性模型与回放硬门采用推荐方案：35个`REG-*`全通过；固定输入离线重放结果确定；冻结夹具复现21次资产方向转换、11次正式阶段变化、20交易日内快速资产/阶段反转均为0和23交易日中位确认延迟；历史输入无前视；调参只能形成新候选模型；`model-v0001`须用户显式批准。
- 本机性能门采用推荐预算：REST本地p95不超过500ms，Dashboard首次有意义内容不超过3秒，命令持久化应答不超过1秒，Web/Worker冷启动不超过15秒，缓存证据下单日确定性投影不超过60秒，2018年以来校准/回放不超过15分钟，无网络测试不超过10分钟，空闲RSS不超过1.5GiB且完整回放峰值RSS不超过4GiB。外部请求与AI耗时另计，页面读取不得触发外部调用。
- 文档是里程碑退出门；最终必须覆盖安装初始化、密钥迁移、doctor、手动完整运行、数据状态、故障恢复、无备份风险、容量降级、模型升级/回退、CLI报告故障和重新初始化，并在干净环境实际演练命令。

### 2026-08-28 第四轮确认

- P0对外数据完整性硬门只统计最近120个中国交易日；模型清单声明的必要预热数据仍必须存在并通过相同的身份、单位、交易日和连续性校验。预热只用于计算，不扩大120日完整率或页面证据窗口。
- 所有P1指标必须有离线契约测试；真实源烟雾按独立适配器、端点或解析Schema族抽样，共享响应结构的多个指标共用一次烟雾证据，独特身份/单位/时间/解析逻辑必须单独抽样。本地派生只用固定输入验证公式和血缘。

### 2026-08-28 第五轮确认

- 不做多日生产影子；切换前必须完成一次最新完整目标交易日的真实端到端演练，串通手动运行、P0/P1获取、原子投影、Dashboard以及AI成功或确定性降级；另用fixture完成一次Worker中断与显式恢复演练。演练结果不进入正式发布历史。
- 最终生成不可变切换清单，固定Git提交、依赖锁、数据库Schema、配置Schema、指标目录、模型/趋势/报告版本、测试结果哈希、数据质量、真实源烟雾、性能、文档演练和已知P2缺口。统一CLI机器校验全部硬门且不提供强制绕过；通过后仍需用户显式确认系统切换。
- 首次系统切换是单向门：旧项目此后只保留为只读证据，不重新成为支持的生成路径。新系统故障只能修复、显式恢复或按无备份决策重新初始化；30个中国交易日的模型回退只适用于新系统内部后续模型升级。
