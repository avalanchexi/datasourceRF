# Markdown 页面数据与只读投影契约

> 状态：V1 Wayfinder 决策资产。  
> 范围：定义页面消费哪些数据、字段语义、版本一致性、空值/故障状态、刷新命令和证据追溯；不定义布局、图表、配色或 Dash 组件。  
> 数据范围以[《Pring 周期驾驶舱 V1 数据盘点》](v1-data-inventory-summary.md)和[《V1 冻结指标目录》](v1-metric-catalog.md)为准。

## 1. 不变量

1. 正式阶段只能是 Stage I–VI 或空，只由债券、股票、商品三个核心资产状态机械映射。
2. 资产候选状态和转折观察不是候选阶段；宏观、库存及国际证据不能改写正式阶段。
3. 当前分析页面只能读取一套已完整发布的分析投影集，不能混合不同 `system_as_of`、数据快照或模型版本。
4. Worker 构建新分析投影集期间，当前指针继续指向上一套完整投影；全部必需数据集通过校验后再原子切换。
5. 浏览器和 Dash 回调不得重新计算均线、趋势状态、正式阶段、宏观状态或库存状态。
6. 运行状态和报告生成状态可以独立更新，但必须携带其关联的 `projection_set_id`；不得让运行时变化改写已发布分析投影。
7. 未认证来源只保留指标定义和 `awaiting_source_certification`，不得填充占位值或自动采用代理指标。
8. 低频指标沿用上一期时保留原统计期、发布时间和时效状态，不复制成当日观测。
9. 搜索结果和 AI 文本不是证据；只有已验证证据观测可以进入分析投影和报告证据包。

## 2. 投影拓扑

### 2.1 原子分析投影集

一套分析投影集由以下独立数据集组成，共享同一个 `projection_set_id`：

| 数据集 | 参数 | 主要用途 |
| --- | --- | --- |
| `cycle_overview` | 无 | 当前正式阶段、三资产摘要、转折观察、宏观确认和数据完整性 |
| `core_asset_detail` | `asset=equity|bond|commodity` | 核心趋势共同骨架及资产专属确认数据 |
| `macro_evidence` | 无 | 政策方向、过热程度、物价压力和国际环境 |
| `inventory_cycle` | 无 | 四象限库存状态和七类独立特征 |
| `release_calendar` | 日期范围、优先级 | 预计发布窗口、实际发布、系统取得及当前时效 |
| `stage_history` | 日期范围 | 正式阶段区间、空档、每日核心资产状态及转换观察事件 |

`evidence_trace` 是按证据身份读取的参数化追溯数据，不复制进每个页面数据集。它必须能够按照当前或历史 `projection_set_id` 重放当时引用的观测版本。

### 2.2 独立运行与报告读模型

以下数据不参与分析投影集的原子完成条件：

| 数据集 | 更新方式 | 关联键 |
| --- | --- | --- |
| `report_index` | 报告排队、生成、失败、完成或过期时更新 | `projection_set_id`、`report_snapshot_id`、`run_id` |
| `runtime_status` | 任务、来源健康、检索预算和恢复状态变化时更新 | `run_id`、目标/产出 `projection_set_id` |
| `retrieval_trace` | 每次获取尝试追加 | `retrieval_attempt_id`、`run_id`、指标或发布事件 |

运行读模型可以比分析投影更新得更频繁。页面读取它们时必须显示各自的 `updated_at`，不得把它们的更新时间冒充分析数据截止时间。

## 3. 公共数据包络

每个分析投影数据集必须包含：

| 字段 | 语义 |
| --- | --- |
| `schema_version` | 当前数据集结构版本 |
| `projection_set_id` | 同一套原子分析投影的不可变身份 |
| `projection_version` | 面向人的单调版本号，不替代不可变身份 |
| `system_as_of` | 这套投影实际可使用证据的系统截止时间 |
| `data_snapshot_id` | 规范观测及其 vintage 的不可变快照 |
| `metric_catalog_version` | 冻结指标目录版本 |
| `model_version` | 正式阶段模型版本 |
| `trend_rule_version` | 120 日趋势状态机版本 |
| `evidence_window_start/end` | 最近 120 个中国交易日形成的证据窗口 |
| `generated_at` | Worker 完成该数据集的时间，不是数据发布时间 |
| `completeness` | `complete`、`degraded` 或 `stage_unavailable` |
| `warnings[]` | 结构化缺失、陈旧、冲突、未认证和初始化警告 |

每条 `warning` 至少包含 `code`、`severity`、`scope`、`metric_id`（可空）、`reason`、`first_seen_at` 和证据入口（如适用）。密钥、认证头、完整外部响应和未脱敏提示词禁止进入任何投影。

## 4. 周期总览数据集

`cycle_overview` 必须输出：

- `current_stage`：Stage I–VI 或空；
- `last_confirmed_stage`：只作历史上下文；
- `stage_started_at`、`duration_trading_days`、`stage_mapping`；
- `stage_unavailable_reason`：非典型组合、P0 缺失/陈旧/冲突或初始化不足；
- 三条 `core_asset_summary`：核心指标、稳定状态、候选方向/持续天数、30/120 日收益、MA120 距离、噪声带、斜率、时效和选择状态；
- `transition_watches[]`：目标资产、证据角色、方向、开始和持续时间、支持证据、反证、时效及冲突；
- `macro_confirmation`：政策方向、过热程度、物价压力、库存状态和国际环境可用性，各自独立；
- `change_reasons[]`：相对上一完整投影的新观测、修订、越阈值、候选完成/取消和版本变化；
- P0/P1/P2 缺失、陈旧、冲突及未认证来源的计数。

`current_stage=null` 时必须同时给出确定性原因，且不得从 `last_confirmed_stage` 或宏观状态推断当前阶段。

## 5. 核心资产详情数据集

三个资产使用同一共同骨架：

- 核心身份、代码、来源、价格/收益口径和认证状态；
- 原始价格/连续收益链、MA120、MA120 距离、`σ20`、`1.5×σ20` 噪声带、20 日均线斜率；
- 120 日稳定状态；
- 候选方向、已持续/要求持续天数、最近中断原因和冲突持续天数；
- 30 日快速方向和转折观察；
- 月末价格、12 月均线、12M 代理状态及与 120 日的背离；
- 状态变化、候选开始/取消、不可用和规则版本变化事件；
- 每条序列的统计期、时效、来源冲突、缺口及证据身份。

资产专属扩展为：

- 股票：沪深300、中证500、中证1000，最近120交易日市场广度，融资和 P2 估值；
- 债券：两个价格确认指数，以及 DR007、政策利率、利差和 Shibor 的市场传导；收益率必须标明与债券价格方向相反；
- 商品：NHCI、七袖套方向/贡献、注册仓单和 NHII 无生猪认证状态；七袖套不得自我确认或运行时接管核心。

专属确认数据不能填入核心状态字段，也不能获得阶段投票权。

## 6. 宏观证据数据集

`macro_evidence` 独立输出四组结果，不产生宏观总分：

1. `policy_direction`：政策行动、市场传导和信用响应三层证据，结果为宽松、收紧、中性、传导冲突或数据不足；
2. `overheat_state`：订单、生产、产能、利润和信用，结果为升温、过热、降温或数据不足；
3. `price_pressure`：商品/原油、PMI 价格、PPI 生产资料、PPI 生活资料、CPI、核心 CPI 的传导层级，结果为上游压力、生产端扩散、消费端扩散、回落或数据不足；
4. `international_context`：纽约金、伦敦金、Brent、WTI、美债 2Y/10Y/2s10s、VIX 和 SOX 的 P2 背景及来源认证状态。

每组结果必须包含 `state`、`as_of`、`supporting_evidence[]`、`contradicting_evidence[]`、`insufficient_evidence[]` 和规则版本。国际指标未认证时只输出定义和认证状态，不输出数值、代理值或推测方向。

## 7. 库存周期数据集

`inventory_cycle_state` 只能是主动去库存、被动去库存、主动补库存、被动补库存或空。空时必须区分数据不足与证据冲突。

七类 `signature` 独立保存，不汇总投票或计算库存总分：

1. 订单－库存差；
2. 原料－产成品关系；
3. 实际库存；
4. 库销/周转；
5. 价格－利润；
6. 产能；
7. 信用/注册仓单。

每类记录包含 `signature_type`、`state=support|conflict|insufficient`、方向、证据、反证、统计期、时效、公式版本和说明。注册仓单必须标明不等于全部产业库存。

## 8. 发布日历数据集

每个真实发布族或指标记录包含：

- `expected_release_window` 及规则来源；
- `release_at`、`public_available_at`、`available_at`；
- 统计期、频率、来源时区、宽限期；
- 当前展示值是否仍为上一期；
- `freshness_status=current|awaiting_release|stale`；
- 最近获取结果、实际发布事件、关联证据数量和下一检查时间。

计划发布时间、实际发布和系统取得是三个独立事实。无新数据时可以继续读取上一期规范观测，但不得修改其统计期或生成新的观测。

## 9. 阶段历史数据集

历史数据必须保留：

- Stage I–VI 正式阶段区间和生效事件；
- 每日债券、股票、商品稳定状态；
- 非典型组合区间；
- P0 不可用、冲突、陈旧和初始化不足造成的显式空档；
- 候选开始、完成、取消和冲突事件；
- 30 日观察、12M 代理及方向背离；
- 每段/每日对应的数据快照、模型、趋势规则和投影版本。

历史查询只读，不对空档做连续填充，也不按当前修订值静默重写历史结果。

## 10. 报告、运行与检索读模型

### 10.1 报告索引

报告记录至少包含业务日、截止点、报告快照、同日版本、状态、关联投影、AI 适配器或确定性模板、生成耗时、证据包哈希、模型/提示词/schema 版本、正文保留状态和失败摘要。历史报告正文不得在打开时重新生成。

本契约不定义 AI 正文协议；输入、输出、超时、替代、引用和确定性简版由“验证双 AI CLI 的证据报告协议”单独冻结。

### 10.2 运行状态

运行状态至少包含任务/运行身份、类型、幂等键、排队/领取/心跳/完成时间、当前步骤、尝试次数、错误分类、可恢复性、下一重试、目标及产出投影身份。

### 10.3 检索追踪

检索记录至少包含指标或发布事件、优先级、是否预计已发布、检索层级、耗时、结果分类、负缓存、下一重试、预算使用及剩余量、来源认证和对阶段/转折/P2的影响。

## 11. 证据追溯数据集

以 `evidence_observation_id`、`source_claim_id`、`derived_observation_id` 或报告引用为入口，返回：

- 指标定义版本、标量含义、单位、频率和证据角色；
- 观测身份、版本、统计期、维度、值和合法 `value_state`；
- 来源机构、来源声明、制品哈希和已验证 URL；
- `release_at`、`public_available_at`、`fetched_at`、`available_at`；
- 时效、选择、质量和来源认证状态；
- 其他来源声明、容差、冲突和选择原因；
- 修订链、被替代版本和回填状态；
- 派生公式版本、确切输入观测版本和计算截止点。

追溯查询不得返回密钥、认证头、未经脱敏的外部正文或 AI 内部提示词。

## 12. 空值、降级与故障语义

| 情况 | 数据合同结果 |
| --- | --- |
| 核心 P0 缺失、陈旧或冲突 | `current_stage=null`，投影仍可发布为 `stage_unavailable`，保留上一确认阶段作历史上下文 |
| 三核心形成非典型组合 | `current_stage=null`，显式记录非典型组合，不创建新阶段 |
| P1 宏观/库存数据不足 | 正式阶段不变；对应状态为空或数据不足，列出缺口 |
| P2 国际数据失败或未认证 | 正式阶段和国内状态不变；仅记录不可用/未认证 |
| 预计窗口尚未结束 | 沿用上一期，状态 `awaiting_release`，不是获取失败 |
| 来源获取失败 | 不生成空观测；记录 `retrieval_attempt`，上一有效观测按其自身时效读取 |
| 已发布但未披露 | 使用 `not_disclosed`，不得填 0 |
| 制度上不适用 | 使用 `not_applicable`，不得与缺失混淆 |
| 新投影构建部分失败 | 当前指针不切换；继续读取上一完整投影，运行读模型显示失败及恢复动作 |
| 双 AI CLI 失败 | 分析投影不受影响；报告进入失败或确定性简版状态 |

## 13. 刷新命令边界

页面只能提交幂等命令，不直接写分析数据：

- 盘后完整刷新；
- 指定发布事件/指标刷新；
- 用户显式手动深搜；
- 报告生成或重新生成新版本；
- 可恢复失败的重试。

命令至少返回 `job_id`、`run_id`、幂等键、接受时间和目标 `projection_set_id`（如已分配）。任务互斥、重试、恢复和每日自动报告边界由“定义刷新编排、幂等与故障恢复模型”继续冻结。

## 14. 验收条件

1. 任意两个当前分析数据集的 `projection_set_id`、`system_as_of`、数据快照和模型版本一致。
2. 构建中或失败的新投影不会导致当前指针暴露部分结果。
3. 运行/报告状态可以更新，但始终能追溯到目标或产出的分析投影。
4. 正式阶段、资产候选、转折观察和宏观确认具有互不混用的字段与枚举。
5. 三资产使用共同趋势骨架，同时保留资产专属确认数据且不获得额外投票权。
6. 宏观四组状态独立，库存七类特征独立，系统不存在宏观总分或库存总分字段。
7. 阶段历史包含正式区间、每日核心状态和显式空档，不进行历史连续填充。
8. 未认证来源没有数值或自动代理；获取失败不生成空观测。
9. 每个页面引用值都能进入对应证据观测、来源声明、vintage 或派生输入链。
10. 所有契约都不依赖任何具体视觉布局或前端组件。
