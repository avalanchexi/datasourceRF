# 本机无备份与主存储保留策略

> 决策日期：2026-08-24  
> 适用范围：Pring 周期驾驶舱 V1  
> 状态：已确认  
> 核心取舍：系统为个人使用的单节点本机应用，不为运行数据建立第二份副本，主动接受全部本机历史可能丢失。

## 1. 结论

V1 的运行数据采用 `backup_mode=none`：不建立日常备份、Windows侧离线副本、升级前快照、密钥备份或手动完整备份命令。GitHub只管理源码、Markdown规格、指标目录、数据库迁移、依赖锁文件和非敏感配置模板；它不是SQLite、内容寻址证据、报告正文、日志或密钥的备份介质。

本策略不改变运行期间的不可变证据语义。只要本机主存储仍存在，来源声明、vintage、证据观测、分析投影和报告快照仍按既有ADR追加保存、点时查询且不原地覆盖；“无备份”只表示主存储丢失后没有第二份副本可以恢复。

## 2. 明确不备份的内容

以下内容只保存在WSL原生XDG运行目录，不产生恢复副本：

- SQLite数据库、WAL和任务账本；
- 内容寻址证据制品及其数据库引用；
- 分析投影和运行读模型；
- 自然语言报告正文；
- 日志、缓存、临时下载和诊断响应；
- `TUSHARE_TOKEN`、`TAVILY_API_KEY`、`EXA_API_KEY`；
- Codex CLI与Claude Code CLI的登录状态。

普通配置可以提交GitHub，但仓库只保存不含秘密值的配置和模板。三个数据源密钥以明文保存在仓库外本机配置目录的独立`secrets.env`，权限保持`0600`；不加密、不备份，且仍禁止进入GitHub、命令输出、日志、报告、证据包或AI上下文。

## 3. 数据丢失与恢复承诺

V1不提供运行数据恢复服务级目标：

| 项目 | 决策 |
| --- | --- |
| 运行数据RPO | 不保证；允许丢失全部本机运行历史 |
| 运行数据RTO | 不保证；仅best effort重新初始化 |
| 密钥RPO/RTO | 不保证；丢失后由用户重新取得或登录 |
| WSL、磁盘或整机损坏 | 不在V1恢复承诺内 |
| 误删、SQLite损坏或迁移失败 | 可以清空本机状态并重新初始化，不保证找回原历史 |

从GitHub恢复只恢复代码和静态定义。重新采集能够形成新的`system_as_of`历史，但不能重建已经丢失的旧`available_at`、来源vintage、证据制品、运行审计或报告快照，也不得冒充原历史。

## 4. 升级边界

- 不创建升级前SQLite快照或制品清单副本；不提供数据库回滚承诺。
- 升级只允许从干净、已提交并可从GitHub重新取得的代码版本执行。
- 升级前仍执行依赖锁、配置、可用磁盘、Alembic当前版本和目标版本预检，并记录代码、依赖、Schema、模型、趋势和报告版本。
- Alembic使用前向迁移；`downgrade`不承担恢复保证。
- 迁移失败时停止Worker写入并显示`reinitialize_required`。可以修复迁移后继续，也可以删除本机运行状态并从空库初始化；不得暗示Git回退能够恢复数据库。

统一CLI不提供通用`backup`命令。`doctor`、`migrate`和升级流程必须明确显示`backup_mode=none`以及不可恢复后果。

## 5. 主存储保留类别

保留是主存储内部的生命周期，不是备份。

| 类别 | 保留规则 | 到期后保留的结构化信息 |
| --- | --- | --- |
| SQLite中的来源声明、vintage、证据观测、派生结果、阶段、血缘、规则和运行审计 | 长期 | 全部 |
| 被数据库中的正式声明或快照引用的原始页面、响应、下载文件和其他证据制品 | 长期 | 原制品及哈希 |
| 自然语言报告正文 | 30天，不可变 | 确定性事实骨架、证据引用、版本、状态和正文哈希长期 |
| 未验证搜索响应与候选页面 | 7天，且全局最多1GiB | 获取尝试分类、时间、来源、结果状态和安全摘要长期 |
| 轮转日志 | 14天，且全局最多200MiB | 由SQLite承担的业务审计不受影响 |
| 临时文件、部分下载、AI部分输出和失败正文 | 作业结束即清理；异常遗留在下次启动清理 | 稳定失败分类与运行审计长期 |
| 无任何数据库引用的孤立内容制品 | 经过7天宽限期后可清理 | 如存在获取尝试，保留其结构化元数据 |

到期清理不能改变已发布分析投影、正式阶段或结构化报告快照的身份。报告正文到期后页面应明确显示“正文已按保留策略清理”，不能表现为报告从未生成。

## 6. 自动清理顺序

Worker或维护命令只能按以下顺序清理：

1. 已结束作业的临时文件、部分下载和可重建缓存；
2. 超过7天或使该类别超过1GiB的未验证响应，先删最旧；
3. 超过14天或使日志超过200MiB的轮转日志，先删最旧；
4. 超过30天的自然语言报告正文；
5. 无数据库引用且已经过7天宽限期的孤立制品。

SQLite、长期结构化血缘、被引用证据和仍在30天保留期内的报告正文都不能因为磁盘压力被自动删除。清理完成后空间仍不足时，系统必须停止产生新数据，而不是继续删除权威内容。

## 7. 磁盘水位与降级

容量检查同时覆盖：

- WSL中XDG运行目录所在文件系统；
- 承载该WSL虚拟磁盘的Windows卷。

若承载卷不能自动识别，初始化时必须配置并由`doctor`验证；不能只依据WSL虚拟文件系统显示的可用空间。任一相关卷触发门槛即生效：

| 可用空间 | 行为 |
| --- | --- |
| `<20GiB` | 显示容量警告，执行已到期可重建内容清理 |
| `<10GiB` | 在上述行为之外，拒绝手动深搜、报告重生成和P2大制品获取 |
| `<5GiB` | Worker不再接受任何写任务；Web继续只读展示最后完整投影和清理指引 |

当前环境只读盘点显示：WSL根文件系统报告约810GiB可用，但Windows `C:` 仅约17GiB可用且使用率98%，`D:`约62GiB可用且使用率84%。这证明实现不能只看WSL内部的虚拟容量。该盘点是规划时事实，不是永久配置值。

## 8. GitHub边界

GitHub中允许：

- 源码、测试和文档；
- ADR、Wayfinder资产和指标目录；
- Alembic迁移、Schema和契约；
- `pyproject.toml`、`uv.lock`及非敏感配置模板。

GitHub中禁止：

- SQLite、WAL、内容寻址制品和投影；
- 运行日志、真实报告正文和外部响应；
- `.env`、`secrets.env`、API key、token和CLI认证状态。

实施开始前项目必须纳入Git版本控制并配置忽略规则。运行时目录继续位于仓库外的WSL XDG路径，不能因“GitHub管理数据”而移入源码树。

## 9. 验收场景

1. `doctor`明确显示`backup_mode=none`、无RPO/RTO和本机历史可能全部丢失；系统不存在后台或定时备份任务。
2. CLI帮助中没有通用运行数据`backup`命令；升级流程也不创建SQLite或制品副本。
3. 从GitHub检出代码后可以初始化空系统，但不能声称恢复已经丢失的`system_as_of`历史。
4. 仓库扫描拒绝SQLite、WAL、运行制品、日志、真实报告正文、`.env`和`secrets.env`；三个数据源密钥只在仓库外`0600`文件中存在。
5. 31天前的报告正文被清理后，结构化事实骨架、引用、版本、状态和正文哈希仍可查询。
6. 被来源声明或报告快照引用的证据制品不因年龄或容量压力被删除。
7. 未验证响应超过7天或1GiB、日志超过14天或200MiB时，按最旧优先清理；孤立制品必须经过7天宽限期。
8. 任一相关卷低于20/10/5GiB时分别触发警告、非核心大任务限制和全写入停止；Web保留只读能力。
9. 模拟迁移失败后系统进入`reinitialize_required`，不自动执行数据库降级、不声称存在恢复点，并要求用户修复迁移或明确清空重建。
