# Pring 周期驾驶舱 V1 实施与验收计划

> 状态：已确认  
> 用途：Wayfinder 到 `/to-spec` 的权威实施顺序与验收输入  
> 不在本计划中：直接编写生产代码、视觉设计、把旧报告当作正确标签

## 1. 总体交付规则

1. 实施分为七个逐步可运行的里程碑；每个里程碑都必须产生可执行成果，而不是只完成一组内部文件。
2. 每个里程碑提供一个统一验收命令，且退出门全部通过后才允许领取依赖它的下一里程碑。
3. 日常测试不联网、不依赖真实账号或CLI登录；真实来源只通过独立、脱敏、可审计的烟雾测试验收。
4. 旧项目`/mnt/d/cursor/datasource`全程只读，只用于提取脱敏失败形状、接口经验和差异根因；旧报告、旧阶段和旧golden不是真值。
5. 新系统不读取旧系统作为运行时数据源、阶段源或降级源，不做双写择优。
6. 当前`.scratch/pring-cycle-dashboard/spec.md`及其12张实现票早于本地图的大部分最终决策；它们只能作为旧草案输入，必须由`/to-spec`和`/to-tickets`重写后才能实施。

## 2. 依赖顺序

```text
M1 工程与领域骨架
  └─► M2 点时证据与确定性核心
        └─► M3 真实P0与首个候选模型
              └─► M4 完整P1证据层
                    └─► M5 本地产品运行面
                          └─► M6 报告与运维降级
                                └─► M7 最终验证与直接切换
```

不允许在M2退出门通过前接Web或AI，不允许在M4退出门通过前把宏观、库存或检索结果作为完整产品投影发布。

## 3. 所有里程碑共同证据

每个里程碑必须提交或生成：

- 一个无凭据可运行的统一验收命令；
- 单元、属性、表驱动、契约或临时SQLite测试；
- 固定输入的离线端到端fixture；
- 外部适配器的成功、空响应、权限不足、限频、身份不符、日期不符、冲突和解析失败形状；
- 需要真实来源时独立保存的脱敏烟雾结果，只保存身份、字段、时间、数量、哈希和结论，不保存token或未获许可正文；
- 对应`REG-*`、规格条款和ADR的追踪表；
- 至少一个失败或降级验收，不能只证明成功路径；
- 同步更新的开发或运行文档。

## 4. M1：工程与领域骨架

### 可运行成果

- 初始化Git源码仓库与GitHub可管理的静态项目边界；运行状态、密钥、SQLite、WAL、制品和日志全部排除在仓库外。
- Python 3.12、`uv`、`pyproject.toml`、`uv.lock`、格式化、类型检查和pytest基线。
- 统一`pring-cycle` CLI，至少提供`doctor`、初始化、Web启动、Worker启动和测试入口。
- WSL原生XDG目录、仓库外`0600`密钥文件、SQLite WAL、Alembic和内容寻址制品骨架。
- FastAPI + Dash单Web进程与独立单Worker可以在断网、无项目凭据、无CLI登录时启动。
- 把`CONTEXT.md`中的领域状态、证据身份、模型版本、投影身份、运行身份和报告身份实现为明确边界类型。

### 退出门

- `doctor`明确显示Python、依赖锁、XDG目录、SQLite/Alembic、凭据启用状态、`backup_mode=none`和RPO/RTO不保证。
- Web只绑定`127.0.0.1`；不受信Origin不能追加命令。
- 仓库和`/mnt/d`无运行时写入，日志与错误中无密钥、认证头、完整外部响应或AI提示上下文。
- 核心领域包可以在不启动Web、SQLite或网络的情况下导入和测试。
- 架构验收覆盖离线启动、原子制品登记、XDG位置、Markdown安全和升级失败进入`reinitialize_required`。

### 文档

- 开发环境、目录边界、无凭据启动、`doctor`、密钥边界、无备份风险。

## 6. M3：真实P0与首个候选模型

### 可运行成果

- 中国交易日历以及`000985.CSI`、`000012.SH`、`NHII.NH`真实适配器与认证状态。
- 官方涨跌幅/前收构造的连续收益链，原始点位、调整标记和质量结果并列保存。
- 最近120个中国交易日的P0完整性检查；模型所需窗口前预热另行存在并通过同等身份、单位、交易日和连续性校验，但不扩大页面120日证据窗口。
- 暂定`1.5×σ20`噪声带、8日持续、MA120的20日斜率和冲突保持规则进入`model-v0001`候选。
- 同步CLI可以针对最新完整目标交易日刷新P0并生成确定性投影；P0失败时安全返回`action_required/current_stage=null`。

### 退出门

- 最近120个中国交易日三核心不存在未解释的身份、单位、日期、重复、缺口或来源冲突；必要预热足以计算目标日状态。
- 当前阶段为空只能来自可解释的领域状态，不能由未分类错误或总体完整率掩盖P0缺口。
- 2018-06-01至2026-08-19冻结夹具复现21次资产方向转换、11次正式阶段变化、20个交易日内快速资产/阶段反转均为0和23个交易日中位确认延迟。
- 历史校准只使用`public_as_of`证据；后来认证的更早数据只可作校准/预热，不生成认证前正式版本回放。
- 参数变化只能形成新的候选模型；`model-v0001`此时仍不得自动生效。

## 7. M4：完整P1证据层

### 可运行成果

- 冻结61组指标定义全部进入版本化目录；全部P1具有可运行适配器或派生公式及离线契约测试。
- TuShare、PBOC、NBS、EIA等官方适配器，以及本地、TuShare、认证官方直连、Tavily、Exa、受限AI WebSearch的固定检索降级链。
- 冻结单事件`1/1/1`、单运行`8/4/1`、每日`16/8/2`预算，P2禁用AI，负缓存和联合发布合并生效。
- 政策行动、市场传导、信用响应、政策方向、过热程度、物价压力、四象限库存和七类阶段特征卡。
- 七袖套去生猪篮子作为条件后备或不投票确认数据实现；不在运行时与NHII逐日切换。
- 完整结构化分析投影可以从CLI生成；P1失败只使对应解释降级，P2未认证项显式为空。

### P1真实源抽样门

- 所有P1先通过离线契约测试。
- 真实烟雾按独立适配器、端点或解析Schema族抽样；共享响应结构的多个指标可以共用证据。
- 具有独特指标身份、单位、时点或解析逻辑的P1必须单独抽样。
- 本地派生不访问真实源，以固定输入验证公式、版本和确切输入血缘。
- 抽样失败会阻塞整个对应适配器/Schema族，不得仅把失败指标标成P2绕过。

### 退出门

- 所有P1都能明确输出有效观测、`awaiting_release`、`stale`、来源失败、冲突、`not_applicable`或`not_disclosed`，不存在未知空值。
- P0/P1不存在未知来源、身份错配、静默代理或未分类错误。
- P2可以保持`awaiting_source_certification`，但页面/报告合同必须披露，且不得改变正式阶段或进入AI WebSearch。
- 报告模块尚未接入时，证据获取也必须独立遵守预算；页面和未来报告不得绕过它自由搜索。

## 8. M5：本地产品运行面

### 可运行成果

- SQLite持久父运行、任务账本、全局单Worker租约、30秒心跳、120秒失效、幂等命令、检查点、取消和显式恢复。
- 手动完整运行优先；自动盘后配置存在但默认关闭，启动不补跑、不检索、不调用AI。
- Worker按统一截止点刷新证据、构建并原子发布完整分析投影；Web只读投影或追加短命令。
- FastAPI + Dash同一localhost进程，提供周期、核心资产、宏观、库存、发布日历、阶段历史、证据追溯、运行和检索状态。
- 活动任务30秒、空闲5分钟的自适应轮询；不引入Redis、Celery、WebSocket、Node或第二Web服务。
- 手动完整运行、定向刷新、手动深搜、取消和恢复均可从CLI与页面发起，并使用冻结幂等身份。

### 退出门

- 重复提交只形成一个权威运行；关闭浏览器不停止Worker；重启后不自动恢复外部调用。
- P0失败进入`action_required`且不生成新阶段或自动长报告；P1/P2失败允许投影`degraded`完成。
- 新投影失败时继续读取上一套完整投影，页面不混用不同`projection_set_id`或截止点。
- 页面读取不触发外部调用、不重新计算趋势/阶段、不显示宏观总分或库存总分。
- 页面始终显示当前合法操作、稳定错误分类、P0/P1/P2影响和版本身份。

## 9. M6：报告与运维降级

### 可运行成果

- 确定性事实骨架、冻结证据包、共同报告Schema和后置语义/引用校验。
- 本机Codex CLI与Claude Code CLI独立子进程适配器；默认Codex、Claude替代，每个适配器每次最多一次。
- 单适配器300秒硬超时、5秒终止宽限、双适配器约610秒总预算；部分输出、工具事件、取消和校验失败不形成报告快照。
- 双CLI失败时形成`completed_degraded`确定性报告；报告失败不回滚分析投影。
- 报告正文30天、未验证响应7天/1GiB、日志14天/200MiB、孤立制品7天；被引用证据和结构化血缘长期保存。
- WSL/Windows承载卷20/10/5GiB警告、限制非核心大任务、停止Worker写入；不得自动删除权威状态。
- 可选自动盘后默认关闭，启动不追赶；统一CLI完成脱敏白名单密钥迁移、维护和重新初始化。

### 退出门

- 两个适配器各自通过共同fixture的正式实现烟雾；切换当天登录/额度不可用不阻塞，只要确定性降级完整。
- AI无法改写正式阶段、发起自由搜索、读取API key或绕过证据引用。
- 安全Markdown、进程组超时、替代、取消、双失败、报告落后于新投影和30天清理语义通过。
- `doctor`和文档明确无运行数据备份、RPO/RTO不保证及`reinitialize_required`含义。

2. 固定证据、日历、模型和截止点的离线重放产生规范化后完全一致结果。
3. M3冻结夹具统计完全复现，且任何调参都已经形成新候选并重新通过全部门。
4. P0最近120个交易日、必要预热和P1抽样门通过；所有已知P2未认证项列入清单。
5. 故障注入证明事务中断、重复命令、陈旧租约、P0失败、双CLI失败、磁盘降级和升级失败遵循冻结语义。
6. 所有文档命令在干净WSL环境实际演练。
7. 性能与资源预算全部通过。

### 切换前演练

- 不运行多日生产影子。
- 使用最新完整目标交易日完成一次真实端到端演练：手动运行、P0、按Schema族抽样的P1、原子投影、Dashboard以及AI成功或`completed_degraded`全部走通。
- 演练结果明确标记为验收产物，不进入正式发布历史。
- 另以fixture完成一次Worker中断与用户显式恢复演练。

### 不可变切换清单

最终切换清单至少固定：

- Git提交和工作树清洁状态；
- Python与`uv.lock`；
- Alembic head、配置Schema和运行目录策略；
- 指标目录、来源认证、模型、趋势、投影合同、报告Schema和提示版本；
- 自动化测试结果及哈希、35项回归矩阵；
- P0质量、P1烟雾和已知P2缺口；
- 离线回放与冻结统计；
- 性能/RSS结果；
- 文档干净环境演练结果；
- 真实端到端演练和中断恢复结果；
- `backup_mode=none`、RPO/RTO不保证及重新初始化风险确认。

统一CLI机器校验切换清单，不提供`--force`或等价绕过。只有全部硬门通过且用户显式确认后，才执行系统切换并记录切换时间、目标交易日、模型版本和清单哈希。

### 单向切换语义

- 不设置生产影子期或双写期。
- 切换后新系统立即成为唯一受支持结果生成路径；旧项目只读保留作故障证据，不再运行或提供降级。
- 首次系统切换失败时只在新系统内修复、显式恢复或按无备份决策重新初始化，不重新启用旧系统。
- 30个中国交易日的模型回退只适用于新系统内部后续模型版本升级，不适用于退回旧系统。
