# 刷新编排、幂等与故障恢复模型

> 决策日期：2026-08-24  
> 适用范围：Pring 周期驾驶舱 V1  
> 状态：已冻结的实施与验收边界  
> 前置约束：SQLite 单 Worker、原子分析投影集、point-in-time 证据、成本受控检索链和 CLI-only 报告协议

## 1. 结论

V1 采用**手动完整运行优先**的持久编排模型。用户通常先启动本地项目，再针对一个中国目标交易日显式执行“生成当日结果”；自动盘后运行是默认关闭的可选能力，不能假设 Web、Worker、WSL2 或计算机全天在线。

一次完整运行由 SQLite 任务账本中的父运行承载，顺序执行预检、证据刷新、校验、投影构建、原子发布和报告生成。单 Worker 使用持久全局租约串行执行；进程或计算机中断后保留已验证检查点，但恢复任何外部调用必须由用户确认。项目启动本身不得自动补跑、检索或调用 AI CLI。

## 2. 不变量

1. **目标交易日不等于执行日期。** 每次完整运行必须显式携带 `target_business_date`；运行时间、`system_as_of` 和 `report_cutoff` 分别保存。
2. **手动操作是主路径。** 启动 Web/Worker、打开浏览器或重启 WSL 不隐含刷新、补跑或报告生成。
3. **同一时间只有一个父运行执行。** 活动运行的阶段不被其他运行插入；取消只能由用户显式发起。
4. **投影先于报告。** 新分析投影通过校验后原子发布，报告随后针对该不可变投影生成；报告失败不得回滚投影。
5. **核心门槛不可降级替代。** 三条核心价格缺失、陈旧或冲突时，不得用确认指标、宏观证据或上一交易日价格生成目标日正式阶段。
6. **恢复只复用已验证提交。** 部分下载、未验证解析、未发布投影和 AI 部分输出都不是检查点。
7. **运行、投影和报告状态相互独立。** AI 的 `completed_degraded` 不得表达 P0 数据缺失；投影的 `degraded` 不得冒充运行失败。
8. **浏览器不是任务宿主。** 关闭浏览器不取消 Worker；页面轮询失败也不改变账本状态。

## 3. 运行与命令类型

| 类型 | 发起方式 | 目标 | 是否生成报告 |
| --- | --- | --- | --- |
| `manual_full` | 用户“生成当日结果” | 一个目标交易日的完整刷新、投影和报告 | 是，P0就绪后 |
| `scheduled_full` | 用户显式启用的可选盘后策略 | 一个目标交易日的完整刷新、投影和报告 | 是，每日最多一个自动运行 |
| `release_refresh` | 用户或已启用的发布检查 | 一个真实发布事件 | 否 |
| `metric_refresh` | 用户高级操作 | 一个指标或发布族 | 否 |
| `manual_deep_search` | 用户显式确认预算后发起 | 一个指标或真实发布事件 | 否 |
| `report_generate` | 用户针对现有投影发起 | 一个 `projection_set_id` | 是 |
| `report_regenerate` | 用户显式重跑 | 一个现有报告对应的投影或更新投影 | 是，新建不可变版本 |
| `data_gap_notice` | P0待处理时由用户显式发起 | 一次失败的核心就绪评估 | 否；只生成确定性缺口说明 |

“继续”不是新的父运行类型。它在原 `run_id` 下创建新的 `attempt_id`，并从安全检查点恢复。已经存在正式报告后再次生成必须创建新的父运行或报告重跑运行，并记录被替代关系。

## 4. 完整运行阶段与完成条件

### 4.1 阶段

```text
queued
  → preflight
  → refreshing_evidence
  → validating_evidence
  → evaluating_core_readiness
  → deriving_states
  → building_projection
  → publishing_projection
  → generating_report
  → completed
```

父运行的终态为：

- `completed`：该运行类型的完成条件已经满足；
- `action_required`：P0核心证据缺失、陈旧或冲突，允许人工继续；
- `interrupted`：租约失效或进程终止，允许人工继续；
- `failed`：不可恢复的本地校验、持久化或编排错误；
- `cancelled`：用户显式取消，可能已经发布投影，但没有假装完成余下阶段。

完成结果另存 `outcome`，至少区分 `changed`、`no_change`、`unresolved` 和 `completed_with_data_gaps`，不扩张父运行终态枚举。

### 4.2 各类型完成条件

- `manual_full` / `scheduled_full`：已经原子发布目标交易日投影，并生成不可变报告快照。报告可以是合格 AI 报告，也可以是双 CLI 均失败后的确定性 `completed_degraded` 报告。
- `release_refresh` / `metric_refresh`：检索和校验尝试已经审计；若证据选择、时效、冲突或派生状态变化，则新投影已经原子发布，否则以 `completed + outcome=no_change` 结束。
- `manual_deep_search`：预算使用、候选、校验和结果已审计；未找到合格证据以 `completed + outcome=unresolved` 结束，不制造空观测。
- `report_generate` / `report_regenerate`：已经写入一个合格或确定性降级的不可变报告快照。
- `data_gap_notice`：已经生成并保存确定性缺口说明；它不是正式长报告，也不占自动报告名额。

## 5. P0就绪、T+1与部分来源失败

### 5.1 核心数据就绪门

目标交易日只有同时满足以下条件才可生成新的 `current_stage`：

1. 中国交易日历定义有效；
2. 中证全指、上证国债指数和南华工业品指数均有目标交易日合格收盘值；
3. 三条核心序列没有阻塞性缺口、陈旧或来源冲突；
4. 趋势规则所需120日证据窗口和预热输入完整且已验证；
5. 指标目录、模型和趋势规则版本均已冻结并可记录。

门槛不满足时，完整运行进入 `action_required`，不发布该目标交易日的新正式投影，也不自动生成长报告。页面继续读取上一套完整投影，并通过运行读模型显示缺失P0、最近有效日期、获取错误和最早可重试时间。用户可以继续运行，或显式生成 `data_gap_notice`。

若定向刷新发现**当前已发布投影**所依赖的P0后来发生有效冲突、撤回或时效失效，则必须发布新的 `stage_unavailable` 投影，不能继续把已知无效阶段显示为当前阶段。

### 5.2 T+1数据

融资等 T+1 的 P1 数据不阻塞目标交易日投影或报告。完整运行只使用 `report_cutoff` 前已经发布并验证的最近一期，保留真实统计期和时效。次日到达后可以通过定向刷新进入新投影，但不修改旧报告，也不自动重新生成报告。

### 5.3 P1/P2失败

P1/P2缺失、陈旧、冲突或未认证不阻塞P0有效时的完整运行。投影以 `degraded` 发布，报告确定性事实骨架必须列出缺口；P1不得形成当前转折或宏观确认，P2只作带警告背景。

## 6. 幂等、互斥与排队

### 6.1 命令幂等

| 命令 | 幂等身份 |
| --- | --- |
| 手动命令 | `command_type + client_request_id` |
| 自动完整运行 | `scheduled_full:<target_business_date>:<report_policy_version>` |
| 实际发布事件刷新 | `release_event_id + source_artifact_content_hash` |
| 报告生成 | `projection_set_id + report_policy_version + client_request_id` |
| 恢复命令 | `run_id + client_request_id`；成功接受后创建新 `attempt_id` |

同一客户端请求ID的重复HTTP提交返回原命令和原运行。显式“重新生成”必须创建新请求ID，并记录 `supersedes_run_id` 或 `supersedes_report_snapshot_id`。同一目标已有活动完整运行时，普通重复操作返回该活动运行；只有其完成、取消或失败后才能显式重跑。

### 6.2 互斥租约

SQLite保存一个 `worker:global-execution` 租约。Worker以短事务原子领取：

- 初始心跳间隔30秒；
- 初始租约失效时间120秒；
- 参数进入运行配置版本，实测调整必须留变更记录；
- 租约失效后，新Worker只把原运行标记为 `interrupted`，不得自动恢复外部调用。

幂等键解决重复命令，租约解决同时执行；两者不得合并为一个含糊的“任务锁”。

### 6.3 排队

活动父运行不被抢占。队列优先级依次为：

1. 人工恢复和当日手动完整运行；
2. 人工定向刷新和手动深搜；
3. 人工历史补跑；
4. 可选自动盘后运行。

同级按接受时间排序。一个完整运行进入报告阶段后仍保持父运行连续性，不允许其他刷新插入到投影发布与该报告之间。

## 7. 重试、缓存与恢复

### 7.1 请求级重试

- TuShare和认证官方源的幂等请求，在初始请求之外最多执行两次短传输重试；只处理连接中断、超时和明确可重试的5xx。
- 认证失败、权限不足、配额、限频、尚未发布、语义/单位/统计期错误和校验失败不做短重试。
- Tavily、Exa和AI WebSearch不突破已冻结的单事件、单运行和每日预算，也不以“重试”为名重复同渠道请求。
- 手动运行结束后不创建隐藏后台重试；运行读模型显示 `next_retry_at`，用户达到时点后决定是否继续。
- 可选自动模式中，只有P0可以在21:00截止前再执行一次工作流补试；P1/P2不触发完整运行补试。

负缓存与 `Retry-After` 继续采用已冻结的检索契约；恢复运行不得绕过负缓存或每日预算。

### 7.2 手动深搜

一次深搜只针对一个指标或一个真实发布事件。用户确认后，单事件搜索上限提高为：

- Tavily：2次；
- Exa：2次；
- 受限AI WebSearch：P0/P1最多1次，P2为0次。

深搜仍受每日Tavily 16、Exa 8、AI WebSearch 2次硬上限约束。搜索结果只是候选；只有通过认证官方来源、字段、统计期、单位、发布时间和point-in-time校验后才能形成证据并触发投影重建。

### 7.3 检查点与恢复

可以复用：

- 已经原子登记、哈希匹配的来源制品；
- 已验证来源声明和规范证据观测；
- 已提交的派生结果及其确切输入血缘；
- 已发布分析投影和不可变报告快照。

必须重做：

- 临时或部分下载文件；
- 未通过验证的解析候选；
- 未完成或未原子发布的投影目录；
- AI stdout、部分JSON、超时输出和校验拒收输出。

用户点击“继续”后在原 `run_id` 下创建新 `attempt_id`，重新冻结新的 `system_as_of`，并从最近安全检查点推进。已经生成正式报告后再运行必须创建新版本，不能在原报告快照中继续。

## 8. 取消与进程停止

- 页面取消请求持久化到任务账本；Worker在下一安全点停止。
- 正在运行的AI CLI按300秒超时协议的同一进程组终止规则处理；部分正文不写快照。
- 已验证证据继续保留；未发布投影不切换当前指针。
- 投影已发布而报告被取消时，投影继续有效，父运行终态为 `cancelled` 并关联已发布投影。
- 关闭浏览器不影响Worker。显式停止Worker、关闭WSL或重启计算机导致心跳停止，租约过期后成为 `interrupted`。

## 9. 投影与报告编排

1. Worker冻结证据和规则截止点；
2. 构建全部必需分析数据集；
3. 校验共同 `projection_set_id`、`system_as_of`、数据快照及模型版本；
4. 原子切换当前投影指针；
5. 运行读模型立即显示投影已发布、报告待生成；
6. 从该 `projection_set_id` 构造确定性事实骨架和证据包；
7. 默认Codex、替代Claude，每个适配器最多一次，单适配器300秒、终止宽限5秒、总预算约610秒；
8. 合格输出或确定性降级写入不可变报告快照。

报告失败、超时或取消不回滚投影。报告生成后发生宏观、T+1或其他定向更新时，旧报告保持绑定原投影；页面标记“报告早于当前投影”并显示差异来源，只有用户显式操作才能生成同日新版本。

CLI运行期间页面只显示当前适配器、首选/替代序号、已运行时间、300秒上限、最后心跳、切换状态和取消入口；不得把流式stdout或半成品正文暴露为报告。

## 10. 可选自动盘后运行

- 默认关闭；由用户显式启用。
- 初始启动时间为北京时间18:30，P0等待截止为21:00；两者配置版本化。
- 只有中国交易日产生计划身份。
- 自动幂等身份为 `scheduled_full:<target_business_date>:<report_policy_version>`，同一身份最多接受一个父运行。
- 正常AI报告与确定性 `completed_degraded` 报告都满足当天自动报告；取消、终止或失败后不得自动创建第二个运行，用户可以人工继续或重跑。
- 如果计划触发时已有报告绑定当前完整投影，且目标交易日、指标目录、模型和报告策略版本一致，则计划记录 `satisfied_by_report_snapshot_id` 并跳过。若之后已经发布新投影，则仍可使用当天唯一一次自动运行。
- 服务未成功启动或计算机离线时，不在下次启动自动补跑。页面列出遗漏交易日并推荐生成最新交易日；历史日期由用户选择。

“每天最多一份自动长报告”因此表示：每个中国目标交易日和报告策略版本最多接受一个自动父运行，而不是按自然日、进程启动次数或午夜边界计算。手动报告不占自动名额，但可以在内容与版本完全匹配时满足该计划。

## 11. 页面可见状态

运行期间和故障后，页面始终保留上一套已发布的完整投影，并通过独立运行读模型显示：

- 运行和任务身份、类型、目标交易日及目标投影；
- 排队位置、当前阶段、开始时间、最后心跳和已运行时间；
- P0缺失/陈旧/冲突，P1/P2缺口及对正式阶段的影响；
- 稳定错误分类、是否可恢复、负缓存和最早重试时间；
- 当前合法操作：继续、取消、重新生成、定向刷新、手动深搜或生成缺口说明；
- 新投影是否已发布、报告是否生成中，以及报告是否早于当前投影；
- CLI适配器、尝试序号、超时上限和替代状态，但不显示半成品正文。

轮询失败只显示连接异常，不清空投影或将运行改为失败。

## 12. 验收场景

1. 用户双击“生成当日结果”，服务端只形成一个父运行，并向两个请求返回同一身份。
2. 用户关闭浏览器后Worker继续；重新打开页面能看到相同运行和最新心跳。
3. 证据获取阶段关闭WSL，重启后运行变为 `interrupted`，且在用户点击继续前没有任何外部调用。
4. 恢复运行复用已验证制品，但拒绝部分下载和AI部分输出。
5. 三核心任一缺失、陈旧或冲突时进入 `action_required`，不生成新阶段或自动长报告；确定性缺口说明可由用户单独生成。
6. P1失败时投影和报告仍完成，投影为 `degraded`且报告列出缺口。
7. 宏观定向刷新没有新证据或状态变化时只记录 `outcome=no_change`；有变化时原子发布整套新投影，不自动生成报告。
8. 报告运行时页面已经可读新投影；取消报告不会回滚投影，部分正文不会形成快照。
9. 双AI失败后确定性报告形成 `completed_degraded`，父完整运行仍可 `completed`。
10. 自动模式默认关闭；服务离线错过三天后再次启动只显示遗漏，不自动补跑或调用AI。
11. 相同自动身份重复唤醒只接受一个运行；匹配当前投影的手动报告可以将自动计划标记为已满足。
12. 报告完成后发布新投影，旧报告保持不可变并显示版本落后，只有手动重跑才形成同日新版本。

## 13. 不在本决策中

- 本地备份、RPO/RTO、容量水位和制品清理由后续[《本机无备份与主存储保留策略》](local-no-backup-and-retention-policy.md)冻结为无备份、无恢复保证及分级清理降级；
- CLI版本升级后的认证、历史重算和跨模型可比性；
- Dash视觉布局、图表和交互设计；
- 多Worker、多机、Redis、WebSocket或公网运行。
