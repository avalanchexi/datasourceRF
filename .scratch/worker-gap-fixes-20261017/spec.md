# 规格：⑦ 暴露的 Worker 缺陷修复（2026-10-17）

**Status:** ready-for-agent

决定见 [decisions.md](decisions.md)；根因调查（Codex，含 file:line 与数据主键）复制在 [investigation.md](investigation.md)。

## Problem Statement

用户验收首页 ⑦"数据说明与解读"时发现：10-15 的人民币中间价已发布却没取到、只能沿用 10-14；社融 9 月数据 10-14 已发布，页面却写"未请求 2026-09（等待发布）"；EIA 布伦特、WTI 正常的分批发布滞后被列为"缺失"；仓单 07-21、09-09 的历史缺期在缺口列表里找不到；AI 解读正文出现 `tushare:index_daily`、`stage_iii` 这类代号。另有一个潜在缺陷：价格阶段为第二阶段且贷款动量未知时，确认度计算抛 `AttributeError`。

## Solution

用户看到的 ⑦ 如实区分"真正缺失"与"等待发布"；已发布的社融、中间价能被取到；缺口列表与完整度对得上；AI 报告正文用中文名；确认度在任何阶段都不因缺读法而报错。

## User Stories

1. 作为驾驶舱用户，我希望 10-15 这类"媒体写'人民币兑美元中间价报 6.7253'"的新闻能被解析为当天中间价，以便中间价不因句式不同而落后一期。
2. 作为驾驶舱用户，我希望央行中间价栏目列表页被识别，系统按目标日点进当天公告取值，以便官方直连能补上中间价。
3. 作为排障者，我希望检索失败原因区分"首次失败原因"和"被负缓存拦下"，以便判断该修规则还是等缓存过期。
4. 作为驾驶舱用户，我希望同一次发布已取得总量时，社融其他成员不再被估算门禁拦下，以便已发布的数据当次就取。
5. 作为驾驶舱用户，我希望社融各成员逐一判定是否等待发布，而不是一个成员等待、全组不请求。
6. 作为驾驶舱用户，我希望估算门禁未到期时，每次运行仍查一次官方目录，以便提前发布能被发现。
7. 作为驾驶舱用户，我希望 ⑦ 写清社融已取得哪些成员、还缺哪些成员，而不是"整期未请求"。
8. 作为驾驶舱用户，我希望 EIA 这类分批发布的指标在下次发布日前列在"等待发布"组，不算缺失。
9. 作为驾驶舱用户，我希望"等待发布"按来源原件写明的下次发布日判断，原件没写时按登记的发布滞后判断。
10. 作为驾驶舱用户，我希望完整度的缺口数不含"等待发布"，以便完整度反映真正缺的东西。
11. 作为驾驶舱用户，我希望证据时效仍只有 current/stale，"等待发布"只是缺口清单的分组（2026-10-13 决定不变）。
12. 作为驾驶舱用户，我希望仓单 07-21 五个品种、09-09 聚丙烯这类历史缺期出现在 ⑦ 缺口列表，按指标归组，明细进抽屉。
13. 作为驾驶舱用户，我希望完整度表的"其他缺失 N"能在缺口列表里找到对应条目。
14. 作为报告读者，我希望 AI 报告正文用中文指标名和"第三阶段"这类中文阶段名。
15. 作为报告读者，我希望正文仍出现原始代号时，报告照常保存，报告详情标注"含未翻译代号"。
16. 作为维护者，我希望报告输入保留机器字段用于校验，另附中文展示名。
17. 作为维护者，我希望确认度对任意阶段求关系时，成员读法缺动作不再抛 `AttributeError`，而按规则记"未确认"。
18. 作为维护者，我希望以上每个缺陷都有能先红后绿的回归测试。

## Implementation Decisions

- 解析规则：媒体中间价句式扩展在新闻规则家族内完成，保留统计期、币种（USD/CNY）、报价方向（CNY per USD）校验。
- 官方直连：登记央行中间价栏目为可解析列表，列表页按目标日找公告链接再取正文；不改检索降级链顺序。
- 失败原因：获取尝试记录首因；负缓存拦截单列原因，⑦ 与链路页都可读。
- 发布门禁：已取得的同一发布事件证据优先于估算门禁；门禁按成员评估；`awaiting_release` 仍只用于发布判定，不进证据时效。
- 缺口清单：新增"等待发布"分组（投影字段携带下次发布日或推算依据），不计入缺失与完整度缺口；前端 ⑦ 单列显示（原因中文用票 13 的对照表扩展）。
- 仓单：最终补缺计划里的历史缺期并入缺口清单，按指标归组、带期与成员明细。
- 报告：报告输入加中文展示名（指标、来源、阶段）；提示词要求正文用中文名；报告解释校验发现原始代号时加标注，不判失败；AI 不改阶段（ADR-0003）。
- 确认度：修复缺动作成员在缺失诊断路径上的属性访问；不改预期表与模型版本。
- 不需要新模型版本：取数规则、发布门禁、缺口分组、报告提示都不在模型清单内（决定 3 已核）。

## Testing Decisions

- 好测试只断言外部行为：给定已存原件或构造的发布事件与证据，断言解析出的值、门禁是否放行、缺口清单分组与成员明细、报告标注、确认关系、首页可见文本；不断言内部函数调用。
- 测试缝四个，均为现有入口（2026-10-17 用户确认）：
  1. **完整运行**（Worker 执行集成测试）：社融发布门禁、"等待发布"分组、仓单历史缺期进缺口清单、中间价经检索降级链取到值。属运行级材料，按 ADR-0034 走完整运行。外部页面用 10-15 隔离副本存下的原件（财联社 10-15 页面、央行中间价栏目列表页与公告、EIA 原件）复制成测试夹具，不访问外网、不读隔离副本路径。
  2. **单日汇总**：第二阶段、贷款动量未知时确认度报错的回归测试（确认度在单日汇总中计算，ADR-0034）。
  3. **报告入口**（报告输入与报告解释校验的现有测试）：中文展示名、"含未翻译代号"标注。
  4. **首页渲染 `dashboard_page`**：⑦ 的"等待发布"组、社融已取得与仍缺成员。
- 先例：`tests/integration` 下 Worker 执行与检索补缺用例、`tests/retrieval` 已存原件解析用例、`tests/reports` 报告输入与校验用例、`tests/web/test_reading_section.py`。
- 两项必跑冒烟按 `docs/agents/testing.md`；终点前跑一次全套。
