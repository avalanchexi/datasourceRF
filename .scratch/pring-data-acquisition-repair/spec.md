# 数据获取可信性、检索补缺与 Pring 输出修复

## Problem Statement

用户无法从“已有数据”“validated 标签”“历史回放通过”判断当前数据是否真的正确、可用，尤其无法判断 Tavily／Exa 是否补齐了模型需要的证据。页面保留旧目标日结果，不能证明最新数据已经进入模型；阶段计算自洽也不能保证候选持续天数和报告解释正确。

2026-09-06 事实审查覆盖全部 61 项目录指标：P0 6、P1 42、P2 13。272,949 条来源声明通过所执行的结构检查，691 个登记制品哈希与长度匹配，但固定公开时间、请求前系统可用时间、逐请求原件缺失、五个市场家族认证缺口仍存在。当前生效模型绑定被冻结隔离的 v3 目录，最新真实运行被来源契约门禁阻断，可读投影目标日仍为 2026-08-03。

正式 Tavily／Exa 请求账本无样本，命中率为 N/A；候选网址没有连接到完整验证及模型使用。三核心的旧 Stage III 可重现，但股票候选实际连续 7 日被显示为 8 日。8 份历史报告全部是确定性降级结果，不能证明 AI 解释成功。

上述数字是审查时快照，不是执行本规格时应保持的数据库目标值。修复不能通过覆盖旧声明、删除否定性审查、绕过认证或把可选背景指标全部设为必需来完成。

## Solution

建立一条用户能核验的完整路径：明确本次需要什么证据，取得并保留原件，验证身份、字段、单位、期次和真实时间，保存不可变来源声明，按指定点时及模型选值，形成原子分析投影，再输出保持事实骨架不变的报告。

工作分为三条可独立推进的路径：确定性缺陷修复、来源及规则补齐、搜索与报告运行修复。它们在新目录及候选模型认证、120 个中国交易日公开点时重放、当前目标日真实运行和系统切换处汇合。外部证据缺失只阻塞其依赖分支，未解决问题持续显式呈现。

验收分别记录：
- 数据取得和结构校验结果。
- 来源语义、时间、维度完整性与模型输入可用性。
- 检索效果及实际模型采纳。
- 正式阶段、候选持续天数、派生指标等确定性输出。
- 报告解释的证据支持程度及 AI 实际运行结果。
- 真实运行、模型生效、系统切换及历史不变性。

用户指示“下一步”后，确认确定性输出和解释质量分别验收。它不改变允许 completed_degraded 的运行规则，降级不能被计为 AI 解释验收成功。

## User Stories

1. As a 数据使用者, I want 看到全部 61 项指标的应有期次与维度, so that 我能知道实际缺口而不是只看到记录总数。
2. As a 数据使用者, I want 区分 P0、P1 和 P2 的作用与门禁, so that 可选背景缺失不会被误当成正式阶段失败。
3. As a 数据使用者, I want 区分系统运维证据与标量观测, so that 没有来源声明行不会被误报为下载失败。
4. As a 数据审查者, I want 从采用值找到原始响应及内容指纹, so that 我能复查解析依据。
5. As a 数据审查者, I want 区分原始响应与标准化制品, so that 内容哈希不会冒充未保存的原件。
6. As a 数据审查者, I want 看到实际发布时间的依据及可靠程度, so that 固定钟点或抓取时间不会被当作官方发布时间。
7. As a 研究者, I want 仅有可靠发布日期的证据从下一本地日进入公开点时, so that 日内可得性不会被高估。
8. As a 研究者, I want 无可靠公开日期的证据保持未知, so that 当前抓取不会制造历史先知。
9. As a 运行维护者, I want 系统可用时间在取得并通过校验后记录, so that 请求期间的查询不会提前看到结果。
10. As a 研究者, I want 明确选择公开点时或系统点时, so that 回放市场可知事实与重现本机历史不会混淆。
11. As a 数据审查者, I want 修订追加为新 vintage 并保留旧版本, so that 旧报告仍可重现。
12. As a 数据使用者, I want 获取失败留下分类记录但不产生空观测, so that 失败不会被当成零值。
13. As a 数据使用者, I want 认证来源冲突保持冲突, so that 平均值或静默替换不会掩盖不一致。
14. As a 数据使用者, I want 看见真实的候选持续天数, so that 7 日候选不会显示成 8 日确认门槛。
15. As a 数据使用者, I want 无候选、候选中断和确认切换分别正确显示, so that 我能理解趋势为什么保持或改变。
16. As a 数据审查者, I want 三核心有独立官方身份、时间和历史方法证据, so that 正式阶段的输入值得采信。
17. As a 数据审查者, I want 融资数据覆盖沪深北且能按单位与官方样本对账, so that 全市场总量不会缺所或重复累计。
18. As a 数据审查者, I want CNY030 的官方身份和真实点位可复核, so that 相似名称或代理值不会替代目标指数。
19. As a 数据使用者, I want 三指数估值明确 PE、PB 和换手率定义, so that 滚动 PE 与静态 PE 不会混用。
20. As a 数据使用者, I want CSI1000 的应有估值成员被完整检查, so that 两指数有值不会被称为三指数齐全。
21. As a 研究者, I want 广度股票池按历史事件和公开时间重建, so that 当前上市区间不会造成存续偏差。
22. As a 研究者, I want 换码保持主体连续并正确处理上市摘牌边界, so that 老股票不会被当作新股。
23. As a 数据使用者, I want 全日停牌、临时停牌、复牌和未知状态分开处理, so that 涨跌统计不会凭空补行。
24. As a 数据使用者, I want 涨跌家数、平盘及零分母都有冻结规则, so that 页面与派生值保持一致。
25. As a 研究者, I want MA120 和新高新低有足够预热及新股规则, so that 120 日输入覆盖不会被误当成有效指标输出。
26. As a 数据使用者, I want 成交金额范围包含明确交易方式并保留未知盘后金额, so that 金额占比不会通过缺值填零产生。
27. As a 研究者, I want 商品输入绑定真实月份合约、结算价格和到期规则, so that 连续合约标识不会替代历史映射依据。
28. As a 研究者, I want 换月只使用当时可知的信息且不跨合约相除, so that 合约切换不会制造虚假收益。
29. As a 数据使用者, I want 去生猪篮子的基点、袖套权重和贡献能对账, so that 篮子结论可以重复计算。
30. As a 数据审查者, I want 其余 P1 认证包也逐家族核验, so that 旧标签不会替代 42 项认证完成条件。
31. As a 数据使用者, I want P2 的未认证、未授权、尚未发布和获取失败分别显示, so that 暂缺原因清楚且不会暗用代理。
32. As a 检索使用者, I want 同一唯一证据缺口在重复请求中保持身份, so that 命中率不会被重试或多个网址放大。
33. As a 检索使用者, I want 本地、TuShare、官方直连、Tavily、Exa 和受限 AI 按既定顺序处理, so that 成本及来源选择可解释。
34. As a 检索使用者, I want 未知官方网址与尚未发布被区别判断, so that 本来需要搜索的缺口不会提前被误挡。
35. As a 检索使用者, I want 候选原文经过家族解析和认证条件检查, so that 网页相关性不会被当作模型事实。
36. As a 检索使用者, I want 新发现但未认证的来源保留为候选, so that 搜索不能自动授予来源认证。
37. As a 运行维护者, I want 每次请求开始前与返回后都有持久审计, so that 进程中断不会静默漏账或重复扣用。
38. As a 检索使用者, I want 逻辑查询、物理请求和实际费用分开记录, so that 预算次数不会冒充账单。
39. As a 检索使用者, I want 事件、运行、日预算和负缓存同时约束重试, so that 缓存到期不会自动绕过其他限制。
40. As a 检索使用者, I want 完整运行仅针对真实缺口触发搜索, so that 已有有效证据不会被重复获取。
41. As a 研究者, I want 对同一批分层缺口比较 Tavily 与 Exa, so that 生产降级顺序不会造成供应商比较偏差。
42. As a 数据审查者, I want 模型可用补齐与实际投影采纳分别统计, so that 两个不同环节不会混成命中率。
43. As a 数据使用者, I want 无请求样本时显示 N/A, so that 我不会把它理解为零命中或供应商不可用。
44. As a 数据使用者, I want 页面明确目标交易日和数据截止点, so that 旧结果不会冒充新结论。
45. As a 数据使用者, I want 非典型组合保持空当前阶段及上一确认阶段, so that 系统不会强配一个阶段。
46. As a 报告使用者, I want 每段解释绑定支持证据与反证, so that 有效引用身份之外还能检查事实是否支持叙述。
47. As a 报告使用者, I want CLI 不可用、超时、校验拒收和成功分别记录, so that 降级报告不会被当成 AI 成功。
48. As a 报告使用者, I want AI 无法改写正式阶段和事实骨架, so that 叙述层不会改变确定性结论。
49. As a 模型维护者, I want 新规则只进入新不可变目录及候选模型, so that 历史发布不被重新解释或覆盖。
50. As a 模型维护者, I want 120 个中国交易日重放逐时点核对来源和输出, so that 通过记录有当前版本的真实证据。
51. As a 运行维护者, I want 真实演练与离线 fixture 明确分开, so that 测试通过不会冒充生产完成。
52. As a 系统所有者, I want 模型激活和系统切换绑定已验收清单与显式动作, so that 未完成认证的版本不会生效。

## Implementation Decisions

1. 保持既有深模块、WSL2 单机 SQLite、内容寻址原件、单 Worker、原子分析投影和只读页面架构。不为本任务引入新的阶段文件流水线、任务队列服务或全局重构。
2. 优先修复现有采集、证据仓库、检索编排、趋势输出、报告适配器、模型生命周期与运行读模型的公开边界；通用收据能力在核心采集这个完整行为中提取，并由后续采集复用，不单独安排无法演示的基础层重构票。
3. 一次采集保留请求标识、接口与脱敏参数、请求开始/接收完成/校验完成时间、响应原件、解析规则版本、标准化制品和产生的来源声明身份。原件与标准化内容分别存储和标记，哈希必须有可读取的对应内容。
4. 同一批次可对应多个声明；一份发布可对应多个指标。增加明确关联而不是要求 source_reference 字符串恰好等于制品登记键。历史无法证明的关联保持未追溯状态，不捏造原件或重写旧声明。
5. 原始响应受现有容量和引用保留规则管理；被正式证据引用的依据不能因普通临时响应过期而删除。无运行数据备份的既有决定保持不变。
6. release_at、public_available_at、fetched_at 和 available_at 独立。公开时间必须有可靠依据；只有可靠发布日期从下一本地日开始，无可靠日期为空。available_at 在取得且通过验证后记录，显式 SYSTEM 查询不得提前可见。
7. 对新采集及候选重放修复全部已识别的时间生成路径，包括核心历史、日刷新及上下文缺失时间回填。旧错误字段不原地修改；新版本选择规则不得继续让受否定性审查的旧声明参与新 PUBLIC 认证。
8. 来源/定义已认证、数值有效和在目标点时可见是不同条件。public 未知不自动等于 HTTP 或结构失败；它不能获得 PUBLIC 合格结论，SYSTEM 是否可选继续服从该模型认证和证据规则。
9. 候选持续天数输出实际连续计数；确认门槛独立表达。无候选按既有输出契约显示零或不适用；中断和反向信号正确重置，不因展示修复擅改趋势方向算法。
10. 61 项按频率及维度列出应有证据：日频按中国市场日历和来源制度，月季频按实际发布事件，事件型允许可见窗口内无事件，运维证据使用自身凭据。禁止用统一 120 条要求替代这些差异。
11. 正式三核心、NHII 方法与认证生效区间保持现有 ADR 约束；确认指数不取代核心。任何核心替换必须在候选模型层按已接受后备规则认证，不允许日内或逐日择优切换。
12. 五个市场家族分别交付可复核来源认证包。融资必须覆盖沪深北；CNY030 必须有正确身份与实值；估值按三个指数及全部要求字段检查；广度需历史池与预热；商品需真实合约和结算方法。
13. 其余 27 项 P1 同样有家族级官方语义和发布时间检查。沿用 ADR0013 的官方抽样认证交付渠道，不增加逐条历史观测双来源对账要求；全部 42 项 P1 的认证与目标日可用性分别验收。
14. 本稿不擅自冻结仍开放的业务选择：静态/滚动 PE 是否新增或改名、广度停牌和新股窗口、零分母表达、金额范围、商品选月缓冲/生效时点和基日/基值。对应家族票先根据已有证据形成明确决议，再实现和认证；仅提交选项或遇到无法取得的原件不得把该家族认证勾为完成。
15. 已有真实输入和失败反例继续复用：融资 120 日三所矩阵、三指数滚动 PE 样本、广度 120 日输入与两日停牌正负裁决均保留其有限证明范围。新股/停牌/金额规则未冻结前，不把候选输入直接登记为正式广度。
16. 商品收益采用已确定的同合约结算口径；换月不跨合约相除。固定七袖套及能源 20% 权重、生猪排除和不重复投票保持既有决定。尚未接受的具体日历选月和基点建议仍属待决条件。
17. P2 保留公开接入和受限授权分类；已允许的公开渠道可以补齐并认证，缺许可或无可靠来源者保留明确缺口。P2 缺口不改变正式阶段，不将九个缺源背景指标的全部取得作为 P1/核心模型的新增硬门。
18. 唯一检索证据缺口固定模型、指标定义、期次、维度、目标与 as-of；请求与重试不产生新缺口。一次实际发布事件可服务多个缺口，保留多对多归因并避免重复计量。预期发布窗口与已证实际发布事件分别标识，不为满足事件预算虚构一个实际发布时间。
19. 生产检索恢复已接受的固定顺序：有效本地证据、TuShare、已认证官方直连、Tavily、Exa、符合条件的受限 AI WebSearch。成功终止后续渠道；P2 在 Exa 后停止；报告 AI 不自行取数。未配置渠道明确记录，不用假成功填补链路。
20. 发布门禁以已知发布事实/窗口和定义判断；“未知原文 URL”不是“尚未发布”。真正未到发布窗口不搜索；可搜索事件不因缺少预先给定的 URL 而被全部挡住。
21. 搜索候选只进入适用的确定性家族解析器。检查官网身份及重定向、指标定义版本、统计期、维度、单位、数值、真实时间和原件；未认证新来源继续作为候选，只有满足目标模型输入条件才计为完整补齐。
22. 每次物理外部请求前持久登记/预留其身份和预算，返回后关联响应、结果及验证状态；中断留下明确的未知完成状态，恢复依既有显式恢复规则和可验证检查点处理，不暗中再请求或宣称提供商恰好调用一次。
23. 消费者可查逻辑查询、物理请求、重试、缓存命中、失败分类、候选淘汰原因、下一可试时间和供应商费用依据。没有实账或计费元数据的成本保持未知，不能以本地预算计数推算真实账单。
24. 以既有已接受初始检索决策为修复基线：事件 Tavily/Exa/AI 各 1，运行 8/4/1，日 16/8/2；P2 AI 为 0；自动关键词改写为 0。手动单指标深搜按既有提升范围运行，仍受已接受的日上限约束，不沿用无界日消费豁免。
25. 初始候选上限 3、摘要合计 1,800 字符、交给确定性解析器的已选页面片段上限 1,600 字符；原件另行保存，不因片段截断伪造字段完整性。无法在该边界内验证就保留未解决，后续参数变更须明确版本化。
26. 恢复已接受错误分类和缓存：超时/网络/5xx 为 15 分钟；空结果或语义/字段失败按 P0/P1 6 小时、P2 24 小时；429 按 Retry-After 或 60 分钟；402/403 按可信重置时点或次日 00:05。缓存、发布、事件每日一次和全日预算同时成立才能再试，缓存到期不自动解除其他门禁。具体提供商错误先按实际响应分类，不能把所有 403 武断当作已知付费额度原因。
27. 原始搜索响应保留 30 日；长期保留脱敏查询身份、原件指纹、验证结论、费用依据及补齐归因。响应过期明确标记，不以指纹代替仍可下载正文的承诺。当前只留 URL 的实现描述不能覆盖此前已接受的保留政策。
28. 定向刷新完成模型可用证据补齐；后续正式投影采纳通过真实模型运行边界验证。完整运行生成版本绑定的缺口计划，并在总预算内调用同一检索服务，避免另做第二套搜索算法。显式指定的历史 cutoff 不得为纳入新采集而前移；当次实时完整运行在采集窗口结束、计算前一次性冻结最终 SYSTEM cutoff，按它形成最终评价缺口集合与请求归因，不能先按旧 cutoff 宣称补齐再用新 cutoff 发布，也不能修改已冻结 scope 的身份。
29. 检索评价主指标是完整补齐且满足模型输入条件的唯一缺口数除以该渠道实际请求处理的唯一缺口数。HTTP 成功、有效原文、字段校验、需求总体覆盖和实际模型采纳是独立指标，所有分母均披露，无样本为 N/A。
30. 实测对照在独立实验标识下使用同一冻结、按家族/优先级/难度分层的真实缺口集合；两个渠道分别观测，不让先执行者的入库改变另一渠道起始缺口。生产仍串行，生产 Exa 条件补缺率与配对试验效果分开。样本、截止点、预算及停止条件在请求前固化；不事后挑选成功样本，不以旧五次探针或跨项目数字代替。
31. 不凭当前零样本拍定供应商命中率门槛或更换供应商；首次实测交付可复算基线、样本分母、未解决原因、耗时和实际可得费用。是否调整渠道、预算或扩大样本属于后续版本决策。
32. AI 继续使用已登录的 Codex/Claude CLI，应用不读取厂商 API key、不改直连 API。沿用一次报告每 CLI 最多一次、超时/取消/工具越界和后置校验规则。共同协议测试与真实成功证据分开。
33. 至少一份真实 CLI 输出通过事实骨架及逐段证据支持核对，才可标记 AI 解释验收通过；全失败仍可形成合法确定性降级报告，但解释验收单列未通过。该双栏结果不会把原本允许降级的系统运行改成新的 AI 可用性硬门。
34. 新目录/候选模型绑定全部定义、来源认证、选择与时间规则、公式及执行指纹；保持 v3 否定性审查与历史只读边界。旧值只能以明确旧版本身份重现，不作为新候选已通过的替代证据。
35. 版本回放使用精确 120 个中国交易日及最小必要预热。起止区间在执行前由认证交集与日历固定；保留原 2026-03-09 至 2026-08-28 作为已讨论目标区间，若来源可认证区间不支持就报告阻塞，不能静默挪日期缩窗宣称完成。
36. 当前目标日真实演练与历史回放分开，目标日按当时最新完整中国交易日确定并记录。验收读取实际 API/页面投影及报告绑定身份，不把生成日期当分析日期。
37. 模型激活、30 交易日内部逻辑回退、系统切换沿用既有显式操作和机器验收条件。实施时先完成可审阅的证据清单，再消费适用的用户授权；本次规格/拆票确认不冒充已有运行数据中的激活或切换记录。
38. 运行文档、质量/回归/性能结果、代码依赖、输入证据快照及清单指纹必须对应最终执行版本。后续搜索补入可能影响既有 cutoff 的声明/vintage 时，同样检查重放输入是否改变。任何后续代码或证据变化使制品失配时，只重跑受影响及既有必需门，不用前一代码或证据版本的全绿结果替代。

## Testing Decisions

1. 测试只断言用户可观察行为、持久证据与时间选择结果，不测试私有函数调用顺序、字段赋值实现或机械镜像。真实缺陷必须先有失败反例，修复后绿；无必要不做全局预重构。
2. **主测试入口：现有任务命令/API → 持久任务 → 单次 Worker 执行 → 投影/运行状态/证据/报告读取。** 使用隔离 SQLite 和内容寻址目录，替换外部数据 transport、时钟及 CLI 子进程响应；原件解析、规则选择、证据仓库与投影生成保持真实。当前 v3 正式隔离持续生效，测试成功路径使用独立且通过自身契约的测试模型，不能 patch 掉生产门禁。
3. 现有先例包括定向刷新串行检索、完整运行有效非典型组合、来源契约隔离、原子投影、绑定旧投影的报告命令、CLI 官方 LPR 采集及真实切换清单校验。沿用其公开提交与查询方式；既有只返回假 claim ID 的检索测试不足以证明新闭环，新增成功例必须能读回真实来源声明、原件、选值与投影关联。
4. **必要的领域边界例外：公开点时/系统点时选值接口，以及趋势/阶段的公开确定性接口。** 针对发布时间未知、发布日期跨日、请求完成边界、修订前后与冲突；针对候选 7→8 日、无候选、中断和反向。少量手算或人工核对的期望值独立于被测实现，不以同一引擎重跑一致作为全部正确证明。
5. 候选持续天数同时核对存储投影、API、Dashboard 和报告事实骨架。旧快照保留原样，新运行应给出修复字段；不修改已发布正文来让回归变绿。
6. 来源家族使用已保存真实原件做离线 parser→声明→点时选值→候选输出测试，并保存少量真实官方对照证据。错标识、错单位、错统计期、少成员、重复输入、矛盾修订、截断和未知时间必须有负例。
7. 广度保留现有两日停牌正负裁决反例，并增加换码、已退市、上市未满窗口、预热不足、盘后金额未知和零分母例；商品增加到期边界、不可知映射、跨合约相除和结算/收盘不同的反例。细节期望遵循完成后的明确业务决议。
8. 搜索从真实 transport 形状的可控响应走候选下载、认证条件、入库和采纳，测试官方域重定向、相关但错期网页、无原件、重复缺口、部分多维补齐、中断后未知结果、日预算、Retry-After 和 P2 停止。HTTP 重试与逻辑预算分别断言；不要只断言返回 candidate_source。
9. 真实 Tavily／Exa 实验必须显式与离线回归区分，报告零样本、拒绝样本、分层分母与未解决缺口；归因总数与登记尝试、声明和模型采用记录可对账。
10. 报告通过共同 schema/事实骨架/引用白名单测试后，再检查真实输出的段落事实与支持/反证一致。保留取消、超时、CLI 缺失和双失败确定性降级测试；事实身份一致不等于自然语言每句已获支持。
11. 120 日回放同时检查完整性、认证生效、隐藏预热、PUBLIC 的逐 cutoff 选择、差异解释和 SYSTEM 历史重现。新结果可能合理不同于旧结果，不把差异数必须为零设为目标；差异必须可归因且不含未来证据。
12. 最终按项目已有质量、回归、故障恢复和性能门执行。fixture、中断恢复与真实目标日演练分别留证；所有临时测试产物留在项目/工作树范围内，运行正式数据仍遵循已有 WSL 原生目录设计。文档阶段只检查文档结构、依赖和链接，不启动生产 Worker 或重复应用全量测试。

上述主入口与两个领域边界已由本轮用户继续指示确认；不提议新增面向测试的生产后门或横跨模块的 mock 网。

## Out of Scope

- 推翻三核心价格决定 Stage I–VI、让宏观/AI 投票、强配非典型阶段或训练新的投资预测模型。
- 在旧 v3 中原地修认证、倒填公开时间、覆盖历史报告/来源声明或删除失败研究制品。
- 默认并行调用 Tavily 和 Exa、无限搜索/重试、降低认证来提高命中率，或由搜索自动取得使用许可。
- 不经明确规则决策替换 CNY030、混用静态/滚动 PE、缩小金额范围、将盘后未知填零或切换商品代理。
- 强制所有指标都有 120 条值、所有历史值双源对账、所有受限 P2 必须采购后才允许核心阶段运行。
- 新增数据购买、凭据托管、对外数据分发、直接模型 API、常驻自动补跑、多 Worker 或新基础设施。
- 新建运行数据备份、把内部模型回退当作恢复旧系统运行。
- 修改或关闭原父任务22/25、原审查票或冻结审查文件。新票只贡献可链接的修复证据。
- 在本次规格与拆票阶段修改应用、调用真实搜索、执行模型激活或系统切换。
