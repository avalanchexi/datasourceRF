## 2. 单事件事实及独立手算

A1区分全年每10股5.96元、中期已派2.36元和本次末期3.60元。本次事件只能用末期税前每股`d=3.60/10=0.36`；不能把全年0.596元再次扣除，也不能把个别股东税后0.324元作为统一参考价调整。公告明确无送股和转增，因此本样本股份倍数为1。[A1第1页][announcement]

|日期|深交所前收`qss`|深交所今收`ss`|TuShare`pre_close`/`close`|渠道涨跌幅/官方展示|
|---|---:|---:|---|---|
|2026-06-11|11.32|11.30|11.32 / 11.30|−0.1767% / −0.18%|
|2026-06-12|10.94|11.24|10.94 / 11.24|2.7422% / 2.74%|

表内价格来自[Q1][quotes]及第1节T1实际行，而非根据分红反向生成。独立算式如下，本轮用Python标准库`Fraction`交叉复算，不调用应用计算引擎：

```text
股权登记日未复权收盘 P = 11.30 = 113/10
本次每股税前现金红利 d = 0.36 = 9/25
除息参考价 R = P − d = 10.94 = 547/50

前价归一到本次除息后基准的比例 k = R/P = 547/565
                                               = 0.9681415929203539823…
若用累计复权因子方向表示单事件跳变，则比值为1/k = 565/547。
11.30 × (547/565) = 10.94，精确相等。

除息日按参考价的涨幅 = (11.24/10.94 − 1) × 100%
                    = (1500/547)% = 2.742230347349177…%
错误使用昨日未复权收盘 = (11.24/11.30 − 1) × 100%
                      = (−60/113)% = −0.530973451327434…%
```

这说明直接用上一原始收盘会把本例上涨判断成下跌。已有渠道4位和官方2位展示与独立算式相容；不能以它们显示出来的舍入涨跌幅反向拼成“精确”120日调整链。[Q1][quotes]、[D1][daily-doc]

用于窗口软件例时，可以把两点写成`[10.94,11.24]`，独立等权均值为`11.09`；这只是两点算术核验，不是MA120验收。保存原价的可证十进制和精确有理比值，最后按获准输出规则格式化，避免先将547/565近似为二进制浮点再乘而造出本应相等价格的伪差异。这是由算式得出的实现建议，不是交易所为本项目规定的完整复权算法。

现金总回报的另一算式`((11.24+0.36)/11.30−1)×100% = (300/113)% = 2.654867…%`与参考价涨幅不同。不能将两者互称，或据单日参考价已匹配，便宣称已核验渠道的分红再投资算法。更早窗口价格逐项怎样接链仍须绑定明确公式与完整事件输入。

## 4. 送转、拆并股及完整链仍超出这个样本

本例明确没有送转，故不能覆盖股份倍数改变、配股对价、回购专户不参与导致的差异化分派、拆股或并股。后续每个事件应由自身原件绑定每旧股现金额、股份兑换/送转比例、必要对价、适用股份基数及生效日，不能只登记一个无来源的最终因子。[A1][announcement]、[票09已批准规则](business-decisions-draft.md:30)

已有深交所2026规则第4.4.2条给出了包含现金、配股价格及股份变动比例的参考价公式，第5.2.3条区分除权参考前收；[PDF原件](evidence-08/9b66f8b0db70f84a25ef1ccb4ee2351001724e408117552d75f6d8993483c586)的SHA-256为`9b66f8b0db70f84a25ef1ccb4ee2351001724e408117552d75f6d8993483c586`、282084字节，本轮重新验哈希。但该版7月6日生效，不能把它直接当成6月12日的适用规则原件；历史版本缺口沿用[研究08](research-08.md:42)。即使采用纯送转情形下`P/(1+s)`这样的代数退化式，也不代表已经取得一个真实送转样本，更不是完整120日认证。

## 5. 当前下载adj_factor能否证明当时可知

**不能单独证明。** 本轮读取并保存的[TuShare官方adj_factor说明][factor-doc]将接口定义为渠道自行生产的因子，可按股票或交易日期取历史；列出的输出只有`ts_code/trade_date/adj_factor`。它没有为本项目提供每个历史值的最初公开时间、修订vintage、事件原件绑定或历史as-of查询参数。盘前9:15–9:20是说明中的通常入库安排，不能逐行转成实测PUBLIC。此处结论是对该文档所能证明范围的判断，并未证明每个因子实际被改写，也未声称TuShare其他未查接口不存在额外能力。

[官方pro_bar说明][bar-doc]明确前复权利用价格乘当日因子再除基准因子，指定`end_date`决定回看基准，并说明采用分红再投资模式。由此可推断：把计算终点固定在历史T，只约束归一基准；今天取得的`factor(d)`是否等于历史T时已公开的那个版本，仍需独立证据。统一缩放在精确数学中可能不改变MA上方/极值比较，但历史修订、舍入或事件遗漏不能靠这个性质排除；也不能因此忽略已批准的当时可知链要求。

两个文档都没有把本例的547/565认证成TuShare实际历史因子比。本轮没有下载`adj_factor`真实响应；不能虚构000001对应因子绝对值或称已完成渠道因子对账。

## 7. 要闭合的最小剩余原件

1. **此现金事件的历史公开锚点**：第一方披露列表或发行人发布记录，明确绑定2026-025及同一正文哈希/身份；只有日期时保留日期精度，不能伪造当日开市前可知。
2. **历史价格可知性和调整制度**：6月11日收盘、6月12日参考前收及价格的当时可得证据；6月当时生效的交易规则或已认证历史制度包。事后Q1导出证明数值，不能独自补发布时间。
3. **事件连续链和预热**：同一稳定证券身份的窗口内及必要预热所有价格、已生效调整事件及其修订；一笔除息不能证明239个市场日期输入、全部股票或无遗漏事件。
4. **如使用渠道因子**：实际原响应、参数/字段、因子精度与定义、事件对应、原件及修订时序，逐目标日选当时可见vintage；否则保留输入不足。纯送转/拆并股等需另有真实样本，不继承本现金样本的通过结论。
