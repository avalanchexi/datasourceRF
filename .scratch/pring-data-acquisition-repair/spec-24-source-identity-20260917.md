# 规格：来源身份与新鲜度回退（2026-09-17）

由[票24](issues/24-non-official-adoptable-sources.md)的 grill 收敛而来。本规格取代票24 最初的范围——那份范围建立在两个后来被事实推翻的前提上。

## 被推翻的两个前提

| 立票时以为 | 事实 |
|---|---|
| 非官方来源要能被采用，需为 28 项建通用新身份 | [ADR-0013](../../docs/adr/0013-tushare-delivery-with-official-sampling.md) 早已允许 TuShare **认证为交付渠道**；用户 2026-09-17 确认"默认 TuShare 是官方通道"。那 28 项挂在未认证，是**认证工序没走完**，不是身份不够用 |
| 需要逐条对账、不一致即阻断 | 用户澄清规则是"**TuShare 更新不及时时用官方数据**"——新鲜度回退，不是逐条对账。不触碰 ADR-0013 的"不要求每条正式观测都同时拥有第二来源"，**无需修订任何 ADR** |

据 [2026-09-07 准备清单](p1-certification-readiness.md)，27 项 P1 的分流是 **A 18 / B 3 / C 2 / D 4**。**解锁整条链的关键路径是把 18 项 A 类走完 ADR-0013 的认证**，那是票13 的本职，不在本规格内。

## 本规格要建的行为

### 一、新鲜度回退

TuShare 是默认官方通道。当 TuShare 尚未发布某指标某期次时，该指标该期次改用官方页的值。

- 触发条件是**新鲜度**（上游有没有该期的行），**不是数值比对**——因此不需要容差，也不需要区分"修订差异"与"真实错误"。
- 粒度是**按指标、按期次**；**不中止运行**，其余指标不受影响。
- 每个点必须能查到**由哪条通道交付**。采集回执已逐次记录渠道，展示层需要能读出来。
- 两条通道都是官方级，因此点的**认证身份不因通道而跳变**；变化的只是交付通道。

**待确认的解读**：用户 2026-09-17 早先答"对账不一致：阻断则以官方数据为准"，晚些答"更新不及时用官方数据"。本规格把两条合并理解为**触发时改用官方值，而非中止运行**。若理解有误，一、二两节都要重写。

### 二、保守推定的 PUBLIC 时间

拿不到发布时刻时，PUBLIC 可见时间记为公告日/调整日**次日 00:00**。

- 它是证据模型里的**一等字段**，可查询、可按目标日回溯——不是采集回执上的附注，也不是注释。现有的 `publication_precision` 只是 `worker.py:1398` 的一个回执 kwarg，承担不了。
- 必须能与官方认证的发布时刻**区分开**，且在来源声明中写明"保守推定，非官方认证"。
- 方向安全：推定只会让数据**更晚**可见，不会让未公开的值被提前采用。这是它可接受的根本原因。
- 使用者：B 类 3 项（`CN_DR007`、`CN_SHIBOR_ON_1W_3M`、`CN_LPR_1Y_5Y`）与 C 类 2 项（`CN_RRR_EVENT`、`CN_FUTURES_WARRANTS`）。

### 三、指标口径修正

| 指标 | 动作 |
|---|---|
| `CN_USDCNH_FXCM` | 改用香港财资市场公会（TMA）USD/CNH 即期定盘为标准口径，**重命名去掉 FXCM**。注：该 id 的 FXCM 来自 TuShare 自己的标的代码 `USDCNH.FXCM`，属沿用上游代码时继承的缺陷 |
| `COMEX_GC_ACTIVE_MONTH_SETTLEMENT_USD_OZT` | **删除**。与 LBMA 金价信息高度重叠，且历史批量需 CME DataMine 付费 |
| `LBMA_GOLD_PRICE_PM_USD_OZT` | **删除**。历史需 ICE Benchmark Administration 授权，只能走 FRED 转发；为一项 P2 背景指标建整套非官方身份语义不划算 |
| `CBOE_VIX_INDEX` | 接 Cboe 官方免费 CSV，正常认证（TuShare `index_global` 的 20 个指数**不含** VIX） |
| `NASDAQ_SOX_INDEX` | 接 Nasdaq 官方指数站，正常认证（同样不在 `index_global` 内） |
| `CN_USDCNY_CLOSE_1630` | 接 CFETS / 中国货币网，正常认证。本项目已有该域通道（`CN_LPR_1Y_5Y` 走同一域且已认证） |

指标 id 是身份的一部分，重命名与删除都会波及目录版本、历史声明与投影，须作为独立迁移设计。

### 四、非官方身份：**不需要建**（2026-09-17 决定）

`LBMA_GOLD_PRICE_PM_USD_OZT` 是**唯一**真正无法官方认证的指标：历史数据需 ICE Benchmark Administration 授权，LBMA 站上的历史序列已应其要求下架，免费路径只有 FRED 的 `GOLDPMGBD228NLBM` 转发。

保留它，就要建整套新身份语义——新状态、选点与发布门禁、迁移、投影与报告的分开计数与展示。不保留，则**一项都不用建**。

**先例**：`context_projection.py:1189`、`:1268` 已在用 `derived_from_certified_inputs` 作为 `certification_status` 的第三个取值，横跨 7 个模块。投影层本就不是二值的，真要加时有形状可循。

**用户 2026-09-17 决定：暂不纳入 `LBMA_GOLD_PRICE_PM_USD_OZT`**，与 `COMEX_GC_…` 同样处理。

**于是新身份一项都不需要建。** 票24 最初的前提——"非官方可信来源要能被采用，需新增第三个可采用状态"——至此完全消解：TuShare 是官方通道，VIX/SOX/USDCNY 走各自官方通道，两项受限的黄金指标都不纳入。`certification_status` 保持现状。

日后真需要金价时再单独立票；那时先例仍在。

## 不在本规格内

- 那 18 项 A 类的认证执行（票13）。
- 第59批持锁身份（票23）。
- 120 天真实回放与切换（票21）、配对检索主指标（票20）。
- `tushare_context.py` / `official_context.py` 的拆分——应在本规格落地后再做，否则先拆再改会白做一次。

## 未核实

- 本项目 TuShare 令牌的积分等级（`index_global` 需 6000 分、`fx_daily` 需 2000 分）。
- 上述各官方 URL 当前是否可达、是否可程序化取用。
- TMA 定盘的取用方式。

三条都要发请求才知道，属实现阶段各票的第一步。
