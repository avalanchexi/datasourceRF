# Spec专项481：窗口父项范围

**结论：全批获取关联可以保留作审计血缘，但不能把未采用的独立报价变成每个窗口结果的必要父项。** 模型采用必须核对该输出实际计算及成员资格判断所需的120日、必要更早停牌参考、身份、日历和事件证据。规格不强制采用某种关联表结构；可以限定声明父项，也可以明确区分批次关联与实际父项。只要后续采用仍因无关报价损坏而失败，单纯保留全批关联就尚未满足要求。

依据：[规格Implementation 4](spec.md:128)明确“同一批次可对应多个声明”，所以全批审计关联本身不是越界。[票09](issues/09-breadth-window-metrics.md:25)则要求“每个派生结果绑定完整必要价格、复权事件、公式及父项集合”，第18行限定更早输入为“计算需要的更早参考”。[已确认规则09](business-decisions-draft.md:30)固定“共同市场最近120个交易日窗口，含当日”；第32行要求目标日当时已知的调整链和成员资格。[Testing21](spec.md:198)要求核对“父项集合及公式结果”。由这些条款可确定：取数批次大小不能扩大单日公式或资格的依赖范围。这是对条款共同语义的判断，并非存在一句禁止全批收据的明文；不引用信用脉冲专属Implementation41。

**P2静态发现：失败范围被扩大。** `tushare_context.py:300`把全批收据绑定每个窗口声明；`evidence.py:337`读取全部关联原件，`:354`因任一父件损坏返回空集；`market_breadth.py:738`重建全部输出后才筛选目标日，`:761`还比较整批标准化结果。因此独立未来/更早未采用日报价损坏，即使该输出全部必要证据及PUBLIC均完好，仍会使其采用失败。不能将这一结果解释为早日缺证。

最小可证伪公开场景：沿既有合法候选准入、公开采集及候选PUBLIC选择，用121个明确合成市场日生成D120、D121两个输出，无停牌/调整，所有必要时间已证。

1. 先确认两个输出均可采用，保存声明身份、值、PUBLIC及可查询血缘。
2. 仅损坏D121独立daily原件：D120仍应可采用，D121应失败。
3. 还原后仅损坏D1独立daily原件：D121窗口为D2–D121，仍应可采用；D120应失败。

使用不同内容哈希的日报价，保持共同身份、日历、事件覆盖及标准化制品完好。若某早日确实承担停牌参考、连续身份或排除成员的必要依据，它就是实际父项，损坏应阻断；不能只按日期粗删。一个物理原件同时承载必要与无关内容时，整件完整性仍必须校验。本场景针对可独立读取、确未采用的报价，不要求拆分原件或放宽完整性验证。无需新增业务选择；本轮未执行场景。
