# 24: 非官方可信来源成为可采用身份

**Problem:** 三项历史原件（DR007 首次公开时间、PP/CF/TA 仓单单位、存款准备金率发布时间）拿不到官方原件，整条链（票13→19→20→真实切换）因此停摆。用户已决定放开非官方可信来源并接受保守推定，但现有代码落不下去：`certification_status` 只有 `certified` 与 `awaiting_source_certification` 两个取值，而**只有 `certified` 会被选点与发布**（`evidence.py:267`、`437`、`500`、`1339`）。把非官方源标成 `certified` 会抹掉用户明确要求保留的区分，因此必须新增第三个身份。

**Blocked by:** 无。

**Dependency rationale:** 票13 的三项缺件不再是本票前置——本票要建的正是"没有官方原件时如何诚实地用数据"。

## 已定的口径

| 项 | 决定 |
|---|---|
| 新状态 | `certified_non_official`：**可被选点、可进入投影**，但在来源声明、投影与报告中与官方认证**分开计数与展示** |
| 保守推定 | 无发布时刻时，PUBLIC 可见时间记为公告日/调整日**次日 00:00**；只会让数据更晚可见，不会提前采用 |
| 可信源 | **TuShare**（已接入、令牌有效）；**商业数据商**（Wind / 同花顺 / 东方财富等）——具体哪一家对应哪些指标**尚待指定**，见下 |

## 待设计的可观察行为

- 新身份的声明可被选点并进入投影，且投影、报告与来源声明中**官方与非官方分开呈现**，任一只显示总数的地方都算未完成。
- 保守推定的 PUBLIC 时间**可查询、可回溯**：它是证据模型里的一等字段，不是采集回执上的附注，也不是注释。`publication_precision` 目前仅是 `worker.py:1398` 的一个回执 kwarg，不足以承担。
- 采用非官方源的值时，**原始来源身份、抓取回执与推定依据可关联**；不得出现"已采用但说不清来自哪家"的点。
- 模型清单的认证门（`evidence.py:1370` 的 `evidence_source_not_certified_by_model`）对新身份有明确规则：允许还是拒绝，须显式表达而非靠默认分支。
- 真实切换与票19 候选目录对新身份的接纳规则明确：能否参与、如何在就绪清单中标示。

## 验收条件

- [ ] 新增 `certified_non_official` 并覆盖选点、发布、投影、报告四处路径；官方与非官方在每一处都分开计数，有反例证明混算会失败。
- [ ] 保守推定的 PUBLIC 时间落入证据模型并可按目标日回溯；有反例证明推定值不会让公告当日的值被采用。
- [ ] 具名可信源清单落成可检验规则：清单外的来源不得取得该身份；每个源与其覆盖的指标一一对应。
- [ ] 数据库迁移与既有数据的兼容：已存的两种状态语义不变，旧清单不因新状态而失效。
- [ ] 票13 的三项缺件按本票口径分别落定：取得官方原件的照旧认证，取不到的以新身份加保守推定采用，**并在来源声明中写明是保守推定而非官方认证**。

## 仍需用户指定

1. **`CN_USDCNH_FXCM` 的口径要重新定义。** FXCM 是零售经纪商，它的报价是自家撮合价、不是任何基准；把它当离岸人民币的标准口径，与票13"数值对得上不等于口径有依据"是同一类问题。改用香港财资市场公会（TMA）的 USD/CNH 即期定盘，还是明确它只是参考价？
2. **黄金要一项还是两项。** `COMEX_GC`（期货结算价）与 `LBMA_GOLD`（伦敦现货定盘）信息高度重叠，且两项都取意味着两条受限通道（CME DataMine 付费、IBA 授权）。
3. **对账不一致如何处置**（承第一节）。
