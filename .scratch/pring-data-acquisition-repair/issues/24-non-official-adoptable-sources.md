# 24: 非官方可信来源成为可采用身份

**Problem:** 三项历史原件（DR007 首次公开时间、PP/CF/TA 仓单单位、存款准备金率发布时间）拿不到官方原件，整条链（票13→19→20→真实切换）因此停摆。用户已决定放开非官方可信来源并接受保守推定，但现有代码落不下去：`certification_status` 只有 `certified` 与 `awaiting_source_certification` 两个取值，而**只有 `certified` 会被选点与发布**（`evidence.py:267`、`437`、`500`、`1339`）。把非官方源标成 `certified` 会抹掉用户明确要求保留的区分，因此必须新增第三个身份。

**Blocked by:** 无。

**Dependency rationale:** 票13 的三项缺件不再是本票前置——本票要建的正是"没有官方原件时如何诚实地用数据"。

## 待设计的可观察行为

### 阻断口径的代价，须在设计时正面处理

"TuShare 优先、官方页只做对账"加上"不一致即阻断、官方为准"，合起来意味着：

1. **官方页仍需每次运行都取**——否则无从对账。所谓"只做对账"不减少请求，只改变谁是取数主路径。
2. **官方与 TuShare 的差异多半来自修订时点，而非错误。** CPI、PMI、社融这类月度数据会修订；两个通道的快照时点不同，数值就会不同。按"不一致即阻断"，例行运行会**频繁失败**。
3. 因此设计必须回答：**什么算"不一致"**——完全相等，还是允许容差？修订导致的差异如何与真实错误区分？阻断的是整个运行，还是仅该指标？
4. "以官方为准"与"TuShare 优先"并存时，**实际被采用的值是官方的**——那么这 8 项的身份就不是常态 `certified_non_official`，而是取决于官方页当次是否可达。身份可能逐日变化，展示层必须能表达。

第 3、4 条是本票实现前必须定清的，**不能靠默认分支蒙混**。

## 与既有 ADR 的冲突（2026-09-17 grill 期间发现）

立票时我没查 ADR，漏了两条已接受的决定，它们直接管本票的核心问题：

**[ADR-0013](../../../docs/adr/0013-tushare-delivery-with-official-sampling.md)「P1 结构化交付采用 TuShare 并以官方样本复核」**：

> 对 TuShare 已稳定提供结构化字段的 P1 指标，系统可以把 TuShare **认证为交付渠道**，但必须先用对应官方发布样本核对指标语义、字段、单位、统计期、发布时间和使用许可；**不要求每条正式观测都同时拥有第二来源**。任一 Schema family 的官方抽样或许可核验失败时，该 family 仍保持未认证。

两处冲突：

1. **"第三个状态"可能根本不需要。** 按 ADR-0013，TuShare **可以被认证为 `certified` 交付渠道**——门槛是"每族做一次官方样本核对"，不是"每条观测都有官方原件"。那 28 项之所以还是 `awaiting_source_certification`，很可能是**这次抽样核对还没做**，而不是 TuShare 天生只能是非官方。若如此，本票的新状态只需覆盖真正无法核验的来源（FRED 转发的金价、保守推定的发布时刻），范围大幅缩小。
2. **"每次运行都对账 + 不一致即阻断"与 ADR-0013 明文相反**——它写的是"不要求每条正式观测都同时拥有第二来源"。新规则要求每条观测都有第二来源并逐条比对。

**[ADR-0006](../../../docs/adr/0006-dual-as-of-and-immutable-evidence-vintages.md)「双点时语义与不可变版本」**已有冲突处置先例：

> 多来源冲突**不平均**；**P0 过期或冲突时不生成新正式阶段**。

即：冲突不取中间值（与"以官方为准"一致），且阻断粒度**按优先级区分**——P0 冲突才阻断正式阶段。新规则"任何不一致即阻断"比这严，且不分优先级。

**采纳新规则等于修订这两条 ADR**，必须显式做（写新 ADR 取代或补充），不能靠本票悄悄改掉。

## Q1 的事实：ADR-0013 要求的盘点早就做过（2026-09-07）

[27 项 P1 候选认证准备清单](../p1-certification-readiness.md)正是按 ADR-0013 做的逐族核查，分流结果：

| 分流 | 数量 | 含义 | 卡在什么 |
|---|---|---|---|
| **A** | **18** | 可先整理官方候选认证材料 | **没卡在证据，卡在"这项工作还没做"** |
| **B** | 3 | 数值材料齐，时间或使用条款待核 | `CN_DR007`、`CN_SHIBOR_ON_1W_3M`、`CN_LPR_1Y_5Y`——历史 PUBLIC 未知 |
| **C** | 2 | 外部原件仍缺 | `CN_RRR_EVENT`、`CN_FUTURES_WARRANTS` |
| **D** | 4 | 纯派生，依赖父项 | 父项认证即可 |

**结论：那 28 项挂在 `awaiting_source_certification`，主因是 ADR-0013 的认证工作没执行完，不是 TuShare 天生只能算非官方。** 18 项 A 类的材料齐备、只差走完认证流程。

因此 `certified_non_official` 真正需要覆盖的，收缩到：

- **B 类 3 项**的历史 PUBLIC 时间（用保守推定次日 00:00）；
- **C 类 2 项**的外部原件（RRR 事件、仓单单位）——即票13 的三项缺件；
- **FRED 转发的金价**（IBA 授权限制，无法取得官方原件）。

从"28 项需要新身份"缩到 **6 项左右**。本票范围应据此重写。

**这也意味着本票不是解锁链条的关键路径**——把 18 项 A 类走完认证，才是。那是票13 的本职工作，本票只补它补不上的那几项。

## Q1/Q2 的答复（2026-09-17）与由此得到的三处缺口答案

> **Q1**：默认 TuShare 是官方通道
> **Q2**：当 TuShare 数据更新不及时时，使用官方的数据

### 这与 ADR-0013 不再冲突

"默认 TuShare 是官方通道"正是 ADR-0013 已经允许的——**TuShare 可认证为交付渠道**，门槛是每族一次官方样本核对。所以那 18 项 A 类走完认证即 `certified`，本票不需要为它们造新身份。

"更新不及时用官方数据"是**新鲜度回退**，不是逐条对账。它不要求每条观测都有第二来源，因此**不触碰** ADR-0013 的"不要求每条正式观测都同时拥有第二来源"，**无需修订任何 ADR**。

### 对前一条答复的解读，需确认

2026-09-17 早先答"对账不一致：阻断则以官方数据为准"。结合本次"更新不及时用官方数据"，我把两条一并理解为：**触发时改用官方值，而不是中止整个运行**——即"阻断"指的是阻断 TuShare 那一版的采用，不是阻断运行。若这个理解有误，须在实现前纠正。

### 三处缺口的答案

| 缺口 | 答案 |
|---|---|
| **什么算"不一致"** | 触发条件不是数值比对，而是**新鲜度**：TuShare 尚未发布该期次。这是客观可判的（有没有该期的行），**不需要容差**，也不需要区分"修订差异"与"真实错误"——原先那个难题随触发条件的改变而消失 |
| **阻断粒度** | 不阻断运行。**按指标回退**：该指标该期次改用官方值，其余指标不受影响 |
| **身份逐日变化怎么展示** | 两条通道**都是官方级**（TuShare 经 ADR-0013 认证、官方页本就是官方），所以身份不在 `certified` 与非官方之间跳变。真正逐日变化的是**哪条通道交付了这个点**，而采集回执本就逐次记录渠道。展示层只需能显示"本期由哪条通道交付"，不需要新的身份语义 |

### 一个已有先例

`context_projection.py:1189`、`:1268` 已经在用 **`derived_from_certified_inputs`** 作为 `certification_status` 的第三个取值（派生指标用），且该值出现在 7 个模块。**投影层本来就不是二值的**——若将来确需 `certified_non_official`，有现成的形状可循，不是新发明。

### 本票剩下的真实范围

大幅收缩。不再需要"让非官方源可被采用"的通用机制，只剩：

1. **新鲜度回退**：TuShare 未出该期时改用官方值，按指标、按期次，留痕哪条通道交付。
2. **保守推定的 PUBLIC 时间**（次日 00:00）落入证据模型，供 B 类 3 项与 C 类 2 项使用。
3. **`LBMA_GOLD` 走 FRED 转发**——唯一真正需要非官方身份的一项；也可选择改为不纳入模型，从而完全不需要新状态。
4. **指标口径修正**：USD/CNH 改用 TMA 定盘并重命名；删除 `COMEX_GC_…`。
5. **VIX / SOX / USDCNY_CLOSE_1630** 走各自官方通道，正常认证，不需新身份。

**而解锁整条链的关键路径不在本票**，在把那 18 项 A 类走完 ADR-0013 的认证——那是票13 的本职。
