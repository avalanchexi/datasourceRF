# 26: 保守推定的 PUBLIC 时间成为证据模型的一等字段

**What to build:** 拿不到官方发布时刻的指标，其 PUBLIC 可见时间按公告日/调整日次日 00:00 记录，且使用者能看出这是推定而非官方认证的时刻。

**Blocked by:** 无。

**Dependency rationale:** 票13 的 B 类 3 项与 C 类 2 项都卡在这一点；本票建的是它们可用的诚实表达方式，不代替取得原件。

## 待设计的可观察行为

- 推定时间是**证据模型里可查询、可按目标日回溯的字段**，不是采集回执上的附注，也不是注释。现有 `publication_precision` 只是 `worker.py:1398` 的回执 kwarg，承担不了。
- 推定与官方认证的发布时刻**可区分**；来源声明中写明"保守推定，非官方认证"。
- **方向安全可验证**：推定只让数据更晚可见。须有反例证明公告当日的值不会被采用。
- 使用者：`CN_DR007`、`CN_SHIBOR_ON_1W_3M`、`CN_LPR_1Y_5Y`（B 类）与 `CN_RRR_EVENT`、`CN_FUTURES_WARRANTS`（C 类）。
- 日后取得真实发布时刻时，可用它取代推定值，且**历史判断不被追改**（[ADR-0006](../../../docs/adr/0006-dual-as-of-and-immutable-evidence-vintages.md) 的不可变版本语义）。

## 验收条件

- [ ] 推定时间可按目标日回溯查询，且与官方时刻在查询结果中可区分。
- [ ] 公开反例：公告当日的值不被采用；次日起才可用。
- [ ] 来源声明中出现"保守推定"字样，变异检查证明去掉标注会失败。
- [ ] 数据库迁移不改变既有点的语义；未推定的点行为不变。

## 范围

本票不认证任何来源，也不解除票13 对官方原件的记录；取得原件后仍应改用真实时刻。
