# 02: 核心采集原件与双点时可追溯

**What to build:** 一次核心历史或日刷新后，用户能够从来源声明读取实际响应、标准化结果及四类时间，并通过公开点时和系统点时查询确认可见边界。

**Blocked by:** None (can start immediately).

**Dependency rationale:** 以核心采集完成一个通用收据能力的纵向切片，后续上下文与检索复用。

**Status:** ready-for-agent

## Acceptance criteria

- [x] 真实采集入口保存脱敏请求身份、原始响应、标准化制品、解析规则与声明关联；哈希必须对应可读内容，不能只记 normalized hash。
- [x] available_at 在接收并通过校验后记录；请求开始与校验完成之间的 SYSTEM 查询不能选中该新声明。
- [x] 移除核心历史及日刷新的固定 15:30 发布推定；可靠精确时刻、仅可靠日期、未知日期三种情况分别遵守领域规则。
- [x] PUBLIC 未知的声明不得被计为公开点时可用，且不混同传输或数值校验失败。
- [x] 旧声明与历史快照不修改；无法还原的历史原件关联明确标为未知，禁止用旧全量制品冒充新请求。
- [x] 以隔离运行库执行采集→声明→两种 as-of 查询，包含校验失败不写声明及制品写入中断反例。

## Testing decisions

以规格中的公开任务/采集/查询边界验证可观察行为，复用真实解析与证据仓库；只替换外部 transport、时钟或 CLI 子进程。来源实测、隔离 fixture 与正式发布分别标识，必要反例先失败再修复，不以实现自身的重复计算替代独立期望。
