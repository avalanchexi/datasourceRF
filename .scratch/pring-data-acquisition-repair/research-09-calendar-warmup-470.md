## 3. 最小可复用提取方式

下面是报告中的只读提取示例，可独立复算边界和指纹；不导入应用、不写文件。它不产生股票池、价格或认证声明。先拒绝重复原行，再取所需日期，不能用集合悄悄去重来掩盖原件异常。

```python
from datetime import date, datetime
from hashlib import sha256
import json
from pathlib import Path

raw = Path(
    ".scratch/pring-data-acquisition-repair/core-transport-196/"
    "2c8576c3d87cca2973053122683cd3ee48c1b29b3524f500179e123d40785705.json"
).read_bytes()
assert sha256(raw).hexdigest() == (
    "2c8576c3d87cca2973053122683cd3ee48c1b29b3524f500179e123d40785705"
)
data = json.loads(raw)["data"]
assert data["fields"] == ["cal_date", "is_open"]
rows = data["items"]
assert len(rows) == len({day for day, _ in rows}) == 3525
assert all(type(flag) is int and flag in (0, 1) for _, flag in rows)
calendar_dates = sorted(datetime.strptime(day, "%Y%m%d").date() for day, _ in rows)
assert len(calendar_dates) == (calendar_dates[-1] - calendar_dates[0]).days + 1
opens = sorted(
    datetime.strptime(day, "%Y%m%d").date()
    for day, flag in rows if flag == 1
)
first, last = date(2026, 3, 9), date(2026, 8, 28)
visible = [day for day in opens if first <= day <= last]
warmup = [day for day in opens if day < first][-119:]
inputs = warmup + visible
assert len(warmup) == 119 and len(visible) == 120
assert warmup[0] == date(2025, 9, 3) and warmup[-1] == date(2026, 3, 6)
assert visible[0] == first and visible[-1] == last
assert len(inputs) == len(set(inputs)) == 239 and inputs == sorted(inputs)
assert [day for day in opens if day < warmup[0]][-1] == date(2025, 9, 2)
assert sha256(("\n".join(day.isoformat() for day in inputs) + "\n").encode()).hexdigest() == (
    "69647b0bb9c9a95d5b527d1387cc12f9fc027d21ec3be2e5d53370b84b642d2e"
)
```

首个可见日的窗口为 `inputs[0:120]`，最后一个可见日的窗口为 `inputs[119:239]`。每个窗口都由 120 个不同市场日组成；输出日期仍只有 `visible` 中 120 日。若某成员首个预热日停牌且需要此前已证价格，09-02 是该日历上的紧邻参考日；连续停牌或调整链可能需要更早输入，原日历可继续向前查，但**实际需要多早由成员事实决定，日历存在不等于参考价格与事件也存在**。[窗口与停牌规则](business-decisions-draft.md#L28)

## 4. 软件 fixture 与真实认证的界限

**软件验证可以立即复用：**以此真实 SSE 日历日期序列构造隔离共同窗口，明确其来源和作为 fixture 的适用范围；用合成股票、合法成员事件及价格数据覆盖 239 个输入日，经已批准公开采集／准入／候选查询验证仅输出 120 日、隐藏预热不外泄、重复日不凑数、每一输出消费正确的必要窗口。时间对照采用明确标识的合成 PUBLIC 证明；既存日历原件保持不变。该路径不需新增网络请求，也不需拿股价日期代替独立日历。

**真实认证仍有不同层次的缺口：**

1. 196 请求身份仅为 `exchange=SSE`，不能把这份响应的源身份改成 SZSE、BSE 或“已认证三所共同日历”。本轮在仓库所查 `cal_date` 原件、04/05/08 收据和休市材料中，找到的是 SSE 长短日历和 SSE 两年安排；未找到同期 SZSE/BSE 日历原响应或足以在本轮闭合三所共同市场身份的完整官方材料。这里不据此断言三所实际日期不同，只保留未核证的适用范围。
2. TuShare 原响应没有 `release_at`、`public_available_at`、版本首发或修订时间。2026-09-11 的实际接收时刻不能回填为 2017—2026 每天的历史 PUBLIC，也不能把研究取得时刻当作应用首次验证后的 SYSTEM 可用时刻。[196 原请求收据](core-transport-196/receipts.json)、[ADR0006](../../docs/adr/0006-dual-as-of-and-immutable-evidence-vintages.md)
3. SSE 两份年度页**确有可见日期级锚点**：2024-12-23 和 2025-12-22；不能一概写为“没有任何发布日期证据”。按项目日期精度规则，若经正式来源审查接受页面日期与正文版本的绑定，可分别从 2024-12-24、2025-12-23 的上海本地日开始用于相应安排。页面元数据的“页面生成时间”、URL 日期、下载时刻不能升级为精确首次发布时间。年度页没有单独交付全部历史修订版本；本轮没有新建 source claim、审查通过或日历认证记录。[2025 原件第 329–362 行](evidence-04/754afc6d12a01013cbadeef55e656aebc4e40aa7ef1cb63792f17dabf9bccdf8.html#L329)、[2026 原件第 329–366 行](evidence-04/11d8a102d0747eaa8e97d9eda71eb9544ce30adbe83c706f7bdc77be4084686b.html#L329)、[规格时间规则](spec.md#L130)
4. 即使日历来源认证完成，票 09 仍须补齐 119 预热日及必要更早参考的真实逐股身份、价格、停复牌与当时可知调整链；两份 CSI 指数原响应不能补成这些股票输入。旧 [08 研究](research-08.md)所列“首个输出日前 119 日完整输入未齐”依然可能成立；本报告只关闭“找不到足够日期原件”的软件准备疑问，不关闭整项输入认证。

本轮已执行的是本地字节哈希、日期结构、窗口计数、原件间日期集合和上述有序指纹核算；没有执行应用测试或 120 日候选回放。新日历下载数 0、2025 软件日期缺行数 0、真实股票预热认证通过数未评估。原票状态、旧证据和正式模型全部保持原样。
