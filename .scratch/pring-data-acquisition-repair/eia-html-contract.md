| `EIA_BRENT_RBRTE` | RBRTE | `https://www.eia.gov/dnav/pet/hist/RBRTED.htm` | Europe Brent Spot Price FOB | Dollars per Barrel → `usd_per_barrel` |
| `EIA_WTI_RWTC` | RWTC | `https://www.eia.gov/dnav/pet/hist/RWTCD.htm` | Cushing, OK WTI Spot Price FOB | 同上 |

新取得的[官方父日表](https://www.eia.gov/dnav/pet/PET_PRI_SPT_S1_D.htm)将两行分别标为WTI - Cushing, Oklahoma / Brent - Europe，注明原油USD/barrel、产品USD/gallon；历史链接与两日页对应。父表同日对照：08-28为WTI84.57、Brent89.75；09-01为91.48、96.02。该父表可作同源格式/身份交叉核对，不算第二独立来源。官方[定义说明](https://www.eia.gov/dnav/pet/TblDefs/pet_pri_spt_tbldef2.asp)区分即时交付现货与其他价格，并说明周/月/年值是日收盘现货价的非加权平均；因此不能拿周值替代周五日值。

## 2. HTML结构与日期坐标

两份已保存日页均采用每行**6个格**：首格周区间（class B6），后5个格为Mon到Fri（class B3）。表头的首格class G2、5个日期列class G。class是当前观察到的结构证据，不能替代语义表头校验。页面还嵌套布局表、导航、图例，解析器应选中唯一正确表头对应的数据行，不从整页任意数字中抽值。

每周标签包括起始年、起始月日及结束月日，如`2026 Aug-31 to Sep- 4`。将起始日期解释为周一，每个数据格按列偏移0至4天；验证结束日期等于起始+4天，并处理跨月/跨年。月份应按固定英文缩写词表解析，不依赖运行主机中文区域。每行必须保留空格位置，不能先删除空格再zip日期。

以下为原始格顺序，不是重新排列后的文本：

| 序列/周标签 | Mon | Tue | Wed | Thu | Fri |
|---|---:|---:|---:|---:|---:|
| Brent `1987 May-18 to May-22` | 空 | 空 | 18.63 | 18.45 | 18.55 |
| WTI `1985 Dec-30 to Jan- 3` | 空 | 空 | 空 | 25.56 | 26.00 |
| Brent `2026 Aug-24 to Aug-28` | 92.71 | 88.24 | 87.77 | 90.18 | 89.75 |
| WTI 同周 | 86.34 | 83.90 | 83.46 | 84.81 | 84.57 |
| Brent `2026 Aug-31 to Sep- 4` | 空 | 96.02 | 空 | 空 | 空 |
| WTI 同周 | 87.03 | 91.48 | 空 | 空 | 空 |

因此Brent96.02属于**2026-09-01**，不是08-31；WTI第一笔25.56属于**1986-01-02**，不是1985-12-30或1985-01-02。Brent全历史从05-18的网格开始，但第一笔数值为1987-05-20。`period_start=period_end=该格的实际日期`，日频含义不能被周标签改成周频。不得为了补中国交易日而将美英源日历空格补值。

结构拒绝条件：周起止不一致、不是预期Mon–Fri列、缺/多数据格、错误跨年、重叠日期、同系列同日重复或冲突、错表头、页面仅有布局/验证码、响应被截断、无法按声明字符集可靠解码。错位必须在候选入库前拒绝；不能先算出“看起来合理”的值再靠范围容差通过。

## 3. 空值、特殊标记及真实负数

官方图例定义四个标记：`-`无数据报告、`--`不适用、`NA`不可得、`W`为防止披露个体公司数据而不公布。它们分别保留原始标记和对应缺值原因，不合并为0。空`<td>`/`&nbsp;`只证明该日期格没有数值，**不自动证明休市、未发布或数值为零**。网页图例中的字符不是日期观测，不能计入缺值统计。

[逐格统计](evidence-14-eia-followup/source-inspection.json)由已存原始字节独立重算；两页所有周起止、6格结构和不重复日期均通过：

| 统计 | RBRTE | RWTC |
|---|---:|---:|
| 日期格总数 | 10,255 | 10,615 |
| 有限数值 | 9,967 | 10,236 |
| 正数 | 9,967 | 10,235 |
| 负数 | 0 | **1** |
| 数字0 | 0 | 0 |
| 空格 | 288 | 379 |
| 日期格中的`- / -- / NA / W` | 各0 | 各0 |
| 03-09至09-04窗口数值 | 122 | 123 |
| 该2026窗口内负数 | 0 | 0 |

唯一负值是官方RWTC **2020-04-20 = -36.98 USD/barrel**；后四格依次8.91、13.64、15.06、15.99。对应Brent同日17.36。这是从本页取得的WTI现货原始值，不是从WTI期货负价格新闻代入。[官方WTI日页](https://www.eia.gov/dnav/pet/hist/RWTCD.htm)

解析层应区分完整的有符号十进制数字、空格、四类明示缺值、未知非法标记；`-36.98`属于数值，单独`-`才是图例标记。拒绝NaN/Infinity及不能识别的非数值，不因负号误判缺值。此次没有0，故数字0作为明确数值的测试只能标为隔离反例，不能声称找到了真实0。值域异常与数值解析分离，未知阈值不能擅自当成EIA官方规则。

当前API的`0<value<1000`不能直接套到包含1980年代起全历史的HTML。建议先完整解析并保留源值/日期格，再按**明确请求的日期窗口**选候选及执行适用验证：2020负值不会令2026请求整页失败；若请求覆盖2020-04-20，必须保留-36.98或给出明确“当前模型不支持该值域”的局部原因，不得写NA、0或静默删日。不得让窗口外结构错误（如整体列错位）因此绕过结构校验。

## 4. 发布时间：东部时间有新依据，历史逐日首次时间仍无证据

新增[EIA发布总表](https://www.eia.gov/reports/upcoming.php)写明：**“All releases are in eastern time.”** 这为EIA发布日历采用美国东部时间提供了官方依据；实现使用IANA `America/New_York`是对Eastern的工程映射，以处理EST/EDT，不能全年固定UTC−5。本页没有单列RBRTE/RWTC的具体发布钟点，所以不能移植Weekly Petroleum Status Report的10:30或13:00到本表。石油数据入口列出的这些时刻也属于具体周报，并非每条现货日值的首次公开时间。[发布总表原件](evidence-14-eia-followup/966a610f36397c815edc2ed6fcd3b857ea5725eb6ef6723dbea9a48990f02ae9)

两份既有日页和本次父日表均明确：`Release Date: 9/2/2026`，`Next Release Date: 9/10/2026`。应保存原始日期字符串、规范化日期、日期精度、源时区、来源原件和解释规则版本。下一次日期属于计划，不是已经发布；日期会随假期/修订变动，不硬编码“每天”或“每周三”。

| 时间字段/事实 | 可以表达 | 不可表达 |
|---|---|---|
| 页面Release Date=09-02 | 当前页面声明的发布批次日期，精度为日 | 每条历史日值的首次发布日期；09-02具体几点 |
| 已定保守日期规则 + Eastern | 对**声明批次**可计算09-03 00:00−04:00，即09-03 04:00Z，标明“日期精度的保守边界” | 把该值写成真实精确release_at；把观察日+1直接当发布时间 |
| Next Release Date=09-10 | 当次快照声明的下一计划发布日期，可用于展示待更新 | 保证09-10必定发布；把09-10所有缺格先写成not_published；提前登记未来值 |
| Brent HTML注释09:11:32、WTI注释09:11:39 | 页面生成元数据，且没有明示时区 | 已认证的公开时刻 |
| 子页Last-Modified、父页Last-Modified09-02 15:35:56GMT | HTTP对象修改元数据，各页面可不同 | 上游逐日首次公开时间，或统一的09:11发布钟点 |
| 本次取得/校验完成 | SYSTEM可用时间的真实取得链路组成 | PUBLIC首次时间，或过去系统已经拥有数据 |

**推荐建模边界：批次时间与观测首次时间分开。** 可以把已认证页面的Release Date按现有保守规则解释为“该发布批次的可用边界”；是否将该边界绑定到这个响应版本，须由HTML来源认证明确批次字段与正文的关系，不能仅因日期字段存在就自动认证。历史行的`original_public_available_at`仍未知，不能把20世纪每个交易日回填为当天/次日发布。若将历史行作为此批次重新报告的版本登记，必须显式标为“本批次版本”，可见时间不得早于本批次边界；这只支持批次以后读取，**不能据此通过批次以前的历史PUBLIC重放**。本次取回的精确字节是否与09-02某一时刻逐字相同，也没有历史快照证明。

建议首轮接入保留批次日期元数据和准确SYSTEM时间，按项目既有未知公开时间规则隔离未证历史；不为通过120日重放生成合成发布时间。两表最新数值到09-01可作为当前候选，但03-09至08-28的原始历史PUBLIC可得性仍需对应历史批次/可靠发布证据。不能把“日频观测”误等于“每日公开发布”。

1. 已保存[EIA Copyrights and Reuse](https://www.eia.gov/about/copyrights_reuse.php)对其网站数据、文件、数据库等给出一般使用/分发说明，并要求标注EIA来源及发布日期。
2. 同页单列受保护材料：网站上由私人/机构贡献或许可的部分资源可能受版权保护，超出适用使用范围需权利人许可。此例外不能删除或改写为“EIA所有内容无条件公有领域”。
3. 本次[系列定义/来源页](https://www.eia.gov/dnav/pet/TblDefs/pet_pri_spt_tbldef2.asp)确实标注`Refinitiv, an LSEG business`；该页、两个历史页和父日表中**没有找到针对RBRTE/RWTC本地个人分析、下载或存储的额外具体禁令/采购条件**。署名说明上游来源，不等于一份明确的用途禁止条款，也不证明用户没有使用权。

基于上述文本及项目既有公开渠道/本地个人分析授权，建议继续正式取得候选，保存EIA发布渠道、Refinitiv上游署名、版权说明快照、源日期和实际使用范围；**本轮没有识别出需要用户另做用途/许可选择的新具体条款**。这是一项限于已读公开材料和已授权用途的研究判断，不是替Refinitiv授予许可证，也不声称查遍了所有合同。剩余接入门槛是数据来源认证、时间/字段/修订/完整性验收；以后发现明确适用于两序列及实际用途的限制，再按具体证据处理。对外再分发、商用或直接Refinitiv账户服务均不包含在本候选接入结论内。

公开HTTP成功、许可判断、解析通过与模型采纳分别记录；不能把“可公开读”当成来源已经认证，亦不能把一般第三方例外自动转成`not_authorized`。
