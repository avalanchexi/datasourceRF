# 确定 WebSearch 结果的准确性与时效验证规则

## Question

对 Tavily/Exa/AI WebSearch 取得的值：官方域名白名单如何维护与按指标划分；原文保存与数值、统计期、发布日期的解析规则；与注册源交叉核对时的容差（按指标还是统一）；没有可核对源也不在白名单时如何处理；验证结果如何写入加工批次以便追溯；检索预算是否保留现值。

## Answer

2026-09-23 与用户两轮访谈确定。

1. **渠道**：检索降级链为 TuShare → 注册官方直连 → Tavily → AI WebSearch。**Exa 保留，但只作 Tavily 月度限额耗尽时的备用**：Tavily 未达月限额时不调用 Exa；达限后由 Exa 顶替 Tavily 的位置。搜索渠道只是传输手段，前提是数据源头为注册来源：候选页面主机必须在白名单内。
2. **准确性（分级）**：
   - P0/P1：严格。搜索只负责找网址，系统按网址重新抓取原文，由登记的解析器解析数值；Tavily/AI 给出的数值一律不用。若搜索渠道也报了数值或日期，与解析结果比对：小数位数/数量级明显不同（疑似单位或小数点错位）或时效（统计期、发布日期）差别很大，则**不采纳**，按检索未通过处理（原因：与搜索结果不一致）。不设按指标的数值容差。没有解析器的主机不可用。
   - P2：宽松。来源主机在白名单即可接受 Tavily 或 AI 抽出的数值，须保存页面原文及哈希；不要求专门解析器。随之取消“P2 禁用 AI WebSearch”（`retrieval.py:96`）。
   - 起始决策 3 的“与注册源交叉核对、差值在容差内”**取消**：到了搜索这一步，注册源本期已缺值，没有同期值可核对；不设容差、不做通用抽取器。
3. **白名单**：沿用代码常量，按解析器家族登记“主机＋路径前缀”（现 `official_context.py:2308`、`official_lpr.py:29`），随代码版本变化；指标经所属家族对应到白名单。P2 宽松路径同样需在该表登记主机。
4. **时效**：页面必须解析出发布日期，且统计期不早于应有期；日期缺失或晚于运行截止时点即不通过。公开可用时间与注册源同式：min(推算发布时点, 首次取得时间)，页面日期只作校验。
5. **WebSearch 取得的发布预告**：只接受白名单官方日程页上由解析器解析出的预告；否则丢弃，回落到“统计期末后第 N 个交易日”推算，不记缺口。
6. **不通过的处置**：不产生数值，记检索证据缺口。页面与报告的缺口清单单列“检索未通过”，展示指标、应有期、候选网址（≤3）、逐网址原因（不在白名单 / 解析失败 / 统计期不符 / 无发布日期 / 日期晚于截止时点）与批次 id，供用户人工排查（不展示批次 id）；重试走手动深搜，不设人工采用入口。
7. **追溯**：一次手动完整运行即一个加工批次（用户：启动并获取今日数据所产生的明细与派生指标为一个批次）。每次检索记录渠道、查询、返回网址、实际抓取网址、原文哈希、解析器版本（P2 宽松路径记抽取方式）、结果与原因，挂批次 id。**批次与检索记录不在页面或报告中展示，仅用于问题排查时查询**；即现 `retrieval_candidate_validation` 去掉 `run_attempt`、`public_complete`、`public_selected_*` 等回放/认证列。批次表结构本身归票 06。
8. **预算**：适量放开。**取消每日硬上限**；Tavily、Exa 只保留每次运行上限并放宽为 16、8（原 8、4），防止单次运行失控；**AI WebSearch 放开**，不设次数上限，只以“每个检索证据缺口每次运行至多一次”自然收敛，且对 P0/P1/P2 均可用；实际外部约束是 Tavily 月度限额。Exa 预算只在 Tavily 达月限额后才被消耗；手动深搜保留。

术语已同步 CONTEXT.md：改写“检索降级链”“已验证证据”，新增“检索未通过”。取代 ADR 由票 09 统一撰写。
