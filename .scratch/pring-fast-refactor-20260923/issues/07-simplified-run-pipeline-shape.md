# 确定精简后的完整运行流程形状

## Question

主流程保持“获取 → 校验 → 派生 → 投影 → 报告”不变的前提下，三道门分别位于哪一步、失败时各产生什么结果（阻断正式阶段、可见缺口、拒收）；哪些模块保留、合并或删除；模型版本简化为版本号＋显式切换后，运行如何选取模型；首次初始化与日常滚动运行的区别。

## Answer

2026-09-23 与用户三轮访谈确定。

1. **流程与三道门位置**：获取 → **③结构/接口校验**（不通过即拒收、不入库，记入批次）→ **②时效**（current / awaiting_release / stale）→ **①完整性**（枚举窗口内应有明细与公式父输入，得缺口清单）→ 对 missing 与 stale 检索补缺（awaiting_release 不触发；检索结果同过③与票 05 验证）→ 重评①②、冻结输入 → 计算 → 原子发布 → 报告 → 运行末尾按票 06 清理。
2. **P0 缺失**：先补全。顺序 TuShare（缺失重试一次）→ Tavily（达月限额改 Exa）→ AI WebSearch → 按网址重抓原文由解析器解析。**须新写三核心官方页面解析器**：中证指数官网（000985、000012）与南华官网（NHII），并登记其白名单主机。
3. **补全仍失败**：**核心沿用**——只落后 1 期时以上一交易日值参与计算，照常产出正式阶段，页面与报告醒目标注“核心沿用上一期”；落后 ≥2 期或冲突时阻断正式阶段（核心数据待处理），但运行仍完成并发布宏观、库存、缺口等其余输出与报告。沿用值不写成明细；日后重跑同日取到真值则生成新批次与新汇总。**修订票 04 第 9 条的 P0 部分**。
4. **P1/P2 解析异常**：一律按③拒收计入缺口，不再抛出中断运行（改 `worker.py:1652`）；该缺口与普通缺失同样进入检索补缺，**最终由 WebSearch 补全**（Tavily→Exa 备用→AI WebSearch，按票 05 的 P1 严格 / P2 宽松规则验证），仍补不上才按票 04 的沿用或缺失处置。
5. **模块去留**：整删 `material_preflight.py`、`candidate_admission.py`（先迁出目录迁移定义与结构校验）、`model_evaluation.py`、`acceptance.py`、`cutover.py`；迁出少量函数后删 `source_certification.py`、`rehearsals.py`（smoke 命令一并删）；逐处剥离 `source_contract_review.py`、`evidence.py`、`search_evidence.py`、`full_run_requirements.py` 的认证门与逐值发布证据；对应 CLI 命令（`model-source-certify`、`model-input-preflight*`、`model-accept/replay`、验收、演练、切换）一并删除。
6. **模型选取**：运行使用生效指针指向的版本；切换 = `model-activate <版本号>`，无验收、无回放；回退 = 切回旧版本号；版本号记入批次；切换只影响之后的运行，不重算已生成汇总。
7. **首次初始化与日常**：库中无汇总时，拉 120 交易日明细＋公式回看，逐日算出窗口内每一天的汇总、重建阶段史，只为目标交易日生成报告；日常运行只算目标交易日。
8. **漏跑补算**：自动补算窗口内漏跑交易日的汇总，各日只用公开可用时间不晚于该日的明细（票 04 时点规则），不为补算日生成报告；与首次初始化共用逐日计算。
9. **中断**：取消检查点恢复。中断即判失败，重启作为新批次从头运行；保留租约、取消与同目标日幂等。
