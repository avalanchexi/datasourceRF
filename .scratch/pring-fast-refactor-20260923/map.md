# 精简门禁、快速可追溯地产出全部硬输出

## Destination

重构后的系统对**最近交易日**（窗口随目标日滚动）真实跑通一次手动完整运行，产出当前设计的全部硬输出：
三核心状态、正式阶段、阶段特征卡、宏观/库存状态、120 日证据窗口明细和报告；指标目录沿用现有版本（CNY030 为 P2）。
数据准备快速、按加工批次可追溯，开发只跑受影响验证。

### 访谈确认的起始决策（2026-09-23，用户确认“按推荐”）

1. **优化对象**：主要是开发周期；不做非必要的全量验收，只跑受影响验证。
2. **注册来源免验证**：TuShare 与已注册官方直连源不做逐值发布证据、不要求来源认证包；只按**更新频率**判定时效（频率＋发布滞后＋宽限登记在注册表），公开可用时间按该约定推定。保留廉价结构校验（字段/单位/统计期/非空）。
3. **WebSearch 须验证**：准确性 = 白名单官方页面且数值自原文解析，或与注册源交叉核对在容差内（二者满足其一）；时效性 = 页面可见发布日期在窗口内且统计期符合应有期。否则记检索证据缺口。
4. **门禁只剩三道**：①120 交易日内发布的明细是否完整；②数据时效是否正确；③加工是否经正确接口（含结构校验）。三核心缺失仍阻断正式阶段；P1 缺失改为可见缺口不阻断；模型生命周期简化为版本号＋显式切换；系统切换前真实验收取消；AI 降级报告保留。
5. **留存**：~~明细留存期 = 120 日证据窗口＋公式所需回看；汇总结果长期保存~~ → 已由[确定明细留存、汇总保存与加工批次结构](issues/06-detail-retention-and-processing-batch.md)改为明细、汇总、批次统一 120 个交易日；老日期不再支持新模型回放。
6. **追溯**：以加工批次为单位——批次 id、目标交易日、接口与参数、条数、原始响应哈希、时效与结构校验结果、代码版本；明细与汇总均挂批次 id。

## Decisions so far

- [盘点现有门禁与完整运行流程](issues/01-inventory-gates-and-run-pipeline.md)：待删门禁主要是与主链分离的认证→准入→回放→激活→切换旁路链，4 个模块可整删（candidate_admission 须先迁出目录迁移定义）；认证标签与逐值发布证据嵌在主链需逐处剥离；新门①②须新写；worker 中 TuShare 非 P2 异常仍阻断整次运行。
- [盘点测试套件与被删门禁的耦合](issues/03-test-suite-layering.md)：93% 耗时集中在 5 个文件，根因是认证→准入→回放→激活的隔离生命周期夹具（冷建 1742–2068 秒）；22 文件/353 例可整删、47 文件需改写；删门后估计 30–50 分钟（推断），现无不依赖被删门禁的五环端到端用例。
- [盘点注册来源及其频率与发布滞后](issues/02-registered-source-freshness-inventory.md)：生效目录 59 项（P0 6 / P1 41 / P2 12）；TuShare 31、官方直连 17、派生 5、运维 2；USDCNY 16:30、VIX、SOX 与沪深融资新 ID 无可用注册路径；代码无逐源滞后/宽限登记，仅可复用 release_calendar 与 metric_contracts 最大陈旧期；TuShare 宏观接口更新时点须按官方日程推定。
- [确定按频率的时效判定契约](issues/04-freshness-contract.md)：按“应有期＋宽限”判定时效，用交易日计数（日频宽限 1 日，周/月/季 7 日）；发布时点按预告（TuShare→官方→WebSearch）或登记滞后推算；公开可用时间取推算时点与首次取得的较早者；P1/P2 落后 1 期沿用并标缺口、≥2 期视为缺失；时效不拒收；目标交易日由人工启动时点自动决定。
- [确定 WebSearch 结果的准确性与时效验证规则](issues/05-websearch-verification-rule.md)：Exa 只作 Tavily 月限额备用；来源主机须在注册白名单；P0/P1 数值只由登记解析器从重抓原文解析，与搜索值小数位数或时效差别很大则不采纳；P2 可接受 Tavily/AI 抽值并放开 AI WebSearch；取消交叉核对与容差；公开时间与注册源同式；不通过记缺口并单列“检索未通过”提示；批次记录仅供排查不展示；预算取消每日上限，Tavily/Exa 每次运行上限放宽一倍，AI WebSearch 不设上限（每缺口每次运行至多一次）。
- [确定明细留存、汇总保存与加工批次结构](issues/06-detail-retention-and-processing-batch.md)：明细、汇总、加工批次统一只留 120 个交易日，成功运行末尾物理删除；超窗公式回看每次运行临时拉取不入库；批次 = 运行（扩展 `parent_run`、复用 `acquisition_request`），汇总挂非外键 `batch_id`；修订与重跑一律按普通批次追加、取最新；取消双 as-of。
- [确定精简后的完整运行流程形状](issues/07-simplified-run-pipeline-shape.md)：获取→③→②→①→检索补缺→重评→计算→发布→报告→清理；P0 缺失先经 TuShare/WebSearch 补全（须新写中证与南华官网解析器），仍缺则沿用 1 期、≥2 期才阻断（修订票 04）；P1/P2 解析异常改为拒收并经 WebSearch 补全；整删 5 模块、迁出后删 2 个；模型用生效指针＋版本号切换；首次逐日建窗、漏跑自动补算；取消检查点恢复。
