## 每片的流程

1. 读票面、ADR-0036 与相关勘察；只读调查、审查一律 `codex exec -s read-only ... < /dev/null`，不开 Claude 子代理。
2. TDD：先写失败测试，再实现。
3. 跑受影响测试 + 两例切片冒烟（`docs/agents/testing.md`）；涉及 Worker 取数或指标目录时加跑 `test_worker_registered_catalog.py` 与 `test_core_carry_forward.py`。长任务后台跑，约每 3 分钟报进度。
4. Codex 两轴审查（规格、标准），阻断全修完、复审无阻断。
5. 票面 `Status`、验收勾选、`## Comments`（实施记录、验证结果、审查结论、只记录不修的行为差异）、README 票表；单独提交。

## 停下来等用户的情形

- 出现与本票无关的测试失败：报告并说明，不跳过、不删测试；能确认是已知抖动（如高负载下 `database is locked`）的，重跑并记进 Comments。
- 实施中发现票面与 ADR-0036 没写的行为差异：只记进 Comments，不顺手修；若阻碍完成判定，停下问。
- 真实运行失败、Worker 意外退出、TuShare 限额耗尽或外部来源大面积不可用：停下报告，不反复重试。
