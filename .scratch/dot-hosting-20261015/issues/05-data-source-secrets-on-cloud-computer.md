# 数据源密钥在云电脑上怎么交给应用

## Question

应用现在只从仓库外的 `secrets.env` 读四个数据源密钥（`TUSHARE_TOKEN`、`EIA_API_KEY`、`TAVILY_API_KEY`、`EXA_API_KEY`），所有调用方都经 `parse_data_source_secrets(paths.secrets)`。访谈 Q3 定了 token 在 dot 上只放密钥或环境变量、不写入任何文件。要决定：应用改为读环境变量、继续读文件，还是两者都读（谁优先）；本机开发环境保留哪种；`doctor` 与日志脱敏检查怎么认定“已配置”；用户经什么渠道把密钥放进云电脑而不经过 AI 对话；若云电脑没有密钥配置入口，退路是什么。

## 进度

- 2026-10-15 开票并领取（实测等待期间，用户选择先做这张；与实测结果无关的部分可先定）。
- 2026-10-15 第一轮（用户确认）：环境变量优先、文件兜底，白名单不变；本机继续用 `secrets.env`；访谈 Q3 落为“不在对话里粘贴、不回显、不进 git/日志/报告、看护提示禁止 dot 读取或输出”，无平台入口时允许用户经接管亲手写仓库外 0600 文件；密钥入口与变量继承交实测，已追加为清单“步 1b”与提示词 B 第 8 条。
- 2026-10-15 第二轮（用户确认）：Q5–Q9，见答案。

## Answer

2026-10-15 与用户逐题确认（两轮，Q1–Q9）。

- **读取方式**：四键白名单不变，仍只有一个读取入口；先读进程环境变量，缺的键再从仓库外 `secrets.env` 补（环境变量优先）。所有调用方不改。
- **本机**：继续用 `secrets.env`（0600）与 `secrets-migrate`，不要求改成环境变量。
- **访谈 Q3 的落地约束**：密钥进了 dot 能操作的云电脑，dot 就有能力读到，“AI 读不到”做不到。可执行的保证是：不在对话里粘贴、不在终端回显、不进 git/日志/报告、看护提示禁止 dot 读取或输出。访谈 Q3 的“不写入任何文件”收窄为“不留经对话产生的明文副本”。
- **投放渠道**：首选平台上由用户自己设置的环境变量或密钥入口；没有入口时，用户经 ChatGPT“接管”云电脑亲手写仓库外 0600 的 `secrets.env`。是否有入口、后台进程能否继承，由[实测](02-trial-run-on-dot-cloud-computer.md)清单“步 1b”与提示词 B 第 8 条带回（只用假变量 `PRING_TRIAL_DUMMY`）。
- **占位值加代理替换**：只有确认代理也替换 JSON 正文和 URL 参数时，TuShare（正文）与 EIA（URL 参数）才走该入口，否则这两个退回 0600 文件；Tavily、Exa 的密钥在请求头里，可以用。切换当天用 `doctor` 加一次串行 TuShare `trade_cal` 调用确认真实可用。
- **`doctor` 与脱敏**：每个数据源显示 `enabled (env)`、`enabled (file)` 或 `disabled`；同一键两处都有值时标“文件值被覆盖”，不显示值。日志脱敏检查用合并后的值比对。
- **数据迁移**：迁移包只含运行库与 `artifacts/`，明确排除 `config/secrets.env`；云电脑上由 `pring-cycle init` 生成空模板。
- **换密钥**：环境变量只在进程启动时读入，换或新增密钥后由 dot 重启 Worker 与 Web（与“部署 main”同一重启步骤），再用 `doctor` 确认。
- **dot 禁止项**：写进看护任务提示词与给 dot 的长期项目说明：禁止 `env`、`printenv`、用 `cat`/`less` 打开 `secrets.env`、`set -x` 等会回显的命令；回复与推送不得含密钥；确认配置只用 `pring-cycle doctor --json`。

不新增领域术语；不另立 ADR，只修订 ADR-0043 关于 token 存放的一句。
