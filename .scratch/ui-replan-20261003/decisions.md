# 界面重新规划——访谈决定（2026-10-03）

来源：`/grill-with-docs` 访谈，用户逐题确认。勘察（Codex 只读）见本文末尾"现状"。下一步：`/prototype`。

## 决定

1. **三类页面**：数据看板、运行健康（运行血缘健康监测）、证据链。
2. **第一眼**：结论在上、数据健康在下（看板首页）；三个分区各自成页。
3. **范围**：基于现有设计重新规划信息架构并重构全站，不只改首页。
4. **加工批次上页面（只到摘要）**：运行健康页展示运行健康摘要（按来源、环节、结果汇总的计数、成败、耗时、趋势），不展示参数、哈希、原文；已修订 ADR-0022 与 `CONTEXT.md`（加工批次、运行健康摘要）。
5. **桑基图**：用于运行健康页——来源（TuShare、人民银行、郑商所……）→ 环节（直取、补缺、各级检索）→ 结果（采用、拒收、失败、缺口），宽度为请求数或声明数。证据链页**不用**桑基图，用竖向链＋树状展开。
6. **信息架构**：三个一级分区——
   - 数据看板：总览首页；下设核心资产、宏观、库存、阶段史、发布日历（报告归此分区或单列第四项，原型中定）；
   - 运行健康：运行（现 `/runs`）＋新的血缘健康监测；
   - 证据链：新页，可从任意数值点入，也可按指标与统计期检索。
7. **技术栈**：继续 Dash（ADR-0007），图表用 Plotly（含桑基图），重写布局与 CSS。
8. **看板走势图**：Worker 在核心资产投影中加入 120 日价格与均线点位；首页三资产卡带走势小图，阶段史以 120 日阶段色带呈现。页面不计算。
9. **运行健康摘要由 Worker 在运行结束时算好并留存**，页面只读；内容：本次关键数（请求、耗时、检索预算、缺口数，对比上次）、桑基图、近 N 次运行趋势（耗时、请求、缺口）、时效状态分布。
10. **证据链页范围**：结论卡 → 观测（标明跨目录版本归并，ADR-0036）→ 来源声明（选中、其他来源、冲突、修订）→ 获取回执（来源、接口、时间、校验结果）→ 原件（可查看原文）；派生指标递归展开公式输入。不做报告证据链（ADR-0027），不回溯留存期外。
11. **视觉方向**：先用当前投影导出的真实数据做两版静态原型——A 沿用现有基调（米白、青绿、明暗双主题）重排；B option-1 玻璃风——对比后再定。
12. **流程**：`/prototype`（三页原型，视觉两个方向）→ 定稿 → `/to-spec` → `/to-tickets` → `/implement`。
