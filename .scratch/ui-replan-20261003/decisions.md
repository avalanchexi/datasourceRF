# 界面重新规划——访谈决定（2026-10-03）

来源：`/grill-with-docs` 访谈，用户逐题确认。勘察（Codex 只读）见本文末尾"现状"。下一步：`/prototype`。

## 决定

1. **三类页面**：数据看板、运行健康（运行血缘健康监测）、证据链。
2. **第一眼**：结论在上、数据健康在下（看板首页）；三个分区各自成页。
3. **范围**：基于现有设计重新规划信息架构并重构全站，不只改首页。
4. **加工批次上页面（只到摘要）**：运行健康页展示运行健康摘要（按来源、环节、结果汇总的计数、成败、耗时、趋势），不展示参数、哈希、原文；已修订 ADR-0022 与 `CONTEXT.md`（加工批次、运行健康摘要）。
5. **桑基图**：用于运行健康页——来源（TuShare、人民银行、郑商所……）→ 环节（直取、补缺、各级检索）→ 结果（采用、拒收、失败、缺口），宽度为请求数或声明数。证据链页**不用**桑基图，用竖向链＋树状展开。
6. **信息架构**：三个一级分区——
   - 数据看板：总览首页；下设核心资产、宏观、库存、阶段史、发布日历（报告归此分区或单列第四项，原型中定）；
   - 运行健康：运行（现 `/runs`）＋新的血缘健康监测；
   - 证据链：新页，可从任意数值点入，也可按指标与统计期检索。
7. **技术栈**：继续 Dash（ADR-0007），图表用 Plotly（含桑基图），重写布局与 CSS。
8. **看板走势图**：Worker 在核心资产投影中加入 120 日价格与均线点位；首页三资产卡带走势小图，阶段史以 120 日阶段色带呈现。页面不计算。
9. **运行健康摘要由 Worker 在运行结束时算好并留存**，页面只读；内容：本次关键数（请求、耗时、检索预算、缺口数，对比上次）、桑基图、近 N 次运行趋势（耗时、请求、缺口）、时效状态分布。
10. **证据链页范围**：结论卡 → 观测（标明跨目录版本归并，ADR-0036）→ 来源声明（选中、其他来源、冲突、修订）→ 获取回执（来源、接口、时间、校验结果）→ 原件（可查看原文）；派生指标递归展开公式输入。不做报告证据链（ADR-0027），不回溯留存期外。
11. **视觉方向**：先用当前投影导出的真实数据做两版静态原型——A 沿用现有基调（米白、青绿、明暗双主题）重排；B option-1 玻璃风——对比后再定。
12. **流程**：`/prototype`（三页原型，视觉两个方向）→ 定稿 → `/to-spec` → `/to-tickets` → `/implement`。

## 用户补充要求（2026-10-03，作为原型与实施的验收标准）

- **紧密结合现有数据**：原型与页面只用当前投影、运行记录与证据仓库里真实存在的字段和数量；不放模拟指标、不虚构图表；某项数据为空（如当前正式阶段为空、`core_data_pending`）时如实呈现空态与原因。
- **布局与呈现**：布局合理，要素直观、逻辑清晰（先结论、后依据、再追溯）；遵守前端设计规范（信息层级、栅格与间距、字号体系、对比度与可访问性、明暗主题一致）与交互规范（可点击元素有明确反馈、深链接可回退、加载与空态、键盘可达、减少动画偏好）。

## 第二轮访谈：首页报告化（2026-10-03）

原型（分支 `prototype/ui-replan-20261003`，`efa64e3`）被评为信息密度不足；用户以旧项目 `D:\cursor\datasource` 的 `reports/2026-08-19-背景扫描120.md` 为参照。决定（逐题确认）：

1. **首页即报告式长页**：① 周期结论 → ② 三核心与同类资产（按债／股／商三条线分组：核心指数状态、距均线、斜率、候选、120 日走势＋同类上下文指标）→ ③ 海外与汇率 → ④ 宏观事后确认（四项结论、支持／反证、关键指标表）→ ⑤ 库存周期 → ⑥ 周期说明与阶段史 → ⑦ 数据说明；左侧固定目录，数值可点入证据链；运行健康、证据链为二级页面。呈现可用表格或图标等最直观形式。原型只出一个版本。
2. **结论区**：正式阶段（空时写原因）、三核心状态与候选、确认度、非典型组合解读、一句话总结；不加投资建议与仓位。
3. **资产表只用现有 61 个指标**，暂不新增指标；旧报告有而本项目无的（上证50、创业板、上证、深证、COMEX 黄金与铜、BCOM/GSCI、DXY、CNH、BDI、MLF、M0、北向／南向／ETF 资金流）记为候选扩充清单，另行立项。
4. **周期几轮**：不回放历史；按普林格指标判断当前周期，以往各轮在指标、参数、条件不变时保持原样。
5. **列口径**：最新值、近 5 日、近 120 日变化、本系统状态与方向（MA120＋斜率、30 日候选）、走势；Worker 写入投影，页面不计算。
6. **说明方式**：参考旧报告的分层说明，但按本项目数据设计，不套模板；判定方法不变（三核心价格趋势定阶段，宏观只做事后确认）。
7. **非典型组合解读**（新术语，已入 `CONTEXT.md`）：AI 报告依据已验证结果说明与哪些典型阶段只差一项、偏离资产及候选、观察点；不构成阶段判断；运行时默认 Codex CLI 自动生成，失败改用 Claude Code CLI，经解释校验保存。
8. **诊断文字分工**：结论、计数、确认度由 Worker 确定性模板生成；综合解读与非典型组合解读由 CLI（AI 报告）生成，首页以"AI 解读"区块单列。
9. **确认度**（Q16–Q20）：
   - 定义：当前正式阶段的典型经济叙事获得多少宏观与库存证据支持；非概率、非预测、非胜率；不影响阶段、不阻止发布、不改写阶段史。
   - 旧项目只借鉴分层展示与逐项支持／反证／未确认；不搬阈值权重、景气分推库存、90% 起分加减、缺失给半分、宏观改写阶段、DR007 推阶段、配置模板（DR007 等可作转折观察证据）。
   - 形状：政策、信用、过热、物价、库存五维 × 六阶段预期表，每格含支持／反证／未确认／仅观察，随模型版本冻结；首页显示"支持 S、反证 C、未确认 U（可评估 n/5）"及支持率，可展开；首版不分档；非典型组合时"不适用"，照列五维事实并配非典型组合解读。
   - 先修现有宏观结论语义漏洞（`overheated` 不可达、unknown 可致物价 `easing`、heating／cooling 不对称、商品核心 NHII 自我确认、库存卡 `support` 只表示有现行证据）。
   - 预期表另开一轮 `/grill-with-docs` 逐格拍板，底稿为 `docs/research/pring-six-stage-meanings.md` 与 Codex 初稿（见 `legacy-pring-model-survey.md` 第 5 节）。
