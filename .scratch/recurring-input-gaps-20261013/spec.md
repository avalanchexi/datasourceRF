# 规格：反复出现的输入缺口（2026-10-13）

来源：2026-10-13 对“补齐后是否还会出现异常”的访谈（grill-with-docs）。事实取证见 [codex-recurrence-20261013.md](codex-recurrence-20261013.md)，依据是三次体检：`run-97250978…`、`run-b7d59b63…`（目标日 10-09）与 `run-0a8dabc2…`（目标日 10-12）。三次的缺失明细是同一套。

## Problem Statement

用户关心的是：每天 T+1 跑完 Pring 周期模型后，输入是否完整、结果能否直接看。三次真实运行的体检都列出同一批缺口，而且每次都会再出现。这些缺口性质不同，混在一起报告：

- 有的是真正的数据缺失。两融合计在次一交易日 09:05 公开，T+1 运行本来就是为等它而改到次晨（ADR-0041），可是目标日的公开截止被钉在目标日结束，所以运行时已经取到也永远不进模型。
- 有的是上游确实还没发布，例如 EIA 日频现货价按周发布。模型用最新已发布值，这本是正常状态，体检却把它计入“真正缺失”。
- 有的是标签与词表矛盾。证据时效在 T+1 冻结时把持有应有期的 DR007、SHIBOR、公开市场操作等 5 项标成 awaiting_release，每次都产生假的“未到”信号。
- 有的是固定历史缺口。期货仓单 07-21（CU、RB、RU、SC、SP）与 09-09（PP）TuShare 返回 0 行，体检标为“上游未发布”，但很可能是 TuShare 漏了，交易所其实发布过。

结果是：真正的数据异常会被淹没在每次都出现的噪音里，用户无法凭“真正缺失为 0”判断当天输入完整。

## Solution

按用户对**数据异常**的定义（数据缺失、日历错误、数据偏差；上游未发布而用最新已发布值的不算，见 CONTEXT.md）把四类缺口各自处理到位：

1. T+1 运行让目标日汇总使用运行冻结前已公开、期次不晚于目标日的数据。两融当天就进模型，自动运行改到 09:30 发起。
2. 证据时效按词表判定：持有应有期即 current。
3. 体检把“上游未发布、模型已用最新已发布值”单列，不计入真正缺失；体检的公开截止与生产新口径一致。
4. 仓单的两天历史缺口如实标注来源，在体检中单列为“已知历史缺口”，等窗口自然移出。

完成后，一次正常的 T+1 运行体检里“真正缺失”应为 0。若不为 0，就代表真的出了数据异常。

## User Stories

1. 作为模型使用者，我希望 T+1 运行用上目标日的两融合计，这样确认度与观察读数不必落后一期。
2. 作为模型使用者，我希望自动运行在两融公开之后才发起，这样不会因为请求太早而取不到。
3. 作为模型使用者，我希望补算日汇总的口径保持不变，这样历史阶段不会因为本次改动而漂移。
4. 作为模型使用者，我希望已有的目标日汇总不被追加更正，这样改动只影响之后的运行。
5. 作为模型使用者，我希望报告与页面上的证据时效与词表一致，持有应有期就显示 current，这样我不会被假的“待发布”误导。
6. 作为模型使用者，我希望下一期已经发布但尚未持有时，仍能看到真正的滞后标签，这样真滞后不会被一并抹掉。
7. 作为体检读者，我希望“上游未发布、已用最新已发布值”的条目单列，不计入真正缺失，这样真正缺失为 0 时就代表输入完整。
8. 作为体检读者，我希望体检判断“公开时间晚于截止”时用与生产相同的新口径，这样两融不会被体检误报为不进模型。
9. 作为体检读者，我希望仓单 07-21、09-09 的缺口标签与事实相符：交易所发布过就标“来源缺失”，没发布才标“上游未发布”。
10. 作为体检读者，我希望已知历史缺口单列、不静音，并写明预计移出窗口的目标日，这样我知道它何时消失。
11. 作为体检读者，我希望 SOX 指数这类无取数路径（ADR-0029）的永久缺口在文档中有说明，这样不会每次都怀疑它。
12. 作为维护者，我希望目标日公开截止只在一处计算，这样计划、补缺门禁和投影不会各用各的口径。
13. 作为维护者，我希望收尾验收用一次真实 T+1 运行加体检证明“真正缺失为 0”，并与 `run-0a8dabc2…` 的差异都有原因。

## Implementation Decisions

- **目标日公开截止**：由“冻结截止与目标日结束取早者”改为“运行冻结截止”，同时选值期次不晚于目标日。补算日不变，仍只用公开可用时间不晚于该日的明细。生产中计划、补缺门禁与投影目前各自计算这一截止，先收拢到一处再改口径。历史目标日的手动重跑同样按冻结截止取数，与 CONTEXT.md 的目标日汇总定义一致。已在 CONTEXT.md 与 ADR-0041 补写中记录。
- **调度时刻**：计划的发起时刻由 09:00 改为 09:30；P0 截止（提交日 21:00）、补交与幂等键规则不变。计划配置里的时刻若随版本保存，按现有计划版本机制处理。
- **证据时效判定**：持有期不早于应有期即为 current；未过宽限为 awaiting_release，已过宽限为 stale。“已发布期”只用于标注下一期已公开，不再决定 current。
- **体检**（只用标准库，不导入生产代码，规则只依据文档）：
  - 缺失明细新增原因“上游未发布（已用最新已发布值）”：计划的发布判定为 awaiting_release，且上一可得期已入选冻结输入。它不计入“真正缺失”。
  - 公开截止改为与生产一致的运行冻结截止，文档同步。
  - 新增“已知历史缺口”内置表，写入文档：仓单两天的成员、来源判定与预计移出窗口的目标日（按上交所日历计）。表中条目单列展示，不计入真正缺失。
  - SOX 指数在文档中注明为 ADR-0029 的永久缺口，只出现在“目录全部指标”口径。
- **仓单核实**：一次性只读核实上期所与大商所在 07-21、09-09 是否发布了对应品种的仓单日报。结果写入体检文档的内置表，不新接来源。

## Testing Decisions

- 好的测试只看外部行为：给定入库的声明与公开时间，检查投影中冻结的输入与时效标签，不断言内部函数。
- **公开截止**：在现有 Worker 集成测试的接缝上加正反例。正例：目标日两融在次晨公开、早于冻结截止，进入目标日投影的冻结输入。反例：同一值不进入补算日汇总；期次晚于目标日的值不进入。先例是 Worker 完整运行与核心历史补取的集成测试，以及时点选值测试。
- **调度时刻**：在现有调度编排测试上改时刻边界：09:29 不提交，09:30 提交，补交与截止的既有用例保持通过。
- **证据时效**：在现有时效契约测试上加例：持有期等于应有期、下一期已发布未持有，判为 current；持有期早于应有期且未过宽限，判为 awaiting_release。
- **体检**：沿用体检批次的做法，以对真实运行实跑对账为准。对 `run-0a8dabc2…` 重跑，EIA、两融分到新分类，仓单分到“已知历史缺口”，差异逐项有原因。
- **收尾**：全套测试一次（ADR-0025），一次真实 T+1 运行加体检。

## Out of Scope

- WSL 时钟持久处置：已决定永久禁用 timesyncd，由宿主校时，在残余批次票 01 执行。它是收尾验收真实运行的前提。
- `_check_time` 对回拨零容忍、篮子快路径多 4 次请求、留存清理结果不入记录、体检对更正版本与已清理数据的误报：已在 `.scratch/model-rules-residuals-20261013` 开票。
- 新接交易所仓单来源补历史数据。
- 对已有目标日汇总追加更正版本。
- 体检对确认度成员取值的逐条核对。数据偏差的“系统值与上游真值不符”目前只由三核心与派生项的独立重算覆盖，扩展属另一项工作。

## Further Notes

- EIA 的时效按周频推定登记，实际发布日可变，所以 T+1 时目标日值通常未发布，但不能一概断定。新分类以计划的发布判定为准，不另作推断。
- 仓单缺口不影响目标日阶段与确认度计数，只减少持有天数。若缺日将来成为窗口端点，可能改变比较起点，届时由“已知历史缺口”表提示。
