## 现象

### 2026-10-09 补充：同站栏目公平分配与触顶缺口（主 agent 口径）

主 agent 确认两处口径。① 每个列表页一条回执，`source_record_count` 记该页条目数，另两数为 NULL；读了几页、停在哪、为什么停，写进尝试元数据和缺口原因。② 50 页按"一次运行内、每站所有栏目合计（含首页）"计算；一个栏目不能把额度用光、让后面的栏目一页都读不到；触顶时，缺口要写明哪些栏目、哪些期因额度用完而"列表未覆盖"。

- **分配办法：先轮转读列表，再逐期检索**（`full_retrieval.py` 的 `_read_listings`）。完整运行在逐 scope 检索之前，先收集要经官方列表读取的 scope：放行条件与主循环相同（`_gate`：已发布，或较早交易日、未登记发布规则但有列表可读），且尚未取全。这些 scope 按栏目分组。然后轮流读页：每次选已读页数最少的栏目读一页；页数相同时，选已读条目最早日期最新的那个，没读过或没有日期条目的排在前面。每读一页，就记作该栏目最新一个尚未覆盖的期的请求：先绑定该期，再经检索台账追踪，回执也归属该期。栏目在以下情况退出轮转：已读到早于其最早需求期的条目；栏目到底；遇到重复页；同一页失败 3 次；本站 50 页用完；台账拦下了请求（这时由该栏目各期自己的检索再去请求）。之后各期的官方检索直接用已读页面，未覆盖时只在额度内续读。这样同站栏目按页数平分额度，各自由近到远；需要页少的栏目先读完退出，余下的页继续轮给其他栏目，不保留空闲份额。两次被否决的方案没有采用：按份额预留（不变式错误，释放后不再回访）；按日期重排 scope（单个 scope 内仍可能连续翻页把额度耗尽）。
- **计数口径**：台账拦下、没有发出的请求不算读页，也不算失败。货币政策大事记（降准回溯）读的页面记入人民银行站点的合计页数，但回溯本身不受 50 页限制（ADR-0028 的回溯流程不变）。续跑时按回执重建已读页面与已用页数，并排除被拦下的回执。
