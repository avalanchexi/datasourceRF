# 无可靠发布日期时，公开可用时间保持为空

`CONTEXT.md` 术语表把「公开可用时间」定义为：来源给出实际发布时刻时用该时刻；**只有发布日期时
从下一本地日开始；无可靠日期时为空**，并把"推测发布时间"列入 `_Avoid_`。本 ADR 确认**不修改这条
定义**，特别是不为第三种情形引入任何非空推定（采集时刻、目标交易日次日，或其他由日程反推的时点）。
为空即不进入 PUBLIC 点时查询、不可被采用。

这样选是因为 [ADR-0006](0006-dual-as-of-and-immutable-evidence-vintages.md) 的无前视校准：一个非空的
公开时点是在断言"这个值在那一刻已经可见"，而在连可靠发布日期都没有的情况下，这恰恰是无从证实的
那一件事。用一个编出来的时点去满足认证闸，闸就只是在核对我们自己刚写下的数字——
[ADR-0016](0016-certification-gate-escape-valve-is-catalog-membership.md) 决定不放宽闸，这里同样
不能从另一侧把它架空。票 26 的第一版实现已因此整体撤回：它写的 `presumed_public_time()` 与既有
日期分支逐字节等价，新增的列不但冗余，其默认值还会把经日期路径写入的既有声明错标成"来源实际
发布过"——正是这个特性本该防止的失真。

代价要说清楚，而且不小：`CN_DR007` 与 `CN_SHIBOR_ON_1W_3M` 的历史首次公开时间未知，连可靠发布
日期都没有，**因此它们的历史无法认证**；两者都是 P1。按 ADR-0016，它们只能在"缩短已认证历史起点 /
降级为 P2 / 移出目录"之间处置，而不能带缺口留在 P1。这个代价是被接受的：一个无法证明当时可见的
利率历史，其之于点时回放的价值本来就是负的——它会让回放看起来通过，却通不过它声称通过的那件事。
`CN_LPR_1Y_5Y` 不在此列，其许可核验已由用户明示豁免，卡点是使用边界而非时间未知；
`CN_RRR_EVENT` 也不在此列，它有调整日期，落在既有的"只有日期"分支。

本 ADR 不新增字段。两类已有情形（来源实发、仅日期推导）继续靠既有的 `release_at` 与
`public_available_at` 形态区分，第三类以"两者皆空"自然表达，无需第三个标记。
