# 历史发布日期只认该值自己的发布证据

> 已被 [ADR-0021](0021-registered-sources-freshness-replaces-certification.md) 取代（2026-09-23）。

确立某个历史版本的公开可用时间，只接受**该值自己的发布证据**：承载它的那份官方页面、公告或数据文件
本身给出的发布时刻或发布日期。只有日期时按既有定义从下一本地日起算；取不到时**保持为空**，该值不可采用
（[ADR-0017](0017-public-time-stays-empty-without-a-reliable-date.md)）。

**不存在第二级。** 特别是：不得用官方披露日程、编制规则或历史发布节奏去推导"该规则有效期内各日的发布
日期"。`GLOSSARY.md` 已经给这种推定命了名——**预期发布窗口**："依据官方日程或历史发布节奏推定的下一期
可能发布时间范围；它用于监控和时效判断，**不等于实际发布时间**"。而**公开可用时间**的 `_Avoid_` 明列
"计划发布日期"与"推测发布时间"。代码也从未提供这条路径：全仓没有 `expected_release` / `release_window`，
不存在从日程通向 `public_available_at` 的接缝。

本 ADR 的初版曾设两级证据，把归档的官方规则列为第二级。**那是错的**，因为它把两个不同的问题混成一个：

- **编制规则版本**回答"哪套计算/编制规则在哪段时间有效"——属于口径验收（`GLOSSARY.md`：
  "来源、统计期、发布时间、口径和字段均已通过规则检查"，口径与发布时间在那里是并列的两项）。
- **发布证据**回答"这条值哪天对公众可见"。

一份编制规则公告能确立前者，**不能**确立后者。举例来说，南华强制移仓规则公告确立的是 2025-08-15 起
适用哪套移仓规则，它不证明任何一条日线在哪天公开。初版用它作第二级的示例，示例与定义不同类——这正是
概念混用的证据。

代价要说清楚，而且它是本决定的全部重量所在：**取不到逐版本发布证据的历史区段，就是认证不了**。
`CN_DR007`、`CN_SHIBOR_ON_1W_3M` 如此，票 04/06/07/11 中缺少当时发布证据的区段同样如此。这些指标按
[ADR-0016](0016-certification-gate-escape-valve-is-catalog-membership.md) 处置——缩短已认证历史起点、
降级为 P2、或移出目录——而不是靠一个推定出来的时点把闸糊过去。编制规则版本史仍然要补，但它补的是口径，
不折算成发布时间。

这样选，是因为放松的那一侧没有底。一旦允许用日程反推历史可见性，点时回放就会在它声称验证的那件事上
自欺：回放看起来通过了，通过的却是我们自己写下的日程。[ADR-0006](0006-dual-as-of-and-immutable-evidence-vintages.md)
的无前视校准要求的恰恰是相反的东西。

本 ADR 不新增字段、不新增 `certification_status` 取值，也不修改 `GLOSSARY.md`——它记录的是既有词汇表
一直以来的口径，以及一次把它读错之后的订正。
