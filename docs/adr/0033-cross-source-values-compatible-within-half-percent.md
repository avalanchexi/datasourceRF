# 跨来源取值在 0.5% 内视为相容，单位错判为冲突

2026-09-28 用户选择（真实运行遗留分流 [10](../../.scratch/run-findings-20260928/issues/10-sf-total-conflicted.md)）。社融 2026 年 1—8 月累计增量：TuShare `sf_month` 给出 239109 亿元，央行官方页面原文是"23.91 万亿元"，折成 239100 亿元，两者相差 9 亿元（约 0.004%）。TuShare 的值按央行的披露精度舍入后完全一致，是精度差异，而不是修订或口径问题。但冲突判定的容差一直是 0（指标定义里没有容差字段，所有调用方都传 0），所以这一期被判为冲突，信用脉冲拿不到它当输入。

决定：多个注册来源的已认证声明比较时，按两值之比分三档：

- **相容**：相对偏差 `|a−b| / max(|a|,|b|)` 不超过 0.5%，不判冲突，按现行证据优先级规则选值。
- **单位错**：两值之比接近 10 的整数次幂（10、100、1 万等，指数不为 0，误差在 1% 以内），判为冲突，并带原因码 `unit_scale_mismatch`。
- **其余超过 0.5% 的偏差**：仍然判为冲突。

冲突都要进入缺口清单（见 [09](../../.scratch/run-findings-20260928/issues/09-credit-impulse-missing-silently.md)）。两值都为 0 时视为相容；只有一方为 0 时相对偏差按 100% 计，判为冲突。

## 后果

- 这是全局规则，不按指标单独配置。对利率、百分比类指标同样生效：2.50% 与 2.51% 相差 0.4%，视为相容。如果将来某个指标需要更严的口径，再给指标定义加容差字段。
- 接近 0 的值（如小幅同比、净投放）相对偏差会被放大，更容易判为冲突。这和现状（零容差）相比不会变松，不另做处理。

## 考虑过的方案

- **按原文披露精度判相容**（例如 23.91 万亿元的末位是 0.01 万亿元，差值不超过半个单位就算相容）：最精确，但每个来源都得解析并保存原文精度，而现有声明里没有这个信息。
- **只有单位问题判冲突，其余偏差一律容许**：真实的大幅修订或取错行会被静默吞掉。
- **只让官方补缺不连带导入整族指标**：这一次的冲突会消失，但以后两个来源都正常取到时，仍会因精度不同判成冲突。
