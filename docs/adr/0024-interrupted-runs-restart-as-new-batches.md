# 中断的运行作为新批次从头重跑，窗口内漏跑日自动补算

2026-09-23 用户选择：取消检查点恢复——运行中断即判失败，用户重新启动时作为新的加工批次从头运行；保留全局单 Worker 租约、取消与同目标日幂等，仍以手动启动为主、启动项目不自动运行。首次运行（库中无汇总）拉 120 交易日明细＋公式回看，逐日算出窗口内每天的汇总；之后每次运行自动补算窗口内漏跑交易日的汇总（各日只用公开可用时间不晚于该日的明细，不为补算日生成报告），与首次初始化共用一段逐日计算。

取舍：一次运行只处理 120 交易日数据，从头重跑的成本很低，而检查点复用及“恢复外部调用须用户确认”是 Worker 中最复杂的部分；阶段史不连续会让持续性和滞回判定失真，所以补算而不是留空洞。细节见[运行流程形状](../../.scratch/pring-fast-refactor-20260923/issues/07-simplified-run-pipeline-shape.md)。

本 ADR 取代 [ADR-0010](0010-manual-first-persistent-refresh-runs.md) 中的检查点恢复与“不自动补跑”部分；手动优先与自动盘后运行默认关闭继续有效。
