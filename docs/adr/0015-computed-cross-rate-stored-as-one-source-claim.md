# 计算得到的参考交叉汇率存为单条来源声明

ECB 只发布各币种对欧元的参考汇率，不发布人民币兑美元；项目需要的
`CN_USDCNY_ECB_REFERENCE_CROSS` 是同日 `CNY/EUR ÷ USD/EUR` 的项目计算值。它被存为**一条来源声明**，
值即计算结果，双腿原值、公式、原始 ZIP 与 CSV 哈希、采集回执一并留在采集证明里——而**不是**
按领域词汇的字面读法，建成「两条腿各自的观测 + 一条派生观测」。

这样选是因为派生观测要求「一组明确输入观测」，而本系统的公式输入以 `metric_id` 为键
（`full_run_requirements.py:98` 起的公式映射）。把交叉值做成派生观测，就必须先把 `CNY/EUR` 与
`USD/EUR` 各自提升为一等指标：进不可变目录、走来源认证、进检索计划与缺口预算。这两条腿只是中间量，
项目不消费它们，也不打算为它们承担认证工序——为一个 P2 背景指标引入两个谁也不读的指标身份，
代价与收益不成比例。

代价要说清楚：这个值在系统里**表现为来源声明，却没有任何来源发布过它**。审计它得靠采集证明还原
双腿与公式，而不是派生观测那条现成的输入血缘。缓解手段是把还原所需的一切都留在证明里，并且
不让它冒充 ECB 的发布——`release_at` 与 `public_available_at` 强制为空，发布事件记为
`unresolved-publication`（`ecb_reference.py:583` 起），运维文档也明写它是项目计算值而非 ECB 报价。

记在真实采用之前，是因为这一步难以逆转：观测身份由指标定义版本、统计期和规范维度确定
（见 [ADR-0006](0006-dual-as-of-and-immutable-evidence-vintages.md)），一旦有了真实声明再改表示，
新旧是两组不同的经济事实，旧声明既不能覆盖也不能改写，只能并存。
