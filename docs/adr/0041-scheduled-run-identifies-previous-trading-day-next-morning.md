# 自动盘后运行改为次一交易日上午识别上一交易日（T+1）

2026-10-11，用户在“模型规则补全与真实验证”访谈中作出决定（Q13，见 [访谈记录](../../.scratch/model-rules-validation-20261011/interview.md)）。

## 背景

自动盘后运行原先在交易日当天 18:30 识别当天（[ADR-0010](0010-manual-first-persistent-refresh-runs.md) 的默认关闭仍然有效）。可是有些输入当晚还没发布，例如深交所两融、部分官方数据和 EIA，这些项只能按“上游未发布”暂用上一期。用户明确：Pring 模型的识别按 T+1 进行，进入模型前要先判断输入是否完整，不完整就先获取。

## 决定

- 自动盘后运行在**每个上交所交易日上午 9:00**发起，目标交易日取**上一交易日**。
- 运行前先确认“今天是交易日”，并且上一交易日在日历里有明确依据。日历的补取与暂缓沿用 [票 14](../../.scratch/data-quality-audit-20261010/issues/14-scheduler-weekday-fallback-on-holidays.md) 的做法：缺覆盖时先补取，补取失败就暂缓并定时重试。判定对象由“当天”改为“今天与上一交易日”。
- 上游在运行时仍未发布的最新一期，暂用上一期数据并加标注，之后的运行取到后自动更新。这与现行的“落后 1 期沿用”一致。历史上某天上游本来就没有发布的，仍然记为缺口，不插值。
- 人工运行不受影响。

## 考虑过的方案

- **保持当天 18:30**：结果出得早，但缺口最多。
- **当晚和次晨各跑一次**：数据最全，结果也最早，但每天跑两轮，外部调用和报告都翻倍。

## 后果

- 长假前最后一个交易日，要到节后第一个交易日上午才识别。
- 票 14 的调度判断要改：判定对象从当天改为上一交易日，触发时刻从 18:30 改为 9:00。时效截止取运行时刻（票 27 的口径不变）。
