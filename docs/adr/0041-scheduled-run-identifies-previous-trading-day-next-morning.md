# 自动盘后运行改为次一交易日上午识别上一交易日（T+1）

2026-10-11，用户在“模型规则补全与真实验证”访谈中作出决定（Q13，见 [访谈记录](../../.scratch/model-rules-validation-20261011/interview.md)）。

## 背景

自动盘后运行原先在交易日当天 18:30 识别当天（[ADR-0010](0010-manual-first-persistent-refresh-runs.md) 的默认关闭仍然有效）。可是有些输入当晚还没发布，例如深交所两融、部分官方数据和 EIA，这些项只能按“上游未发布”暂用上一期。用户明确：Pring 模型的识别按 T+1 进行，进入模型前要先判断输入是否完整，不完整就先获取。

## 决定

- 自动盘后运行在**每个上交所交易日上午 9:00**发起，目标交易日取**上一交易日**。
- 运行前先确认“今天是交易日”，并且上一交易日在日历里有明确依据。日历的补取与暂缓沿用 [票 14](../../.scratch/data-quality-audit-20261010/issues/14-scheduler-weekday-fallback-on-holidays.md) 的做法：缺覆盖时先补取，补取失败就暂缓并定时重试。判定对象由“当天”改为“今天与上一交易日”。
- 上游在运行时仍未发布的最新一期，暂用上一期数据并加标注，之后的运行取到后自动更新。这与现行的“落后 1 期沿用”一致。历史上某天上游本来就没有发布的，仍然记为缺口，不插值。
- 人工运行不受影响。

## 考虑过的方案

- **保持当天 18:30**：结果出得早，但缺口最多。
- **当晚和次晨各跑一次**：数据最全，结果也最早，但每天跑两轮，外部调用和报告都翻倍。

## 后果

- 长假前最后一个交易日，要到节后第一个交易日上午才识别。
- 票 14 的调度判断要改：判定对象从当天改为上一交易日，触发时刻从 18:30 改为 9:00。时效截止取运行时刻（票 27 的口径不变）。

## 补写：P0 截止与错过 9:00 的补交（2026-10-12）

由本 ADR 与[票 14](../../.scratch/data-quality-audit-20261010/issues/14-scheduler-weekday-fallback-on-holidays.md)推出、[票 03](../../.scratch/model-rules-validation-20261011/issues/03-scheduled-run-t-plus-1.md)实现的 P0 截止口径此前没有写下来；补交规则由用户在[跟进票 02](../../.scratch/model-rules-followups-20261012/issues/02-scheduler-skips-missed-0900.md)分流时决定。

- **P0 截止**：自动运行的执行入口截止为**首次提交日北京时间 21:00**，不再是目标交易日的 21:00（T+1 下目标日的截止在提交时已过）。提交日取运行不可变的初始提交时点（`run_cutoff_contract.initial_system_as_of`），不随冻结截止、跨午夜冻结或恢复日期顺延。21:00 整仍在截止内，晚于 21:00 才算过期。当前只在进入主体执行前检查，过期的运行转为待处理（`scheduled_p0_deadline_elapsed`），不发外部请求；已开始执行的运行不因跨过该时刻中止。
- **补交**：开启计划时，交易日当天 9:00（含）后、P0 截止（21:00，含）前，Worker 的**首次判断**即提交一次上一交易日，不要求 Worker 在运行中跨过 9:00。晚启动、重启或休眠跨日后醒来的 Worker 都按此补交。运行中的 Worker 当天判定一次后（已提交、休市、无生效模型或已过截止）记住结果，不再读日历、不再提交；重启的 Worker 重新判断，按沿用的幂等键 `scheduled-<目标交易日>-v<计划版本>` 返回原运行（计划版本不变时）。日历不足照旧暂缓、每 10 分钟重试到截止。人工运行与自动运行仍各自独立，互不合并。
- **截止后不提交**：晚于 21:00 的判断不再提交（原先同日 8:59 → 21:01 的一次检查仍会提交，再由执行入口判过期）。
- **已知边界**：幂等键含计划版本，同一天先停用再启用计划会产生新版本，此后重启的 Worker 在截止前会为同一目标日再提交一次；判定时尚无生效模型、当天稍后才激活的，运行中的 Worker 不再提交，重启后才补交。
