# 日常只跑受影响测试，全套只在真实运行前跑一次

2026-09-23 用户选择：日常改动只用 `tools/check.py quick <文件或 node id>` 跑受影响测试（目标 ≤3 分钟）；每个实施切片收尾跑两例快速端到端冒烟，改动涉及 Worker 编排、目录或来源时加跑完整目录正例与三核心反例；全套 `check.py full` 只在到达终点、真实运行之前跑一次，包含全部耗时测试，只看通过与否并记录耗时。删除软件／材料身份收据绑定，`HEAVY_FILES` 只留完整目录用例；被删门禁的测试随对应模块在同一切片删除或改写；两轴审查不再强制；不引入并行。

取舍：ADR-0014 的冻结收据之所以必要，是因为材料身份键覆盖源码、生命周期夹具冷建需半小时以上；这些夹具随认证与回放门禁一并删除后，收据失去存在理由，而“全套一次”足以确认大规模删改没有遗漏。细节见[开发验证策略](../../.scratch/pring-fast-refactor-20260923/issues/08-dev-verification-policy.md)。

本 ADR 取代 [ADR-0014](0014-full-suite-only-at-freeze-points.md)。
