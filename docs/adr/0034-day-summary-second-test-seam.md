# 单日汇总模块作为第二个测试接缝

2026-09-29 用户选择（[架构评审](../../.scratch/architecture-review-20260929/README.md) 候选 3）。快速重构规格曾写明"唯一测试接缝是手动完整运行的公开入口，首次初始化、漏跑补算、核心沿用/阻断都经这一入口测试，不给内部函数单独开接缝"（[spec.md](../../.scratch/pring-fast-refactor-20260923/spec.md) Testing Decisions 首条）。这条规定实际已被突破：`build_context_projection` 被 18 个测试文件、`P0ProjectionService.publish` 被 7 个测试文件直接调用；而单日汇总的规则（门①、核心沿用与阻断、冲突阻断、补算日公开时间边界）只能经完整运行测，每例要付检索和整轮补算的成本。

决定：新建单日汇总模块（`CONTEXT.md`：单日汇总），作为第二个正式测试接缝。

- **单日汇总接缝测汇总规则**：门①、核心沿用（落后 1 期）与阻断（落后 ≥2 期、来源冲突）、补算日只看当日公开的明细、补算失败日不影响其他日、补算后阶段史按日连续。测试直接准备证据与交易日历，调用模块，读取发布结果。
- **完整运行测运行生命周期**：检索与获取、时效与缺口清单的运行级材料、首次初始化重建阶段史与只为目标日出报告、报告关联、当前指针、检查点与恢复、留存、租约。每项保留少量完整运行用例。
- 已有直接调用 `build_context_projection`、`P0ProjectionService.publish` 的测试不强制迁移；新增的汇总规则测试放在单日汇总接缝上。

## 后果

- 规格中"唯一测试接缝"一条按本 ADR 修订。
- 同一规则不在两个接缝上重复测：规则迁到模块接口后，删除完整运行中只为该规则而设的断言，保留运行级断言。
- 单日汇总模块的接口成为测试依赖，改动它要同步改测试；这是用接口稳定换测试成本的取舍。

## 考虑过的方案

- **维持唯一接缝，模块只为代码组织而建**：汇总规则仍要经检索和整轮补算来测，候选 3 的可测性收益落空；而现存 25 个直接调用的测试文件说明，唯一接缝在实践中已经守不住。
