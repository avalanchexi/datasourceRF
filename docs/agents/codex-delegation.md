# 把只读工作交给 Codex CLI

本机装有 OpenAI Codex CLI，可以承接一部分工作，**不消耗 Claude Code 的额度**。

分工是固定的：**Claude Code 是分析与调度核心，Codex 是执行臂。** 分解任务、划定边界、
判断结论可信与否、在互相矛盾的结论之间取舍——这些不外派。Codex 承接的是边界清晰、
能独立完成、产出可被回头核验的那部分。

## 一、什么可以交出去

判据只有一条：**这件事做完之后，它的结论能不能被独立核验？** 能，就可以交；
不能，说明它是判断而不是执行，留下。

可以交：

- **只读调查**——读代码、追调用链、找出某个行为由哪一行决定。
- **事实核对**——给定一条明确断言，判断真伪并给出 `file:line`。
- **写结构化报告**——把调查结果写成指定路径的 Markdown。
- **独立第二意见**——复核另一方已经写好的结论，尤其是对方自己标注了「未实测」的部分。

不要交：

- **改 `src/` 并跑测试的实施**。本机装的是 `--no-editable` 副本，改源码就要
  `uv sync` 重装，而那个副本是全局共用的；重装时机必须与测试调度咬合，见
  [测试执行](testing.md)。这条调度权不能分散。
- **任何触发重型验证的工作**。一次只能跑一个，调度权必须集中在一处，理由同上。
- **需要在多个既有结论之间取舍的判断**。那是核心角色的事。
- **验收勾选与票面状态变更**。勾一个框意味着对证据负责，见 [任务跟踪](issue-tracker.md)。

## 二、命令行

```bash
codex exec -s read-only -C /mnt/d/cursor/datasourceRF --skip-git-repo-check "<提示词>"
```

- `-s read-only` — **这是关键**。它让「不许改文件」成为进程级的机制保证，而不是提示词里的
  一句叮嘱。并发多个任务、又共用一个安装副本时，这个差别是实质性的。
  可选值：`read-only`、`workspace-write`、`danger-full-access`。**默认用 `read-only`**；
  另外两个要交出写权限，本文档描述的用法都不需要。
- `-C <dir>` — 工作目录。
- `--skip-git-repo-check` — 仓库有未提交改动时不拦。
- 输出重定向到 scratchpad 再读，长任务配 `timeout` 并放后台。

模型与推理深度取自 `~/.codex/config.toml`，当前是 `model = "gpt-6-astra"`、
`model_reasoning_effort = "high"`，**命令行不必重复指定**。要临时覆盖用
`-c model_reasoning_effort=...` / `-m <model>`。

关于深度的选择：调查与复核类工作用配置里的 `high`。除非有实测依据说明某类任务降档后结论不变，
否则不要为省时间调低——这类任务的产出是要被当作证据引用的，省下的那点时间不值得拿结论的
可靠性去换。

实测参考（2026-09-21，`gpt-6-astra` / `high`）：

| 任务 | tokens |
| --- | ---: |
| 单点事实核对（读一个函数、判断分支、给行号） | 约 **8,900** |
| 深度复核（追 11 道守卫的完整调用链，跑内存探针，写结论） | 约 **72,300** |

后者那次复核确认了被复核方的结论，同时改正了它的一条理由——这类产出值得它的成本。

## 三、提示词要写什么

Codex 每次都是全新上下文，仓库惯例它一概不知道。所以提示词必须自带：

1. **硬约束**——不许改哪些目录、不许跑什么。即使有 `read-only` 兜底也要写，因为它还会
   影响对方怎么组织工作。
2. **背景文件的路径**——让它自己去读，不要在提示词里转述，转述会丢细节也会带进你的偏见。
3. **要回答的问题，逐条编号**——含糊的任务换来含糊的报告。
4. **产出物的确切路径**（如果要写文件）。
5. **「不要只是附和」**——尤其是复核任务。明确要求它给出自己的判断和 `file:line` 依据，
   而不是复述被复核的那份结论。
6. **用中文写报告**，与仓库其余文档一致。

## 四、拿回来之后

**结论要验，不论谁给的。** 挑对方论断里最反直觉、或者最能推翻现有判断的那一两条，
自己去核。已经发生过的例子：一次复核指出某个守卫对空输入并不设限（核实属实）；
一次审计用提交时间戳推翻了调度者自己写进任务书的前提（核实属实，任务书已订正）。

对方自己标注「未实测」「读码推断」的部分，要么实测，要么在引用时保留这个标注，
不要在转述中把它升级成事实。

## 五、已知的坑

- `--strict-config` 目前会因为 `~/.codex/config.toml:17` 的
  `sandbox_workspace_write.approval_policy` 是本版本（0.155.1）不识别的字段而直接报错退出。
  所以没法用它来校验其他配置项的取值是否合法。
- `codex exec` 不带提示词参数时会读 stdin；在脚本里用要给 `< /dev/null`，否则会挂住。
