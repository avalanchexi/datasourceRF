# Domain Docs

工程技能在探索代码库前，应按以下规则读取项目领域文档。

## 开始探索前

- 如果根目录存在 `CONTEXT.md`，先读取它
- 阅读 `docs/adr/` 中与当前工作有关的架构决策记录
- 文件尚不存在时直接继续，不需要提前创建
- `/domain-modeling` 会在术语或重要决策明确后按需创建这些文件

## 文件结构

本项目采用单一上下文：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用领域词汇

任务名称、重构方案、假设和测试名称应使用 `CONTEXT.md` 中定义的术语，避免随意使用同义词。

如果所需概念尚未定义，应检查它是错误的新说法，还是确实需要通过 `/domain-modeling` 补充的领域概念。

## 标记 ADR 冲突

如果计划与现有 ADR 冲突，必须明确指出，不得静默覆盖原有决策。
