# 数据质量体检

对**一次已完成的运行**及其 120 日证据窗口做只读体检，回答三个问题：数据取全了吗？进模型的输入全吗？模型输出对吗？结果输出为 Markdown 报告，只报告问题，不阻断运行，也不改库。规格见 `.scratch/data-quality-audit-20261010/spec.md`。

目前已实现第一层中的日频逐日核对，以及低频的最新期与发布延迟核对（票 01）；第二层模型输入完整，以及第三层的输出内部一致性复查（票 03）和三核心独立重算（票 04）。派生数据（票 02）会陆续加到同一套脚本里。

## 用法

```bash
python tools/quality/audit.py --run <run_id> [--database <path>] [--out <md>]
```

- `--database` 默认为 `~/.local/share/pring-cycle/pring-cycle.sqlite3`，以 `file:...?mode=ro` 只读方式打开；制品原件从同级的 `artifacts/sha256/<前两位>/<哈希>` 只读读取。
- 不加 `--out` 时报告打印到标准输出。报告末尾会记录本次耗时，对 `run-a8675946…` 实测为 5～9 秒。
- 排序用的临时数据放在内存里（`PRAGMA temp_store = MEMORY`），只读沙箱里也能运行。
- 被审运行必须处于 `completed` 状态。截止时点取 `run_cutoff_freeze.system_as_of`；若该表无记录，则退回 `parent_run.system_as_of`。所有“已持有”都以 `available_at <= 截止` 为准，所以审旧运行时，运行之后才入库的数据不会被算进去。
- 从源码目录直接跑时，建议加上 `PYTHONDONTWRITEBYTECODE=1`，避免在 `tools/quality/` 下留下字节码。

## 独立性约束

- 只用 Python 标准库，**不导入 `pring_cycle`**，也不照抄生产代码里的计算逻辑。规则来源只有三类：库里存储的数据、冻结模型清单（`model_version.manifest_json`），以及本文档写明的内置表。
- 脚本不做任何外部调用，不启动 Worker，也不写库。

## 结构

| 文件 | 职责 |
|---|---|
| `tools/quality/audit.py` | 入口：解析参数、只读打开库、加载 `Run`，依次调用 `SECTIONS` 中的各节并拼成报告 |
| `tools/quality/common.py` | 公共读取：`Run` 封装运行信息，以及冻结目录（`catalog`）、模型用到的指标（`model_used`）、截止前仅有派生值的指标（`derived_only`）、定义相同的目录版本（`same_definition`）、窗口（`window`）、各市场日历（`calendars`）、截止前的取数回执（`receipts`、`reached_source`、`validated_by_cutoff`），以及按哈希读取原件（`artifact`）；另含 Markdown 表格工具 |
| `tools/quality/acquisition.py` | 第一层：取数是否完整（日频、低频） |
| `tools/quality/model_input.py` | 第二层：模型输入是否完整（缺失明细与四个分母） |
| `tools/quality/output_consistency.py` | 第三层（一）：输出内部一致性（阶段映射、确认度计数、报告与投影） |
| `tools/quality/core_recompute.py` | 第三层（二）：三核心独立重算（趋势状态 → 正式阶段），与系统输出逐日比对 |

后续各层的接法：新建一个模块（例如 `derived.py`），提供 `section(run: Run) -> str`，再追加到 `audit.py` 的 `SECTIONS` 列表。需要的公共读取能力放进 `Run`，不要在各层模块里重复写查询。

## 口径

### 两种范围

每项结论都分两种口径报告：

- **目录全部指标**：冻结模型目录（`metric_definitions`）中的全部指标。
- **仅模型用到的指标**：`core_metrics` 中的核心指标、`confirmation_rules` 里任意位置出现过的目录指标编号，再加上 `warrant_conversions` 指向的 `CN_FUTURES_WARRANTS`。v0015 下共 47 项。

以下几类只计入“目录全部”：国际参考类 P2 指标（VIX、SOX、UST2Y／10Y、人民币中间价、16:30 收盘价、ECB 交叉汇率）、运维类指标、确认规则没有引用的派生项。

不进入本层逐格核对的指标：

- 运维类：`CN_TRADE_CALENDAR`、`CN_RELEASE_SCHEDULE`、`SOURCE_OBSERVED_AVAILABILITY`。日历本身的覆盖范围在“日历与窗口”一节单独列出。
- 只有派生值、没有来源声明的指标（`derived_only`），归第一层第三条（票 02）处理。
- 事件型指标，例如 `CN_RRR_EVENT`：没有固定期次，只列名。

### 窗口

窗口取上交所日历中截至目标日的最后 N 个开市日，N 来自冻结清单的 `visible_evidence_window_trading_days`（当前为 120）。报告会把它与最终计划里的 `daily_window` 比对，并给出一致或不一致的结论。

非上交所市场使用同一段自然日区间（窗口首日到目标日），再按各自市场的日历筛选开市日。

### 日频：逐交易日 × 成员

在窗口区间内，对每个日频指标的每个成员、该市场每个开市日记一格，每格归入以下四类之一：

| 类别 | 判据 |
|---|---|
| 已持有 | 截止前已入库的该指标、该成员、该日的 `source_claim`。旧目录版本的声明，只要该指标在那个版本中的定义与冻结定义相同（只允许 `definition_version`、`priority`、`certification_status`、`name_cn` 不同，见 `common.IDENTITY_NEUTRAL`），也算已持有，并在“其中仅旧目录版本”一列单独计数。只有定义不同的旧版本声明的格不算已持有，并在依据里注明 |
| 上游未发布 | 证据来自最近一条覆盖该日、并在截止前取得来源应答的回执（有原件，且 `received_at` 不晚于截止）。满足以下任一条即判为上游未发布：① 原件是 TuShare 结构（`data.fields/items`），而该日的行数为 0，权证按 `symbol` 分开数；② 该回执只取这一天，截止前已校验通过，且 `source_record_count = 0` |
| 未取到 | 没有声明，也不满足上面的证据：没有覆盖该日的回执；覆盖该日的回执在截止前都没取得应答（例如被负缓存拦截）；原件里该日其实有行；或者原件不是 TuShare 结构，无法逐日核对。报告会附上所依据回执的编号与状态 |
| 日历未覆盖 | 该市场的日历不覆盖这一天，不算缺口 |

**哪些回执算数**：截止前发起的回执中，只看“请求的是这个成员的序列”的那些。具体做法是：先找出截止前为该成员在窗口内产出过声明的回执，取它们的请求签名，即接口名加上除日期类参数以外的全部参数（例如权证的 `symbol`、指数的 `ts_code`）；签名相同的回执都算数。从未持有过的成员，退而使用在运行中声明过该指标的回执（`full_run_acquisition.metric_ids_json`）；权证还要求回执请求的正是该品种（参数 `symbol`）。覆盖区间从参数中的 `start_date`／`end_date`／`trade_date`／`period`／`date` 推出。比最近一条取得应答的回执更新、但没有取得应答的尝试，不作为证据，只在依据里计数。

**成员**：

- 权证按品种（`symbol`）划分成员，品种取窗口内出现过的品种与 `warrant_conversions` 列出品种的并集。每个品种使用其 `exchange` 维度对应交易所的日历。
- 其他指标以窗口内出现过的每一组完整维度为一个成员。没有任何声明的指标记为一个成员：无维度的记作“—”，有维度的记作“（无任何声明）”。
- 局限：从未出现过的成员发现不了。

**公开时间晚于目标日**：有些格已经持有，但声明的公开时间（取 `public_available_at`，缺失时取 `inferred_public_at`）晚于目标日结束。这些格单独列表：它们取数是完整的，只是按时点规则不进模型，由第二层报告。

### 月频、季频、周频：最新应有期与发布延迟

**发布依据**，按以下顺序确定：

| 指标 | 依据 |
|---|---|
| 国家统计局各项 | 运行批次 `release_schedule` 中 `nbs:schedule_page` 的条目，对应关系见 `acquisition.NBS_SCHEDULE`。PMI 在当月发布当月数据，其余指标发布上一个月或上一季度的数据；季度条目只取 1、4、7、10 月的发布 |
| LPR | 冻结规则 `monthly_day_20_holiday_roll_0900_asia_shanghai`：每月 20 日 09:00 发布，遇上交所休市日顺延 |
| 其他（人民银行货币信贷、央行工具月度投放等） | 没有官方日程，只能以截止前已入库声明的公开可用时间推定。**局限**：如果整期都没取到，这里发现不了。报告的“发布依据”栏会写明这一点 |

周频按 ISO 周编号期次（v0015 目录中没有周频指标）。

低频只计与冻结定义相同的目录版本的声明（同日频的 `same_definition` 口径）。

**最新应有期**：截止前已经发布的最近一期（按上表依据判断）。截止前该期有任何声明入库，判为“在”，否则判为“缺”。备注栏列出上一期有、本期却缺的成员数。

**超过宽限**：只看发布时间落在窗口首日到截止之间的期次。宽限截止是发布日之后第一个国内开市日的 23:59:59（北京时间）。上交所日历覆盖不到时，改用 SHFE 期货日历判断开休市（内地交易所节假日相同），并在“依据”栏注明；两者都覆盖不到时，记为“宽限无法判定”，在结论中单独计数，不算超过宽限。以下两种情况列为超过宽限：首次入库时间（最早的 `available_at`）晚于宽限截止；或者到冻结截止仍未入库，且截止已晚于宽限截止。到冻结截止时仍在宽限内的期次不列。

发布时间早于系统启用时间（库内第一条回执的时间）的期次，是系统启用后回填入库的。这些期次照样列出并计数，只在“启用前发布”栏标“是”，结论中另外给出数量；其中到截止仍未入库的，就是回填也没补上的期次。

## 日历来源

| 日历 | 来源 | 用于 |
|---|---|---|
| SSE | 库内 TuShare `trade_cal`（上交所）原件，优先用被审运行自己的回执 | 国内日频指标（含银行间指标，按规格统一用上交所日历）；窗口；宽限 |
| SHFE／DCE／CZCE／INE | 库内 TuShare `fut_trade_cal` 原件，优先用被审运行自己的回执；回执在下游失败（如 `ContextObservationsMissingError`）不影响原件中的日历 | 南华指数与商品篮子（SHFE）、各品种权证 |
| US_EQUITY | 内置 NYSE 假日表 | VIX、SOX、EIA Brent／WTI |
| US_TREASURY | 内置 NYSE 假日表，加 SIFMA 的哥伦布日、退伍军人节 | UST 2Y／10Y |
| TARGET | 内置 TARGET 关闭日：元旦、耶稣受难日、复活节周一、5/1、12/25、12/26 | ECB 交叉汇率 |

- 内置的 NYSE、SIFMA、TARGET 表目前覆盖 **2025–2027 年**，在 `tools/quality/common.py` 中，**每年都需要补下一年**；超出覆盖年份的日子会报为“日历未覆盖”，不做猜测。
- 耶稣受难日美国债市有时只提前收市而不全天休市，表里按休市处理。
- 美股表用于 EIA Brent 时，英国银行假日（Brent 当天无报价）不会被排除。EIA 原件是 HTML，无法逐日核对，所以这些日子会报为“未取到”，需要人工按假日解释。
- 报告的“日历与窗口”一节会列出每份日历实际使用的回执编号和覆盖范围。如果上交所日历只覆盖到目标日、没有覆盖到判定日，结论会单独提示，这是 lookback/30 的特征。

## 第二层：模型输入是否完整

`tools/quality/model_input.py`。读取运行的最终取数计划（`full_run_gap_plan` 的 `final`、`adoption`）、投影的分析数据集与 `batch_freshness`，为此 `Run` 增加了 `projection_set_id`、`envelope`、`datasets`、`gap_plan(phase)` 四项只读能力。

### 缺失明细

- 取最终计划中 `status = model_input_missing` 的行，按 `missing_members` 展开为“指标 × 期次 × 成员”。成员键转换成第一层的写法：权证取品种（`CN_FUTURES_WARRANTS:symbol_missing:CU` → `CU`），其他取排序后的维度 JSON。
- 每项附四列依据：
  - **计划的发布判定**：计划 `gaps[]` 中该指标期的 `release_gate`。`awaiting_release` 只说明生产的发布门禁没有找到截止前已公开的声明、且登记的发布时间未到，**不等于**已持有；没有该键也不代表完整。
  - **第一层**：同一格在第一层的类别（已持有／上游未发布／未取到／日历未覆盖）；低频项不逐格核对，标“第一层未逐格核对”。
  - **原因**：截止前已持有该期该成员的声明（只计与冻结定义相同的目录版本，同第一层的 `same_definition`；低频按期次覆盖的月或季匹配 `period_end`）时，比较其公开时间与**公开截止**。公开截止取运行截止与目标日结束（北京时间 23:59:59.999999）中较早者，与生产的完整运行一致（`full_retrieval.py` 中 `min(known_at, utc_now(), _target_end(run))`）。公开时间按生产读视图的口径取 `public_available_at`，为空时取 `inferred_public_at`（标“推定”）。晚于公开截止的，判为“已持有，公开时间晚于目标日”，即按时点规则不进模型。未持有的，沿用第一层的依据。
  - **本运行回执**：本运行在 `full_run_acquisition` 中为该指标、该期（或不限期）登记的回执，按状态和失败原因计数，例如被负缓存拦截的 `failed（negative_cache_active）`。
- **落后 1 期算完整**（规格要求）。满足以下条件的缺失项在“算完整”一列注明，并在结论中与真正缺失分开计数：该项是计划对该指标要求的最新一期，且模型实际用了上一期的值。三核心只以投影里的 `carried_forward` 为准（核心沿用），标记为假时不再按上一期输入推断；其他指标要求上一期该成员的声明（同定义的目录版本、截止前入库）出现在本运行的冻结输入编号中。日频的“上一期”是该成员在第一层里的前一开市日，该日日历未覆盖时不判；低频是上一个月或上一个季度。只凭“上一期已持有”不算：例如 `run-a8675946…` 的两融 09-29 已持有，却不在冻结输入里，所以 09-30 仍算缺失。
- 局限：生产的计划只列它声明过的期次，计划没要求的期次不会出现在这里（第一层负责发现它们）。

### 四个分母

四者口径不同，分别报告，不能互相换算：

| 分母 | 来源 | 计数单位 |
|---|---|---|
| 最终计划行 | `final.requirements`，状态 `local_complete`／`model_input_missing`／`operational_evidence`，其他状态（如 `event_presence_unknown`）另列；公式需求 `derived_requirements` 单独列 | 指标 × 期次（日频为交易日） |
| 冻结输入编号 | 投影 `core_assets`、`macro` 的 `model_input_observation_version_ids`，合并去重后与 `adoption.selected_observation_version_ids` 比对 | 入选的观测（来源声明或派生值） |
| 确认度成员 | `macro.confirmation.dimensions[].key_indicators[].members[]`，逐个展开 | 关键指标的成员 |
| 批次时效 | `batch_freshness`（`batch_id` 为运行编号） | 指标，只看尾部落后 |

- 确认度：**当前阶段为空（非典型组合、核心待定）时，生产在判指标级缺失之前就返回，`key_indicators[].missing` 必为空**，不能据此认定完整。所以本节逐个展开 `members[]`，统计 `evidence_status`（取值不封闭，除 current、stale、missing 外另列）和成员级 `missing`，并列出不是 current 或有缺期的成员。
- 批次时效：`stale` 包含落后 1 期，生产没有单独的沿用状态。本节把 `periods_behind = 1` 的项标为“落后 1 期，算完整”。`periods_behind` 是相对已过宽限的应有期计算的，日历未覆盖时生产会按工作日推定（lookback/30），所以“落后 6 期”不等于真缺 6 个交易日。

### 追溯断链

输入编号既联接不到 `source_claim.claim_id`，也联接不到 `derived_observation.derived_observation_id` 的，单列为追溯断链，不算缺失。核心输入包括 120 日窗口之前用于均线、斜率和持续确认的观测；按留存规则，三核心价格的窗口前声明即使被投影引用也可删除（`retention.py`）。本节会注明核心断链中有多少不在三核心窗口观测之内；宏观断链不适用这条留存例外，出现时需单独查明。

## 第三层（一）：输出内部一致性

`tools/quality/output_consistency.py`。只做 SQL 复查，不重算趋势（重算归票 04）。每项检查列出“期望”和“实际”：期望由冻结清单（`stage_mapping`、`core_metrics`、`confirmation_rules.key_indicators`）和 ADR-0001、ADR-0037、`CONTEXT.md` 的规则推出，实际取自投影与报告。

**核心状态 → 正式阶段**

- `stage_mapping` 的键按债、股、商品的顺序排列。若任一核心状态不是 bull／bear，或 `p0_assessment.gaps` 非空，则期望当前阶段为空、原因为 `core_data_pending`；否则按映射得到阶段（原因 `canonical_combination`），映射不到就是非典型组合（当前阶段为空，原因 `noncanonical_combination`）。
- 核对 `p0_assessment` 的 `event_kind`（有当前阶段为 formal，否则为 gap）、阶段与原因；核对沿用名单与 `carried_forward`，沿用资产的 `reason` 应以 `carried_forward` 开头；核对总览、核心数据集和 P0 评估中的核心资产是否相同，以及阶段史中本投影的事件是否恰有一条且与 P0 评估相同。
- 上一确认阶段：有当前阶段时等于当前阶段；否则取阶段史中目标日及以前最近的 formal 评估（按业务日、`system_as_of`、评估编号排序）。
- 投影信封的目标日、模型、截止与运行一致；确认度记录的阶段、原因与总览一致。

**确认度计数与成员读法**

- 关键指标集合与冻结规则一致；关系只取 support、counterevidence、observation_only、unconfirmed、not_applicable 五种。
- `applicable` 等于“当前阶段非空”；不适用时每个关键指标都是 not_applicable。
- 每个已连接维度的 `counts` 等于其关键指标关系的逐项统计；未连接维度的 `counts` 为空。
- 成员读法：冻结规则列出的主要与辅助成员（库存象限按三条线）都必须展开，主要成员标为 `main`；按动量比较（`agrees_by = momentum`）、状态为 current 且未标 `not_compared` 的成员，动量与主要成员（按冻结规则认定）相反（up 对 down）当且仅当标为 `opposes`；冻结主要成员以外不得有标为 `main` 的成员。库存象限有多个主要成员，不做这两项；按符号比较（`sign`）的成员缺少可比字段，本脚本不复核。有成员与主要成员相反（`opposes`）的关键指标不能标为 `consistent`；分化的关键指标关系不能是 support（`CONTEXT.md`：分化时确认关系不高于仅观察）；计入的关键指标（support／counterevidence）不能有指标级缺失。
- **规则歧义**：“不高于仅观察”是否也排除反证（counterevidence），文档没有写明。脚本不判定，遇到时只在结论中提示。

**报告与投影**

- 取绑定本投影的最新版本报告（`report_snapshot` 按 `projection_set_id` 取最大 `version`），状态应为 `completed` 或降级完成 `completed_degraded`；降级报告没有 AI 解释，不核对报告自检。注意 `version` 是按目标日递增的，不能拿目标日的最新版本代表别的投影。
- 核对报告身份、冻结证据包（属于本投影、哈希相同）、`report_snapshot.current_stage` 列、`formal_stage_basis`、`core_states`、结构化结论（`confirmation_applicable`、`dimension:*`、`key_indicator:*`）、`gap_list`、`core_carry_forward`；核对 `verified_results` 中的正式阶段、核心资产状态、确认度、缺口计数，以及它与冻结证据包 `results` 是否相同；最后列出报告自检的身份与结论校验结果。
- `cycle_overview.macro_confirmation` 是旧版宏观标签的摘要，新版输出通常为空，不与 `macro.confirmation` 比较。

不一致的检查在“实际”一列给出差异所在（不同的键或位置），避免长值被截断后看不出差别。

## 第三层（二）：三核心独立重算

`tools/quality/core_recompute.py` 从被审运行冻结的核心输入出发，按文档写明的规则重算每一天的债、股、商品趋势状态、资产候选和正式阶段，并与系统输出逐日比对。规则清单、每条的出处、已登记的歧义及其裁决见[票 04](../../.scratch/data-quality-audit-20261010/issues/04-core-independent-recompute.md)。实施者声明：实现只依据文档与冻结清单，没有读过、也没有调用生产代码中的趋势和阶段计算。

**输入**：被审运行 `core_assets` 数据集里的 `model_input_observation_version_ids`。

- 能追到 `source_claim` 的编号，直接取声明值。
- 追不到的是窗口前的预热输入：按 ADR-0035，三核心价格不因被投影引用而保留，运行结束后被留存清理。它们改从本运行自己的核心回执原件补读，回执经 `source_claim_acquisition` 与该核心指标的声明关联。只补读声明首日之前的日子，补读条数必须等于追不到的编号数，否则本节报告“未重算”。编号是不可逆的哈希，补读的日子只能按条数和日期推定为被冻结的那批预热输入，报告会注明这一点未核验。
- 与声明重叠的日子，核对原件收盘价是否等于声明值。

**收益链**：按官方 `change/pre_close` 收益链构造价格水平（`pre_close` 取自原件）。原件 `pre_close` 与上一条收盘不相等的日子记为断点，断点照常参与计算。以下两种情况下，收益链无法按文档构造：序列中间缺了一个上交所开市日，或者某一天缺 `pre_close`。此时要用到文档没有写明的沿用处理（A5），所以从这一天起的所有日子都不重算，记为“未核验”。状态机带有记忆，后面的日子也会受影响。

**规则要点**（参数取自冻结清单的 `trend_rules`）：

- MA120 为含当日在内 120 个有效观测的简单均值；斜率为 MA120(t)/MA120(t−20)−1；噪声带为 1.5 倍最近 20 个日收益的总体标准差。
- 牛向条件：距离 ≥ 噪声带，且斜率 > 0。熊向条件：距离 ≤ −噪声带，且斜率 < 0。
- 与稳定方向不同的方向条件构成候选，连续 8 个观测成立后确认。条件中断时候选清零，稳定方向保留。首次确认之前，状态为空。
- 三核心状态按 `stage_mapping` 映射，键的顺序为债、股、商品。阶段从冻结输入的第一天起逐日推进，所以上一确认阶段也计入窗口前的可见历史。
- 某个核心当天没有观测（核心缺日）时，该日不重算，记为“未核验”；收益链中断时的处理见上一段。

**系统输出**：取被审运行投影中 `stage_history` 的全部记录。同一天可能有多条记录，来自更早的运行和模型。目标日另外比对本运行的 `p0_assessment` 和 `cycle_overview`，缺少其中任何一项都会写明。比对的字段为：

- 各资产的 `state`、候选（`candidate_state`、`candidate_days`）；
- 测量值（`distance_pct`、`noise_band_pct`、`slope_pct`），相对容差 1e-9；
- (`current_stage`, `last_confirmed_stage`) 二元组；
- 是否为非典型组合（`stage_reason`）。

报告还核对这些记录所属模型的趋势规则、阶段映射与冻结清单是否相同。

**每日结论**：

| 结论 | 含义 |
|---|---|
| 一致 | 所有字段一致 |
| 有差异 | 至少有一个字段不一致 |
| 未核验（核心缺日或收益链中断） | 当天核心缺日，或在收益链中断之后，没有重算 |
| 未核验（可见历史之前的阶段） | 系统的上一确认阶段早于冻结输入能看到的历史 |
| 系统无记录 | 窗口内这一天系统没有任何记录 |

**差异归因**：已汇总的日子不再重算，所以窗口前部的日汇总是早先的运行按它当时持有的历史算出的。对来自早先运行的记录，如果有差异，就取那次运行自己的核心回执原件（接口与 `ts_code` 和被审运行相同，截至其目标日），按同一规则复算一次。复算与记录一致时，再看两份输入的关系：那次运行的原件起点早于冻结输入、且重叠日价格相同的，记为“起算点不同”；否则记为“早先输入不同”（原因待查）。复算仍不一致，或原件已不可读的，记为“未解释”。复算中只在可见历史之前的阶段上有分歧的，原因栏会注明“可见历史之前的阶段未核验”。

**歧义的裁决**：以下三处文档原有歧义，按用户裁决（2026-10-10）只算一种解释。

- A2：价格位置与斜率反向（趋势冲突）、但稳定方向仍保持时，阶段照常映射，不置空（以校准票第 5 条为准，dashboard spec 已订正）。
- A8：上一确认阶段取更新后的值：当天有有效阶段时，它本身就是上一确认阶段。
- A3：确认当天，候选字段清空为（空, 0）。

以下几处不比对，留待票 05 分流：

- `transition_pending`（A4）：只列出位置与斜率反向的日子，以及系统 `reason` 的取值；斜率为 0 不算反向。
- `candidate_30d`（A6）：文档没有写明公式，不重算。
- 核心沿用的计算细节（A5）：见下方局限。

**局限**：

- 只认 `trend-v0001` 和 `candidate-duration-v0002`；规则版本或 `trend_rules` 的键超出这个范围时，报告“未重算”。
- 核心沿用（落后 1 期）的计算细节文档没有写明（A5），所以缺日不重算。
- 补算日按观测日期截取历史，各价格的历史公开可用时间没有独立核验。

**实测**：对 `run-a1110cb8…` 和 `run-a8675946…`，目标日 09-30 两边逐项一致：债牛、股熊、商品牛，非典型组合，`current_stage` 为空。按裁决收敛后，窗口内 109 天一致（含确认当天 09-10），未核验 0 天。08-26 至 09-09 的 11 天有差异，`run-a0418…` 的原件从 01-28 起，冻结输入从 02-03 起，重叠日价格相同。用前者复算，与记录一致，归因为“起算点不同”。本节耗时约 0.1 秒。
