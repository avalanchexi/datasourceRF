# 旧项目普林格周期模型审计与指标匹配

## 0. 摘要

- 最严重的问题是：**中性信号被当作熊市精确匹配，商品看多在默认公式下不可达，随后宏观约束、阶段序号加权和领先指标平移又改写资产阶段**。最终结果不再具有严格的三资产价格组合含义。
- 全部 **35 份历史结果**均至少含一个中性资产；其中 **30 份三资产全中性**，却仍输出阶段和 71%—90% 的置信度。
- 从保存的中间字段静态还原：**33 次一致性改写、29 次加权融合改写、25 次领先指标平移**；最终阶段全部不同于最初三资产映射结果。
- 对照同目录行情，**19 次最终阶段与至少一项明确的股债方向相反**；2026-08-05 还把 `CN10Y.current_yield=141.0` 当作国债收益率使用。
- 旧模型的“库存周期”实为九项景气指标评分；35 次全部为“主动补库存”，没有直接使用库存数量、库存增速或周转天数。
- 指标匹配呈现“**宏观名称重合较多、核心资产及计算口径匹配较低**”：旧 CN10Y 收益率、海外商品混合评分、沪深300评分均不能直接替代新项目三核心价格状态。
- 新项目正确隔离了正式阶段与宏观解释，但仍存在 `overheated` 不可达、未知物价方向变成 `easing`、930916 价格方向反向解释、库存卡把“有数据”标为“支持”等问题。
- 建议保留旧报告的逐项理由与分层展示，放弃旧阶段修正和百分比置信度；先修正新五维状态语义，再访谈六阶段确认预期，不把访谈结果变成阶段门槛。

### 1.3 三层计算的实质

**Layer1 并非库存识别。**权重合计60：PPI 10、CPI 5、PMI综合10、新订单10、生产5、工业增加值8、工业营收5、GDP 5、BDI 2。总分达到45、35、25分别划入主动补库存、被动补库存、主动去库存，低于25为被动去库存。输入中没有真实库存字段。  
出处：`pring_analyzer.py:648–707`。

**Layer2 是人为设定的宽松度评分。**权重合计100：降准20、逆回购15、DR007 15、社融20、M2 15、M1 10、M1−M2剪刀差5。≥60宽松、≥30中性，否则收紧。MLF虽然进入取数、完整度和方法说明，却不参与这七项评分。  
出处：`pring_analyzer.py:315–364,475–507,1497–1555,1780`。

**Layer3 并非三资产机械映射的终点。**实际顺序为映射→一致性→序号融合→领先平移→货币置信度调整；保存的 `base_stage` 已经经过前三类改写，不能解释为“原始资产阶段”。  
出处：`pring_analyzer.py:1606–1668,1760–1767`。

## 2. 缺陷清单

### 2.1 严重度与复现标记

- **阻断**：使阶段基本语义不成立、关键状态不可达，或明显错误的核心数值被用于判断；应阻断相应结论的可信发布。
- **高**：可改变阶段、方向或造成显著错误确信。
- **中**：主要影响证据解释、可追溯性、辅助指标或配置表达。
- **低**：不改变计算的局部标签、措辞问题。

下表“可复现”均给出最小输入及静态确定的实际结果，**没有执行项目函数**。“静态推断”表示代码存在该路径，但历史文件不足以确认触发。受影响数量不是彼此互斥的，不能相加。

### 2.5 放到新项目规则下会怎样

新项目严格按债、股、商品三个核心价格状态映射；核心不可用或组合非典型时 `current_stage=None`，宏观证据不能投票。  
出处：新 `GLOSSARY.md:7–40`；`domain/stage.py:16–43`。

因此：

- 若仅把旧35份结果的Neutral解释为“尚无有效牛熊状态”，**35份均不具备生成新正式阶段的条件**。
- 不能据此断言“新项目在这35个日期实际都会为空”。真实新结果必须重新取得000985、000012、NHII价格序列，按新120交易日趋势规则计算；旧快照不具备这些完整输入。
- 宏观一致性改写、序号融合、领先平移、货币加分均不应进入新正式阶段。
- 8月4日可以形成“旧报告III缺乏资产证据支持”的审计结论；不能只凭旧000300的score=0替新000985计算正式股熊。
- 新规则下，领先迹象应进入转折观察，库存和货币进入事后确认、反证或缺口；原始资产阶段不能因这些解释改变。

## 4. 对新项目的启示

### 4.1 值得保留与必须避免

值得借鉴的是**可读的证据组织**，不是旧评分机制：

- 保留“数据值→局部解释→总体结论”的分层表达，以及每项分值旁的理由、来源、统计期。旧结果 `score_details` 和报告分层段落使8月19日结论能够被审计。  
  出处：旧 `pring_analyzer.py:1739–1767`；8月19日报告`:103–123`。
- 保留资产状态与宏观叙事并列展示；当两者冲突时，应明确写反证，不像D26固定把上涨叫支持。
- 保留估计值、缺口与来源说明，但升级为**字段级、派生级**血缘，避免D23的“现价非估计、比较基准估计”被一个布尔值遮蔽。
- 保留逐步理由，但应保存真正的原始状态和每个解释步骤，避免D28把加工后的阶段叫基础阶段。

必须避免：

| 旧做法 | 对应缺陷 | 新项目应坚持的边界 |

| 中性/缺失变熊、最近组合强制命名 | D01、D08、D09、D18 | 未知、缺失、非典型均不能制造正式阶段 |

### 4.3 为“六阶段×五维确认度预期表”访谈准备的输入

首先应区分三层：

1. **原始事实**：某期、某成员的值与可用时间。
2. **维度状态**：政策宽松、信用扩张等当前结论。
3. **相对阶段的确认关系**：这项结论支持、反驳，还是尚不能确认某阶段叙事。

当前代码实现了第二层的若干规则，**不能把其`support`字段直接当第三层**。五维不是五个独立概率，也没有实现一个经校准的总确认百分比。领域对象的 `score`明确为None。  
出处：新 `domain/macro.py:26–46,49–189`；`GLOSSARY.md:39–41`。

#### 六阶段访谈底稿：典型环境，不是已批准的确认规则

下面把新研究文档中的典型环境转成访谈起点。**每格都应允许时滞、冲突和暂不可判；不能作为正式阶段必要条件。**库存和信贷对应关系在研究文档中明确属于中国市场待验证假说。  
出处：新 `docs/research/pring-six-stage-meanings.md:19–27`及各阶段章节；`GLOSSARY.md:7–40`。

| 正式阶段：债/股/商品 | 政策访谈起点 | 信用访谈起点 | 过热访谈起点 | 物价访谈起点 | 库存访谈起点 |
|---|---|---|---|---|---|
| I：牛/熊/熊 | 是否允许刚转宽松但传导未完成？ | 信用仍弱是否只是滞后，不能立即反证？ | 降温、低景气与“数据不足”如何分开？ | 上游降温、消费端黏性是否允许并存？ | 主动去库存与仍被动积库，哪个更有解释力，允许多长过渡？ |
| II：牛/牛/熊 | 宽松延续还是传导改善更重要？ | 早期改善需总量、结构还是私人信用验证？ | 应确认“需求改善”而非要求过热？ | 商品仍熊时生产端价格改善是否可接受？ | 新订单领先、被动去库存是否为典型支持，实际库存未降怎么办？ |
| III：牛/牛/牛 | 政策已不继续宽松是否构成反证？ | 信用扩张与结构质量怎样同时判断？ | heating可支持，但overheated是否意味着后段风险？ | 上游上涨与生产/消费扩散分别确认什么？ | 主动补库存需要库存、需求、生产哪些同月证据？ |
| IV：熊/牛/牛 | 中性/收紧是否都可支持，而非旧代码排斥收紧？ | 高位但动量回落是否仍与阶段相容？ | 过热水平和增长动量放缓如何并存？ | 压力扩散、高位黏性比单月上涨是否更关键？ | 主动补库尾声与被动积库过渡怎样表达？ |
| V：熊/熊/牛 | 收紧余效与新一轮宽松动作是否可能并存？ | 收缩、结构恶化与政府融资托底如何区分？ | cooling不等于物价已降温 | 商品强、终端弱的分化是否是关键确认？ | 被动补库存需要“需求弱+库存积压”，不能只看库存增量 |
| VI：熊/熊/熊 | 宽松启动是否是转折观察，而非改成I？ | 信用仍收缩是否可与政策宽松并存？ | 降温/衰退压力如何避免与“低温”混名？ | 物价缓和需明确下降证据，不能由unknown生成 | 主动去库存是否典型；进入下一轮修复的先行证据如何单列？ |

访谈应形成的最小决策记录：

| 要确定的内容 | 必须落到的规则 |
|---|---|
| 每格“支持”的含义 | 支持典型叙事、反证、暂未确认、无关，不能只有支持/不支持二值 |
| 同一维度选哪些成员 | 明确`metric_id + dimensions + measure`，避免整组所有成员默认投票 |
| 水平与动量 | 例如PMI是否扩张、较上期是否改善，应是两个不同事实 |
| 时间关系 | 月度发布滞后、信用传导滞后、阶段转折后的确认等待期 |
| 冲突处理 | 政策动作/传导、总信用/私人信用、名义库存/实际代理分别保留 |
| 相关性 | NHII、同一PPI的多角色使用不得当成多份独立支持 |
| 缺失处理 | unknown、stale、awaiting_release、conflict不能得到中性或缓和的默认经济结论 |
| 可追溯性 | 每个确认关系保留所用观测、成员、模型版本与理由；不改写正式阶段 |

这些决定应先形成版本化确认语义，再设计总览展示；无需为了得到一个总分而沿用旧模型的任意权重。依据是新项目正式阶段与确认层的既有边界，以及本次查出的D15、D18、D20、N01—N14。
